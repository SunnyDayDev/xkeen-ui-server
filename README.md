# xkeen-ui-server

Централизованное управление конфигурациями XKeen/Xray: общие JSON-шаблоны, переменные, индивидуальные настройки роутеров и доставка изменений агентам.

**Статус: каркас сервера, первый шаг ядра конфигурации и экспериментальный стенд.** Реализован [минимальный Go-сервер](docs/server-skeleton.md) с `/healthz` и штатной остановкой, проверенный в Entware aarch64-контейнере. В ядре доступна [подстановка готовых JSON-значений A06](docs/configuration-model.md#реализованный-шаг-a06); полная сборка и проверки B01/B02 ещё впереди. В репозитории также есть макеты и [Docker-стенд Entware/XKeen/Xray](lab/README.md). Хранилище и операции управления конфигурацией, агент, UI, установочные скрипты и внешний API управления пока не реализованы.

Запуск каркаса при установленном Go 1.27.1:

```sh
sh scripts/run-server.sh
```

Проверка процесса: `curl --noproxy '*' http://127.0.0.1:8080/healthz`. Остановка — Ctrl+C. [Параметры, тесты и ограничения](docs/server-skeleton.md).

## Для чего нужен проект

Когда несколько роутеров используют похожие настройки, общую часть удобно менять один раз. При этом у каждого устройства остаются собственные адреса, реквизиты подключения, правила и исключения.

Сервис хранит общие шаблоны и все индивидуальные настройки, собирает окончательную конфигурацию каждого роутера и отслеживает её применение. Роутеры подписываются на изменения и восстанавливают синхронизацию после потери связи.

## Запланированное поведение

- Центральный сервис в Docker или на роутере с Entware; отдельный агент на управляемом устройстве. Для первого выпуска — инструкция, установочный скрипт из GitHub и службы `init.d`, без собственных opkg-пакетов.
- Элементы шаблона со стабильными ID, произвольным JSON и переменными вида `${clientId}` или `${server.address}`.
- Переопределение значений переменных либо всего содержимого блока с сохранением его ID.
- Общие и локальные правила с изменяемым порядком, включением и отключением.
- Входы и выходы с идентификаторами для роутинга, переопределением и удалением. Используемый роутингом вход нельзя выключить или удалить.
- Проверка обязательных переменных до подключения устройства.
- Синхронизация ревизий, уведомления и проверка связи раз в минуту.
- Подготовка полных файлов, проверка конфигурации, применение маршрутизации через API Xray и запись файлов; рестарт для изменений, которым он необходим.
- Веб-интерфейс и внешний API для программного управления. Внешний API можно выключить; его авторизацию можно включить или отключить отдельно.

## Общая схема

```text
Templates + router values + overrides
                  |
                  v
          Central service <---- Web UI / Management API
                  |
           desired revision
                  |
                  v
             Router agent
                  |
          validate and apply
                  |
                  v
           XKeen / Xray
```

Агент сам подключается к центральному сервису. Центральный сервис остаётся источником истины даже для локальных исключений конкретного роутера.

## Разработка

Работа над новой функциональностью проходит через OpenSpec: исследование, предложение изменения, реализация и завершение. Артефакты находятся в `openspec/`; проектные навыки доступны в `.agents/skills/`.

Для сервера выбрано направление [Go + SQLite без cgo](docs/server-stack-research.md), с размещением в Docker и Entware aarch64. HTTP-каркас реализован на Go 1.27.1; подключение SQLite и проверка физического роутера ещё предстоят. Стек UI, среда агента, транспорт подписки, минимальные версии XKeen/Xray и полный перечень поддерживаемых архитектур ещё не выбраны. Первичная документация отделяет согласованное поведение от открытых решений; она не является обещанием уже существующего API управления.

Публичный репозиторий: [SunnyDayDev/xkeen-ui-server](https://github.com/SunnyDayDev/xkeen-ui-server). Лицензия пока не выбрана.

Клонирование через GitHub CLI:
