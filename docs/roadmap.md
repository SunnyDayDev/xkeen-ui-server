# План разработки небольшими сессиями

Статус: последовательность небольших работ; критерии будущих задач не являются перечнем реализованных возможностей. Сейчас доступны документация, макеты, [стенд](../lab/README.md) и [HTTP-каркас сервера A03](server-skeleton.md). Предметные функции сервера, агент и веб-интерфейс предстоит создать. Принятые решения и результаты указаны отдельно от будущих задач.

## Как выполнять

- Одна сессия — один пункт с одним проверяемым результатом. Ориентир: 30–90 минут; это оценка объёма, не обещание срока.
- Исследование заканчивается решением и примерами, предложение — артефактами OpenSpec, реализация — работающим изменением и проверкой. Переход к реализации выполняется отдельной задачей после согласования предложения.
- Если для пункта нет готового OpenSpec change, сначала выделить отдельную сессию `openspec-propose`. Не включать проектирование, реализацию и весь соседний функционал в один заход.
- Если пункт перестаёт укладываться в сессию, разделить его **до реализации**. Например, добавление и изменение ресурса — разные задачи.
- В конце реализации: целевая проверка, актуальные документация и артефакты, короткий отчёт о результате и оставшихся ограничениях. Архивировать OpenSpec после завершения всех его задач.
- GitHub issue закрывается только по своему критерию готовности. Обзорный issue остаётся открытым до завершения плана или явного пересмотра объёма.

В колонке «Готово» указан минимальный наблюдаемый результат. У задач реализации подразумевается согласованный OpenSpec-контракт. Зависимость от подготовленного контракта не означает, что он уже согласован.

| G07 | Реализовать сборку файла exclude_ips | Текстовый результат и ошибки проверены без утверждения о применении firewall. |
| G08 | Добавить редактор общего exclude_ips | Список и переменные сохраняются; персональный редактор — следующая отдельная задача. |
| G09 | Проверить применение exclude_ips в подходящем окружении | Результат подтверждён трафиком; для реального роутера требуется отдельное разрешение. Отсутствие подходящей среды фиксируется как ограничение. |
| G10 | Собрать Docker-образ сервера | Чистый запуск и сохранение данных после пересоздания проверены. |
| G11 | Собрать агент для первой архитектуры | Получен артефакт A02 и выполнена проба запуска в согласованной среде. |
| G12 | Спроектировать установку и обновление | Согласованы пути, параметры ролей, init.d, сохранение настроек/ключей и удаление; без собственного ipk. |
| G13 | Реализовать первичную установку агента | Скрипт размещает файлы и регистрирует службу в тестовом Entware. |
| G14 | Реализовать повторную установку агента | Настройки и ключ сохраняются; сбой скачивания не ломает установленный агент. |
| G15 | Реализовать установку сервера в Entware | Одна согласованная архитектура, регистрация службы и проверка доступности. |
| G16 | Подготовить workflow выпуска артефактов | Сборка и контрольные суммы проверены пробным запуском; публикация релиза — отдельная задача. |
| G17 | Написать инструкцию чистой установки | Другой разработчик проходит документированные шаги в пустой тестовой среде; ограничения перечислены. |
| G18 | Провести сквозной сценарий на стенде | Шаблон → персональные значения → публикация → применение → обрыв связи → восстановление; результат записан без приватных данных. |

Оставшиеся пробелы заводятся отдельными задачами: ротация/отзыв ключа, персональный exclude_ips, копирование шаблона, оставшиеся операции внешнего API, обновление/удаление сервера, удаление агента, резервное копирование и восстановление хранилища, проверка дополнительной архитектуры, доступность UI с клавиатуры и узкие экраны. Каждый такой пункт сначала получает конкретный сценарий и критерий готовности; это не одна завершающая сессия «доделать всё».

## Границы плана

Первый приоритет — путь до контрольной точки E08 в изолированном стенде. UI, внешний API и Entware-установка следуют отдельными этапами; полноценный выпуск требует их согласованного объёма и закрытия конкретных пробелов из раздела 7.

Лицензия и публикация первого релиза требуют отдельных решений. План не разрешает подключать реальные устройства. Демонстрационные данные во всех задачах должны соответствовать [AGENTS.md](../AGENTS.md).
