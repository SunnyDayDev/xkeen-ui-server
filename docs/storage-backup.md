# Резервное копирование центрального хранилища

Команды выполняет локальный пользователь, которому принадлежит SQLite-файл сервера. Используйте тот же бинарник и UID, что и у сервера, и закройте доступ других пользователей к каталогу копий. Для Docker используйте установленный бинарник внутри контекста с теми же UID и томами. Для Entware выполните команду от UID, указанного при установке сервера.

```sh
umask 077
mkdir -p /srv/xkeen-ui/backups
xkeen-ui-server storage backup \
  --db-path /srv/xkeen-ui/state/server.sqlite \
  --output /srv/xkeen-ui/backups/server-2026-11-24.sqlite
```

Команда сохраняет согласованный SQLite-снимок, включая транзакции, завершённые в WAL до его чтения. Работающий сервер можно оставить запущенным. Чтение SQLite может пользоваться служебными WAL/SHM-файлами источника. Снимок хранит прежние версии схемы, учётные записи, сессии, историю устройств, ключи регистрации и настройки внешнего доступа. Храните его как секрет. TLS-файлы, параметры службы и настройки внешнего валидатора копируются отдельно по правилам соответствующей установки.

## Подготовка восстановления

```sh
xkeen-ui-server storage restore \
  --backup /srv/xkeen-ui/backups/server-2026-11-24.sqlite \
  --output /srv/xkeen-ui/state/server-rehearsal.sqlite
```

Команда проверяет историю миграций, структуру и целостность SQLite, обновляет схему только в подготовленной копии и создаёт новый файл 0600. Имя назначения и его служебные SQLite-файлы должны отсутствовать. При сообщении о неподтверждённой долговечности оставьте исходные файлы на месте и повторите подготовку с новым именем.

## Проверка и переключение

1. Остановите действующий экземпляр перед переключением. Сохраните путь к его более новой базе и оставьте её на месте.
2. Запустите тот же сервер с `--db-path /srv/xkeen-ui/state/server-rehearsal.sqlite` в изолированной среде. Проверьте TLS, `/healthz`, вход администратора, ключи известных роутеров и их последние ревизии и курсоры. При отказе остановите проверочный экземпляр и запустите службу с прежним путём к более новой базе. При переносе рабочего пути в конфигурацию службы проверьте, что при её повторном старте открывается именно выбранная база.
3. Перед открытием доступа сверьте изменения полномочий между датой снимка и текущей конфигурацией. Сбросьте пароль администратора локальной командой `admin reset` для копии, чтобы сбросить сохранённые сессии. Переустановите настройки внешнего API в закрытом режиме и обновите токен перед его включением. Сверьте каждый действующий ключ и приглашение с текущим решением владельца и отзовите устаревшие через доступные штатные операции. Пока нужные операции или актуальный перечень полномочий недоступны, оставьте восстановленный сервер изолированным.
4. После проверки явно переключите путь в настройках запуска, сохранив исходную более новую базу отдельно. Установите, какие изменения после снимка потребуется воспроизвести. После начала записи в восстановленную базу новый возврат к прежнему файлу тоже требует сверки записей.

Подтверждённое восстановление данных отражает полномочия и курсоры на дату снимка. Повторный запуск агента и последующее применение Xray проверяются отдельно.
