# Установка управляемого профиля Xray

Комплект выбранного коммита собирают локально по мере необходимости. G17/G18 проверяют установку на синтетическом HTTPS-зеркале. [Локальная сборка и проверка Entware](entware-local-build.md).


Профиль `agent-application` устанавливает проверенные ARM64 агент и локальный supervisor для выделенного Xray. Начальная поддерживаемая среда соответствует `direct-xray-lab`. Требуются подтверждённые cgroup v2, pidfd, procfs и собственный контролируемый запуск. Возможности конкретной физической прошивки требуют отдельной проверки.

Владелец однократно подготавливает рабочий каталог Xray и фиксирует точный манифест и стартовый процесс. Существующий XKeen и сторонние механизмы автозапуска не должны запускать второй экземпляр для этого каталога. Пара защищённых конфигураций 0600 владельца root задаёт scope с RouterID и origin, роли, доверенный сертификат, путь и хеш Xray, каталог, манифест, PID и start tick. Конфигурация применения задаёт `ReportVersion: 1`. При следующих стартах supervisor использует свой постоянный журнал. Подробности исходной аттестации и режима приведены в [локальной проверке E02](local-candidate-validation.md) и [документации агента](router-agent.md#контролируемый-рестарт-e03).

Возьмите проверенный скрипт, тег и SHA-256 манифеста по G12. Создайте приглашение для того же RouterID, который закреплён в конфигурациях, и поместите его в приватный файл root с режимом 0600.

```sh
/opt/bin/sh "$INSTALLER" install \
  --role agent-application --version "$RELEASE_TAG" --manifest-sha256 "$MANIFEST_SHA256" \
  --run-as 65532:65532 --server https://controller.example:8443 \
  --invitation-file /opt/etc/xkeen-ui-install/agent-invitation \
  --local-config /opt/etc/xkeen-ui-install/local-profile.json \
  --application-config /opt/etc/xkeen-ui-install/application-profile.json
```

Установщик связывает точные защищённые конфигурации с выбранным выпуском и использует CA из application profile для обоих процессов. Он отказывает при существующей транспортной установке. Данные прежней роли сохраняются для отдельно согласованного перехода. Управляйте установленной службой через `/opt/etc/init.d/S93xkeen-managed-agent start|stop|status`. Остановка сохраняет данные регистрации, журнал и рабочий каталог. Точный повтор после прерывания вновь проверяет владельцев процессов и продолжается с прежним журналом.

Подключённый агент может сообщить контакт. Подтверждение применения появляется только после квалифицированного результата E08. Если supervisor восстанавливает состояние с терминальным отказом, он может отправить сохранённый результат в поддерживаемом режиме, а допуск к применению остаётся закрытым.

Синтетическая проверка установки и реального применения выполняется командой `XKEEN_LAB_INSTALLED=1 sh lab/check-agent-preparation.sh`. Она использует локальное HTTPS-зеркало и изолированные процессы. Полная операторская проверка через поставляемый интерфейс относится к [G18](https://github.com/SunnyDayDev/xkeen-ui-server/issues/141).

## Снять управляемую роль

Используйте проверенный скрипт и закреплённый выпуск, который содержит операцию удаления.

```sh
/opt/bin/sh ./install-entware.sh uninstall --role agent-application \
  --version "$version" --manifest-sha256 "$manifest_sha256" --confirm remove-service
```

Команда удерживает запуск роли, останавливает подтверждённые agent и supervisor и разрешает незавершённую попытку под локальным журналом. Подтверждённый Xray останавливается. Точный рабочий каталог, журнал применения, профиль, CA и ключ агента остаются для восстановления. При неопределённом runtime или терминальном откате запуск роли остаётся заблокированным. Дождитесь локального восстановления журнала и повторите ту же команду. Рабочий Xray следует считать неопределённым до проверки, которую требует сохранённый журнал.

После успешной команды установка не запускает прежнее init.d. Для точного повторного install используйте прежние профиль, версию и UID/GID. Он восстановит подтверждённый рабочий каталог под E05 и прежнее серверное подключение. Если оператор отдельно доказал прежний запуск, он может вернуть его вручную. Сверьте защищённый исходный исполняемый файл или init-entrypoint, точные данные каталога и единственный процесс-владелец. На прямом синтетическом профиле проверен отдельный запуск закреплённого Xray с тем же каталогом. При отсутствии доказательства запуск прежнего XKeen остаётся отложенным, а полученный статус сообщает об этом.
