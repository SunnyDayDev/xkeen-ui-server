# Первичная установка транспортного агента Entware

G13 устанавливает один транспортный агент Linux ARM64. Установка проверена в изолированном ARM64 Entware с синтетическим TLS-зеркалом, центральным сервером и SQLite. Поддержку конкретной прошивки определяют доступность pidfd, проверяемый procfs и исполняемая файловая система /opt. Проверка физического роутера проводится отдельно.

Получите у владельца точный Git commit скрипта, его SHA-256, тег и SHA-256 манифеста. Скачайте скрипт по инструкции G12, проверьте его и храните перед запуском в каталоге root с режимом 0700. Выберите отдельный непривилегированный UID/GID и сохраните выданное сервером приглашение в приватный файл root с режимом 0600. Параметр передаёт путь к файлу. [Доверие к выпуску и получение скрипта](entware-installation-contract.md#получение-конкретной-версии-с-github).

```sh
/opt/bin/sh ./install-entware.sh install \
  --role agent-transport --version "$RELEASE_TAG" --manifest-sha256 "$MANIFEST_SHA256" \
  --run-as 65532:65532 --server https://controller.example:8443 \
  --invitation-file /opt/etc/xkeen-ui-install/agent-invitation
```

Укажите `--ca-file` с защищённым, принадлежащим root PEM-файлом, если сервер использует отдельный центр сертификации. Без этого аргумента используется системное доверие Entware. Для синтетического зеркала предусмотрены `--release-mirror HTTPS_ORIGIN` и `--mirror-ca-file FILE`. Они определяют только доставку выпуска.

Установка завершается после TLS-аутентификации. Команды для подтверждённого экземпляра:

```sh
/opt/etc/init.d/S92xkeen-agent status
/opt/etc/init.d/S92xkeen-agent stop
/opt/etc/init.d/S92xkeen-agent start
```

Состояние и рабочий ключ хранятся в `/opt/var/lib/xkeen-ui/agent-transport`. После успешного запуска владелец может удалить обе копии одноразового приглашения, исходный файл и `invitation` в приватном каталоге агента. Храните рабочий каталог и его права при остановке и запуске.

После недоступности сервера повторите ту же команду с прежним тегом, суммой, origin, CA и UID/GID. Установщик использует сохранённое состояние и повторно не записывает приглашение. Регистрация init.d появляется после готовности; точный повтор может завершить публикацию регистрации уже подтверждённого процесса. Если локальный журнал сообщает неопределённое владение, новый процесс не запускается. Прежде чем продолжить после прерывания между запуском и фиксацией процесса, подтвердите отсутствие работающего экземпляра. Перезапуск устройства делает старую запись экземпляра проверяемо устаревшей по идентификатору загрузки.

Профиль применения и сервер принадлежат дальнейшим шагам G14–G18. Команда из примера требует будущих выпущенных файлов для указанного тега; проверка разработки использует `sh lab/check-entware-install.sh`.

## Обновление установленного транспортного агента

Сначала получите доверенную сумму манифеста нового точного тега и проверьте сам установочный скрипт по G12. Сохраните параметры службы в действующем профиле. Укажите только выбранный выпуск.

```sh
/opt/bin/sh ./install-entware.sh update \
  --role agent-transport --version "$RELEASE_TAG" --manifest-sha256 "$MANIFEST_SHA256"
```

Точный повтор подтверждённого выпуска сохраняет экземпляр. Новый выпуск должен объявлять совместимый формат данных в `agent-state-format.txt`. Сбой HTTPS-загрузки или несовпадение суммы сохраняют действующий процесс и файлы. Установка проверяет новое поколение после полной подготовки. При отказе запуска восстанавливается предыдущая подтверждённая версия и исходное состояние службы. Настройки и рабочий ключ остаются прежними.

Если служба остановилась из-за прерванного обновления, повторите команду с проверенным выпуском или вызовите `/opt/etc/init.d/S92xkeen-agent start`. Защищённое намерение восстанавливается до обычного запуска. Если владение процессом не удаётся подтвердить в текущей загрузке системы, требуется локальное восстановление. Если `current` возвращён на прежнее поколение, а центральный сервер недоступен для TLS-аутентификации, запуск остаётся незавершённым до восстановления связи.

## Снять транспортную службу

Используйте проверенный скрипт и закреплённый будущий выпуск, который содержит операцию удаления. Пример использует те же переменные выбора выпуска и контрольной суммы, что и установка.

```sh
/opt/bin/sh ./install-entware.sh uninstall --role agent-transport \
  --version "$version" --manifest-sha256 "$manifest_sha256" --confirm remove-service
```

Команда подтверждает принадлежность службы, блокирует штатный запуск, останавливает свой процесс и удаляет собственную регистрацию и исполняемые поколения. При прерывании повторите ту же команду. Если обнаружены чужой процесс или файлы, сначала установите их происхождение. Ключ, CA и состояние остаются по прежним путям. Повторная установка с теми же версией, настройками TLS и UID/GID переиспользует этот ключ без нового приглашения. Удаление транспортной службы не отзывает серверную регистрацию. Для профиля управляемого применения нужен отдельный процесс снятия роли.
