# Внешний API управления

## Назначение и статус

Планируется внешний API, через который сторонние программы и автоматизации смогут управлять теми же объектами, что и веб-интерфейс. Привязки к конкретному внешнему клиенту нет.

API пока не реализован. Документ описывает область возможностей и согласованные настройки доступа; URL, методы, схема сообщений и коды ошибок ещё не являются контрактом.

## Область управления

| Область | Необходимые операции |
| --- | --- |
| Шаблоны | Просмотр, создание и изменение шаблонов, их элементов, сырого JSON и переменных |
| Настройки роутера | Выбор шаблона, значения переменных, собственный JSON и локальные элементы |
| Роутинг | Добавление, изменение, порядок, отключения, проверка ссылок |
| Входы и выходы | Просмотр идентификаторов, переопределение, удаление; вкл/выкл входов с проверкой зависимостей |
| Устройства | Подготовка подключения, переименование, удаление из списка, получение состояния |
| Конфигурации | Сборка и проверка итогового JSON, просмотр различий и затронутых роутеров, запуск применения |
| Применение | Желаемая и применённая ревизии, стадии, ошибки, результат восстановления |
| Настройки сервиса | Состояние внешнего API и его авторизации |

Обход правил через API не допускается: обязательные переменные, неизменность ID при переопределении и зависимости входов проверяются на сервере одинаково для UI и внешних клиентов.

## Переключатели доступа

На странице «Настройки» есть независимые настройки:

1. **Внешний API** — включает или выключает программный доступ к управлению.
2. **Авторизация API** — требует учётные данные для внешних запросов, когда API включён.

| Внешний API | Авторизация | Поведение |
| --- | --- | --- |
| Выключен | Любое сохранённое значение | Внешние операции управления недоступны |
| Включён | Включена | Внешний клиент должен предоставить действительные учётные данные |
| Включён | Выключена | Управление доступно без учётных данных всем клиентам, имеющим сетевой доступ к API |

Работа без авторизации — поддерживаемый режим для приватного контура. Интерфейс прямо показывает текущий режим. Отключение авторизации внешнего API не отменяет индивидуальную идентификацию агентов роутеров и не определяет способ входа в веб-интерфейс.

Тумблер внешнего API не открывает порты роутера, не настраивает пробросы и не меняет сетевую доступность сервера. Размещение, адрес прослушивания и проксирование настраиваются отдельно при развёртывании.

## Предлагаемая первая схема авторизации

В макете показан токен внешнего API и заголовок `Authorization: Bearer <token>`. Это предложение начальной схемы; формат токена, количество токенов, ротация и хранение должны быть закреплены в OpenSpec до реализации.

Настройки позволяют создать или заменить токен. Значение в интерфейсе скрыто; реальные токены не должны попадать в документацию, общедоступные макеты или журналы.

Начальные значения переключателей пока не согласованы. Предлагаемый вариант: внешний API выключен, авторизация включена. Макеты показывают рабочие состояния, а не установочные дефолты.

## Отдельный протокол агентов

Ключ агента роутера идентифицирует устройство и даёт доступ к его конфигурации и отчётам. Токен внешнего API предназначен для административных операций. Эти полномочия не следует смешивать.

Отключение внешнего API не должно разрывать подписки роутеров или мешать им получить актуальную конфигурацию. Веб-интерфейс должен сохранять возможность снова включить API и настроить его авторизацию.

## Следующее проектирование

- Полный контракт API и его машиночитаемое описание.
- Асинхронные операции применения: идентификатор операции, получение статуса и идемпотентность повторного запроса.
- Конкурентные изменения, проверка версии редактируемого объекта и ошибки валидации с указанием блока и переменной.
- Формат и жизненный цикл токенов; необходимость нескольких клиентов и областей доступа.
- Механизм авторизации веб-интерфейса — отдельное решение.
- Сетевые параметры развёртывания и поведение при изменении настроек самим внешним клиентом.
