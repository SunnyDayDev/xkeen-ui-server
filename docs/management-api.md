# Внешний API управления

## Назначение и статус

Планируется внешний API, через который сторонние программы и автоматизации смогут управлять теми же объектами, что и веб-интерфейс. Привязки к конкретному внешнему клиенту нет.

API пока не реализован. Документ описывает область возможностей и согласованные настройки доступа; URL, методы, схема сообщений и коды ошибок ещё не являются контрактом.

## Область управления

| Область | Необходимые операции |
| --- | --- |
| Шаблоны | Просмотр, создание и изменение шаблонов, их элементов, сырого JSON и переменных |
| Настройки роутера | Выбор шаблона, значения переменных, собственный JSON и локальные элементы |
| Роутинг | Добавление, изменение, порядок, отключения, проверка ссылок |
| Входы и выходы | Просмотр идентификаторов, переопределение, удаление; вкл/выкл входов с проверкой зависимостей |
| Устройства | Подготовка подключения, переименование, удаление из списка, получение состояния |
| Конфигурации | Сборка и проверка итогового JSON, просмотр различий и затронутых роутеров, запуск применения |
| Применение | Желаемая и применённая ревизии, стадии, ошибки, результат восстановления |
| Настройки сервиса | Состояние внешнего API и его авторизации |

Обход правил через API не допускается: обязательные переменные, неизменность ID при переопределении и зависимости входов проверяются на сервере одинаково для UI и внешних клиентов.

## Переключатели доступа

На странице «Настройки» есть независимые настройки:

1. **Внешний API** — включает или выключает программный доступ к управлению.
2. **Авторизация API** — требует учётные данные для внешних запросов, когда API включён.

| Внешний API | Авторизация | Поведение |
| --- | --- | --- |
| Выключен | Любое сохранённое значение | Внешние операции управления недоступны |
| Включён | Включена | Внешний клиент должен предоставить действительные учётные данные |
| Включён | Выключена | Управление доступно без учётных данных всем клиентам, имеющим сетевой доступ к API |

Работа без авторизации — поддерживаемый режим для приватного контура. Интерфейс прямо показывает текущий режим. Отключение авторизации внешнего API не отменяет индивидуальную идентификацию агентов роутеров и не определяет способ входа в веб-интерфейс.

Тумблер внешнего API не открывает порты роутера, не настраивает пробросы и не меняет сетевую доступность сервера. Размещение, адрес прослушивания и проксирование настраиваются отдельно при развёртывании.

## Контракт F19

При чистой установке и первом обновлении без сохранённых настроек внешний API выключен, защита включена, токен отсутствует. Включение API сохраняет требование авторизации. Владелец может явно разрешить управление без токена. Прежние настройки сохраняются при обновлении.

В защищённом режиме автоматизации используют один общий Bearer. Владелец видит и может скопировать значение один раз при выпуске или замене. После закрытия этого экрана доступна явная замена. Новое значение сразу отзывает старое для всех клиентов. Переключение внешнего API или его защиты сохраняет выпущенный токен. Выпуск и замена принадлежат отдельной сессии владельца.

F19 определяет контракт. Допуск реализуется в F20, чтение выбранного шаблона — в F21, условная замена исходного JSON одного существующего элемента — в F22.

## Отдельный протокол агентов

Ключ агента роутера идентифицирует устройство и даёт доступ к его конфигурации и отчётам. Токен внешнего API предназначен для административных операций. Эти полномочия не следует смешивать.

Отключение внешнего API не должно разрывать подписки роутеров или мешать им получить актуальную конфигурацию. Веб-интерфейс должен сохранять возможность снова включить API и настроить его авторизацию.

Выпуск приглашения, восстановление, замена и отзыв ключа требуют отдельного административного права. Настройка работы внешнего API без авторизации сама по себе этого права не предоставляет. Подключение агента ограничено целевым роутером и не даёт прав управления. [Спецификация D02](../openspec/specs/agent-device-credentials/spec.md).

## Следующее проектирование

- Полный контракт API и его машиночитаемое описание.
- Асинхронные операции применения: идентификатор операции, получение статуса и идемпотентность повторного запроса.
- Конкурентные изменения, проверка версии редактируемого объекта и ошибки валидации с указанием блока и переменной.
- Браузерный доступ спроектирован в [F02](../openspec/specs/web-administrator-access/spec.md). Реализация сессии относится к F03; она не даёт полномочий внешнего API.
- Сетевые параметры развёртывания и поведение при изменении настроек самим внешним клиентом.

## Настройки владельца F20

Откройте «Настройки» в веб-консоли и сохраните нужные положения «Внешний API» и «Авторизация API». При выключенном API внешние запросы получают 404. При включённой защите внешний маршрут без действительного Bearer получает 401. Выключение защиты открывает внешнее управление всем клиентам с сетевым доступом по HTTPS.

Выпустите токен, скопируйте его в защищённые настройки внешней программы и закройте однократный показ. Для ротации подтвердите «Заменить токен» и обновите значение у всех клиентов. Если ответ не получен, обновите настройки и проверьте состояние. При необходимости новой выдачи используйте явную замену. После выхода или истечения сессии секрет исчезает из интерфейса.

Настройки владельца используют собственную сессию веб-консоли. Ни внешний токен, ни отсутствие защиты внешнего API не дают права менять эти настройки. Процесс обновления хранит положение обоих переключателей и хэш токена в SQLite. Выпуск и запись из двух вкладок проверяют одну точную версию настроек.

## Чтение шаблона F21

Пример запроса к HTTPS-серверу — `GET /api/v1/templates/item?templateId=example-profile`. Передайте один ID с обычным URL-кодированием. В защищённом режиме требуется заголовок `Authorization: Bearer <token>`. При явно открытом режиме заголовок можно опустить.

Сохранённый пустой шаблон может вернуться как `{"id":"example-profile","version":"1","sections":[]}`. Версия передаётся десятичной строкой. В непустом шаблоне сохраняются порядок секций и элементов, UUID, выключения, исходный JSON как строка, переменные и текст каждого заданного дефолта. Сохраните сильный ETag конкретного ответа для условной записи F22. Ошибки не содержат исходного шаблона. [Описание OpenAPI](../openspec/changes/archive/2026-11-24-define-external-management-api/openapi.json).
