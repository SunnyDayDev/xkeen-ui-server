# Контракт установки в Entware

Это согласуемая схема G12. Реализованные команды появятся в G13–G15. Примеры ниже описывают будущую поставку. Владелец отдельно утверждает выпуск и способ передачи доверенных сумм. [Задача G12](https://github.com/SunnyDayDev/xkeen-ui-server/issues/115).

## Получение конкретной версии с GitHub

На доверенном рабочем месте получите у владельца точный Git commit установщика, SHA-256 этого файла, тег и SHA-256 `SHA256SUMS`. Подходят подтверждённое сообщение владельца или подписанное объявление с заранее известным отпечатком ключа. Сохраните эти четыре значения отдельно до скачивания. Сумма из скачанного выпуска сама по себе проверяет целостность лишь относительно скачанного манифеста.

Замените четыре значения ниже. Тег и файл установщика в примере описывают будущий выпуск.

```sh
INSTALLER_COMMIT='REPLACE_WITH_FULL_GIT_COMMIT'
INSTALLER_SHA256='REPLACE_WITH_OWNER_APPROVED_INSTALLER_SHA256'
RELEASE_TAG='vX.Y.Z'
MANIFEST_SHA256='REPLACE_WITH_OWNER_APPROVED_MANIFEST_SHA256'

umask 077
stage=$(mktemp -d) || exit 1
curl --fail --show-error --location --proto '=https' --proto-redir '=https' \
  "https://raw.githubusercontent.com/SunnyDayDev/xkeen-ui-server/$INSTALLER_COMMIT/scripts/install-entware.sh" \
  --output "$stage/install-entware.sh" || exit 1
printf '%s  %s\n' "$INSTALLER_SHA256" "$stage/install-entware.sh" | sha256sum -c - || exit 1
```

Перенесите проверенный файл и значения на целевой Entware через доверенный локальный способ. Сверьте SHA-256 ещё раз после переноса. После просмотра файла будущий интерфейс будет выглядеть так.

```sh
sh "$stage/install-entware.sh" install \
  --role agent-transport --version "$RELEASE_TAG" --manifest-sha256 "$MANIFEST_SHA256" \
  --run-as 65532:65532 --server https://controller.example:8443
```

UID/GID, сервер и путь до файла в примере заменяются параметрами владельца. Скачивание использует `https://github.com/SunnyDayDev/xkeen-ui-server/releases/download/<tag>/`. Перенаправления допустимы только по HTTPS. Установщик проверяет закреплённый `SHA256SUMS` перед получением известных имён и затем проверяет каждый необходимый файл. Служебная утилита установки, агент, supervisor и сервер имеют отдельные имена Linux ARM64. Синтетическое зеркало использует такую же раскладку и свой явный доверенный сертификат.

## Роли и локальные файлы

| Область | Размещение и владение |
| --- | --- |
| Исполняемый набор | `/opt/libexec/xkeen-ui/<role>/generations/<version>`, принадлежит root, текущий набор выбирается одной заменой в той же FS |
| Профиль запуска | `/opt/etc/xkeen-ui/<role>`, принадлежит root, отдельные несекретные параметры и read-only файлы доверия |
| Состояние | `/opt/var/lib/xkeen-ui/<role>`, приватный каталог 0700 соответствующего пользователя, данные вне поколений |
| Барьер и квитанции запуска | `/opt/var/lib/xkeen-ui/install`, защищённая область root, отдельный журнал supervisor для применения |
| Регистрация | Собственные скрипты в `/opt/etc/init.d` с проверяемым PID, временем старта и владельцем |

Транспортный агент стартует с HTTPS origin, закрытым состоянием и выбранным непривилегированным UID/GID. Приглашение оператор помещает в одноразовый приватный файл. При повторном запуске используется сохранённый ключ. Установка транспортной роли не создаёт профиль применения.

Роль с управляемым Xray включается явно. Установка проверяет фактические возможности процессов, cgroup v2, no_new_privs, pidfd и барьер запуска E03–E08. Дополнительная роль supervisor хранит отдельные защищённые конфигурацию, UID/GID, журнал и Unix-сокет. При недоказанной среде сохраняется прежняя установка. Автоматически менять правила маршрутизации хоста и назначать чужие конфигурации под управление запрещено.

## Сервер, обновление и удаление

Сервер использует собственные непривилегированные UID/GID и SQLite в постоянном каталоге. TLS и браузерный origin задаются явно. Пароль настраивается владельцем через F02 `admin setup` в терминале или из закрытого файла 0600 владельца команды. Для публикации нужен отдельный настроенный доверенный валидатор Xray. Проверка готовности сервера подтверждает слушатель после SQLite, а проверка агента учитывает соответствующий контролируемый процесс и опциональный защищённый канал.

Скачанная версия и конфигурация проходят проверку до остановки текущего процесса. Установщик держит эксклюзивный защищённый lock, фиксирует намерение до эффекта, синхронизирует подготовленные файлы и каталоги и меняет только ссылку текущего поколения. Точный отказ загрузки оставляет прежний процесс и данные. После неуспешного запуска можно вернуть прежнее поколение при доказанной совместимости фактического состояния.

Для серверной миграции отдельно проверяются схема, возможность полного согласованного резерва и доступность предыдущей версии. Если новый процесс мог необратимо изменить формат, автоматический запуск прежней версии запрещён. Текущая база и резерв сохраняются для осознанного восстановления. При удалении останавливается только подтверждённая служба и снимается собственная регистрация. Ключ, настройки, журнал и SQLite сохраняются. Очистка данных требует отдельной операции владельца.

В G12 проверены Entware ARM64 и BusyBox 1.38.0. Доступны `sh`, `curl`, `sha256sum`, `mktemp`, `readlink`, `mv -T`, `start-stop-daemon` и `rc.unslung`. BusyBox `sync` не предоставляет проверку fsync конкретного файла. `flock` был доступен в базовом Debian стенда, поэтому контракт не требует его от Entware. Для жизненного цикла используется защита по конкретному экземпляру процесса. Реализация должна подтвердить её отдельными испытаниями.
