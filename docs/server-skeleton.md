# Каркас сервера: запуск и проверка

Go-сервер открывает SQLite, применяет миграции, обслуживает HTTP-проверку процесса и штатно останавливается. С опциональным TLS сервер также подключает агент, проверяет рабочий ключ и выдаёт зафиксированную желаемую ревизию. `/healthz` подтверждает доступность процесса. HTTPS также обслуживает сессии администратора при включении браузерных маршрутов. Оболочка UI, внешний API управления и применение ревизий относятся к отдельным этапам.

## Toolchain

Для разработки используется **Go 1.27.1**. SDK нужен на машине сборки; готовый бинарник работает без установленного Go. `go.mod` задаёт языковую версию 1.27.0 и рекомендуемый toolchain 1.27.1. Перед проверками убедитесь в фактической версии:

```sh
go version
```

Установщик для своей ОС и архитектуры можно получить на [официальной странице Go](https://go.dev/dl/). Пример установки SDK в локальный каталог проекта на **Linux aarch64**, выполняемый из корня репозитория:

```sh
mkdir -p .build/toolchain
curl -fL -o .build/toolchain/go.tar.gz https://dl.google.com/go/go1.27.1.linux-arm64.tar.gz
printf '%s\n' '3450b45a3f9ee8568792736a5c5e70a1f2e9b36c35a8f74958c03e51d7d92bec  .build/toolchain/go.tar.gz' | sha256sum -c -
tar -xzf .build/toolchain/go.tar.gz -C .build/toolchain
export PATH="$PWD/.build/toolchain/go/bin:$PATH"
export GOTOOLCHAIN=local
go version
```

При этой проверке macOS-архив версии 1.27.1 возвращал 404. Нативный SDK macOS ARM64 был получен через [официальный toolchain proxy](https://proxy.golang.org/golang.org/toolchain/@v/v0.0.1-go1.27.1.darwin-arm64.zip) с проверкой модульной суммы по [Go checksum database](https://sum.golang.org/lookup/golang.org/toolchain@v0.0.1-go1.27.1.darwin-arm64). Это отдельный канал поставки той же версии, а не смена toolchain.

## Запуск

Из корня проекта, при доступном `go` в PATH:

```sh
sh scripts/run-server.sh
```

Скрипт собирает `.build/xkeen-ui-server` без cgo и через `exec` запускает его в foreground. Ошибка сборки прекращает запуск. Адрес по умолчанию — `127.0.0.1:8080`. В другом терминале:

```sh
curl --noproxy '*' -i http://127.0.0.1:8080/healthz
```

Ответ: HTTP 200, `Content-Type: application/json`, тело:

```json
{"status":"ok"}
```

Параметр адреса и помощь доступны как через скрипт, так и непосредственно у бинарника:

```sh
sh scripts/run-server.sh --listen 127.0.0.1:8081
```

```sh
./.build/xkeen-ui-server --help
./.build/xkeen-ui-server --listen '[::1]:0'
```

Запускайте один из приведённых вариантов. `--listen` принимает IP literal и порт 0–65535; порт 0 выбирается ОС. Фактический адрес выводится в stderr как JSON-запись с `event: "listening"`. Hostnames, пустой host и позиционные аргументы не поддерживаются. Явный `0.0.0.0:8080` или `[::]:8080` открывает прослушивание доступных сетевых интерфейсов; по умолчанию используется только loopback.

Без TLS доступен `GET /healthz`. Другие методы на нём возвращают 405 и `Allow: GET`. Неизвестные пути возвращают 404.

## HTTPS-подключение агента D03

Укажите цепочку сертификата в PEM и соответствующий приватный ключ. При ошибке пары сервер выводит безопасную диагностику и завершает запуск до открытия SQLite и порта.

```sh
sh scripts/run-server.sh --listen 127.0.0.1:8443 --tls-cert cert.pem --tls-key key.pem
curl --noproxy '*' --cacert ca.pem https://127.0.0.1:8443/healthz
```

Сертификат в примере должен включать IP `127.0.0.1` в Subject Alternative Name, а `ca.pem` должен доверять его издателю. HTTPS требует TLS 1.2 или новее. TLS до origin обязателен для защищённых маршрутов. При завершении TLS на обратном прокси потребуется отдельное соединение с TLS до этого Go-сервера.

В режиме HTTPS доступны `POST /agent/v1/enroll` с приглашением в bearer-заголовке и рабочим кандидатом в JSON, а также `GET /agent/v1/identity` с рабочим ключом в том же заголовке. Оба возвращают только технический ID области ключа. Выпуск, замена и отзыв выполняются внутренним серверным сервисом; операторский HTTP API появится отдельно. Обратный прокси и диагностика должны исключать запись заголовка авторизации и тела привязки. [Спецификация подключения](../openspec/specs/agent-server-enrollment/spec.md).

`GET /agent/v1/desired` возвращает полный последний снимок в области рабочего ключа. Ответ 204 обозначает отсутствие ревизии; 304 означает совпадение с сильным ETag полной копии. HTTP-посредник не должен кэшировать или преобразовывать ответ. [Получение желаемой ревизии D05](router-agent.md#получение-желаемой-ревизии-d05).

## Сессия администратора F03

Для веб-сессий укажите публичный HTTPS origin вместе с парой TLS. Используйте тот же файл SQLite для запуска и команды администратора. Выполняйте команду локально под учётной записью, которой доступны файл и каталог базы.

```sh
mkdir -p state
sh scripts/run-server.sh admin setup --db-path state/server.sqlite
sh scripts/run-server.sh --listen 127.0.0.1:8443 --db-path state/server.sqlite \
  --tls-cert cert.pem --tls-key key.pem --web-origin https://admin.example:8443
```

Команда запрашивает пароль дважды без эха и восстанавливает режим терминала при отмене. Для установки из файла добавьте `--password-file PATH`. Файл должен принадлежать эффективному пользователю команды, быть обычным файлом с правами 0600 и без дополнительных ссылок. Допускается один завершающий перевод строки LF или CRLF. Пароль должен содержать не менее 15 символов и занимать не более 1024 байт UTF-8. Команда `admin reset` принимает те же параметры, требует существующую базу с администратором и отзывает все ранее выданные веб-сессии.

Прокси передаёт исходный `Host`, а соединение от прокси до Go-сервера также использует TLS с проверкой сертификата. Отключите протоколирование тела входа, cookie и защитного заголовка. При запуске без `--web-origin` браузерные маршруты выключены. Агент по-прежнему использует своё полномочие.

| Запрос | Результат |
| --- | --- |
| `GET /ui/v1/session` | `setup_required`, `signed_out` или `active` с `csrf`. Чтение не продлевает сессию. |
| `POST /ui/v1/login` | JSON с одним строковым полем `password`; ответ `active` с `csrf` и новой защищённой cookie. |
| `POST /ui/v1/session/activity` | Подтверждение явного действия, продлевающее срок бездействия. |
| `POST /ui/v1/logout` | Отзыв текущей сессии, ответ `signed_out`. |

Каждый POST требует соответствующий `Origin`. Продление и выход требуют полученные cookie и `X-CSRF-Token`. Сервер принимает сессию до 30 минут без действия и не дольше 12 часов от входа. Cookie хранится в браузере не дольше 12 часов. Принятые сессии переживают перезапуск с той же базой. После пяти неверных проверок в 30-секундном окне последуют временные отказы до конца окна; сервер выполняет по одной проверке пароля одновременно. Вход с неверным паролем даёт 401 и `invalid_credentials`, вход до локальной настройки даёт 409 и `setup_required`. Статус 429 и `rate_limited` означают ожидание повторной попытки. При временной недоступности возвращаются 503 и `unavailable`.

Проверка `sh lab/check-web-administrator.sh` запускает реальные сборки и проверяет TLS, локальные setup/reset, SQLite, перезапуск и отзыв в отдельном Entware aarch64-k3.10 под LinuxKit 7.0.14. В пробе с лимитом 256 МиБ и отключённым swap совокупный пик контейнера составил около 174–178 МиБ, OOM-убийств не было. Argon2id использует 64 МиБ, три итерации и четыре линии. Измерение относится к лабораторному ядру и синтетическому сценарию. [Контракт веб-доступа](../openspec/specs/web-administrator-access/spec.md).

## Веб-оболочка F04

При настроенном `--web-origin` откройте `/ui/` на соответствующем HTTPS origin. Сначала настройте пароль локальной командой F03. Оболочка использует тот же серверный вход, выход и состояние сессии. Если сессия истекла, открытая вкладка удерживает локальную область работы и после входа не отправляет изменения автоматически.

Svelte-сборка встроена в Go-бинарник. На машине запуска Node не требуется. После правок клиентских файлов пересоберите вложенную выдачу из корня репозитория.

```sh
npm --prefix web ci
npm --prefix web run build
go build -o .build/xkeen-ui-server ./cmd/xkeen-ui-server
```

Сборка проверена на Node 26.5.0. Повторный build сверяют командой `git diff --exit-code -- internal/server/webdist`. Действующий CI проверяет выдачу встроенных файлов через HTTPS.

## Список шаблонов F05

Раздел «Шаблоны» доступен из консоли и напрямую по `/ui/templates`. В нём видны точный идентификатор и версия каждого сохранённого черновика. При сбое чтения можно повторить запрос. Истечение сессии скрывает список, повторный вход возвращает к текущему разделу.

Браузер читает `GET /ui/v1/templates` с действующей cookie F03. Ответ не продлевает сессию и не кешируется. Пример ответа.

```json
{"templates":[{"id":"branch-east","version":"2"}]}
```

Версия передаётся строкой, чтобы сохранить точность int64. Для пустого хранилища возвращается `{"templates":[]}`. При недействующей сессии сервер отвечает 401 и `signed_out`, при недоступном хранилище — 503 и `unavailable`. [Контракт списка](../openspec/specs/web-template-list/spec.md).

## Создание шаблона F06

В разделе «Шаблоны» нажмите «Создать шаблон», введите стабильный идентификатор и подтвердите действие. Идентификатор сохраняется с исходным регистром и пробелами. Пустой черновик получает версию 1 и появляется в списке. Повторный ID оставляет существующий черновик на месте.

Форма использует `POST /ui/v1/templates` с действующей cookie, соответствующим `Origin`, `X-CSRF-Token` и одним полем в JSON-конверте до 8 КиБ.

```json
{"id":"branch-east"}
```

Ответ 201 содержит точный `id` и версию `"1"`. Конфликт возвращает 409 и `template_exists`. Успешная запись продлевает срок бездействия на условиях F03. При истечении сессии вкладка удерживает введённый ID. После входа создание снова требует явного подтверждения. [Контракт создания](../openspec/specs/web-template-create/spec.md).

## Точный редактор шаблона F07

Из списка откройте ID шаблона. В пустом шаблоне выберите поддерживаемую группу Xray. Новая запись появляется только при кнопке «Создать элемент». При правке существующего элемента UUID и расположение сохраняются. Редактор передаёт исходный JSON как текст, включая произвольные поля, форматирование и точные числа. Содержимое проходит проверку структуры A08 при явном сохранении. Сохранение черновика не меняет опубликованную конфигурацию.

Браузер использует приватный маршрут `/ui/v1/templates/item` и передаёт точный `templateId` в запросе. Чтение возвращает строковую версию и выбранный элемент. Запись ограничена 8 МиБ для JSON-конверта и требует тот же шаблон, прочитанную версию, HTTPS-сессию и CSRF. В пустом шаблоне указывается секция. Обычная правка задаёт UUID. Синтаксические ошибки отмечаются у редактора. После конфликта можно прочитать актуальную версию, сохранив открытый текст. Повторный вход не отправляет черновик автоматически.

## Подготовка роутера F09

В «Обзоре» откройте «Подключить роутер». Введите имя, выберите шаблон и заполните обязательные персональные значения. Вид источника и точная версия показаны в форме. Если шаблон уже принят, используется его принятый снимок. При первой подготовке из черновика явное подтверждение может принять его и зафиксировать первую желаемую ревизию тем же действием.

Запустите сервер с браузерным HTTPS из F03 и одним режимом [изолированной проверки Xray](catalog-validator.md). Для локального worker добавьте `--validator-socket /path/to/validator.sock`. Для удалённого worker укажите полный набор.

```sh
--validator-origin https://validator.example:8444 \
  --validator-ca worker-ca.pem \
  --validator-client-cert controller.pem \
  --validator-client-key controller-key.pem
```

Удалённый worker получает весь каталог для проверки. При отсутствии проверки подтверждение не сохраняет назначение. Остальные браузерные маршруты доступны. После истечения сессии войдите снова для возврата к форме. При неопределённом исходе нажмите «Проверить результат», чтобы прочитать сохранённое состояние по выданному ID. Раздел показывает первую желаемую ревизию и ID подготовленного роутера. Приглашение входит в отдельный шаг F10.

Внутренний маршрут `/ui/v1/routers/prepare` читает источник с одним `templateId` или результат с одним `routerId`. Подтверждение использует POST с браузерными cookie, origin и CSRF. Значения отправляются как JSON-текст, а версия и номер ревизии как десятичные строки. [Контракт F09](../openspec/specs/web-router-preparation/spec.md).
