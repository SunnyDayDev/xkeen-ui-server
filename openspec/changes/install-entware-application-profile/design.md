## Границы первого поддерживаемого профиля

Отдельная роль `agent-application` получает проверенные installer, agent и supervisor из одного выпуска. Установка закрепляет пары защищённых конфигураций E02/E03 и проверяет допустимый профиль E08 c `ReportVersion=1`. Ключ приглашения переносится в приватное состояние агента по G13. Сопоставлять нормализованный HTTPS origin, конкретный RouterID, агентский UID/GID и verifier ID. Сверить файловый и сетевой профили с защищённой локальной конфигурацией. Отказ не меняет прежний транспорт и установленный Xray. Новая роль не автоматически заменяет существующую транспортную службу.

Первоначальный baseline выделенного Xray подтверждается один раз доверенным владельцем по штатным командам `--working-manifest` и `--working-process` с точной контрольной суммой закреплённого бинарника. Вторые, следующие и возобновлённые запуски читают защищённый журнал E03–E08. Путь рабочего каталога, Xray, сgroup и сокеты не определяются удалённым запросом. Файлы чужого процесса не усыновляются. Сценарий без доступных cgroup v2, pidfd, проверяемых владельца/исполняемого файла и `no_new_privs` возвращает отказ. Привилегированный supervisor получает наследуемый NNP только для поддерживаемого запуска и минимальные фиксированные параметры. Профиль горячего применения сохраняет отдельные проверки E06/E07.

Готовность доказывается отдельно для субъектов. Supervisor использует подтверждённый экземпляр и действующий защищённый сокет в той же области. Agent запускается после локального барьера и выполняет своё штатное подключение. Если E05 оставляет законный report-only барьер, установленное состояние не объявляется готовым к применению. При неготовом первом запуске регистрация не становится активной. Остановка не сигнализирует чужим процессам и не очищает журналы, ключи или каталог Xray.

Штатный end-to-end G18 остаётся отдельной приёмкой. Он получает приглашение и публикацию через реально поставляемые F09/F10/F18, сохраняет синтетические данные и проверяет восстановление через разрыв связи.
