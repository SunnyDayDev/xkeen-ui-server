## MODIFIED Requirements

### Requirement: Template draft is created once by stable identity

Сервис SHALL предоставлять создание и чтение черновика по явно переданному непустому UTF-8 ID. Идентификаторы SHALL сравниваться точно. Повторное создание SHALL возвращать конфликт без замены записи. Чтение отсутствующего ID SHALL возвращать признак отсутствия. Создание SHALL назначать версию 1. Успешные создание и чтение SHALL возвращать полный снимок и его версию вместе.

#### Scenario: An empty draft can be created
- **WHEN** создание получает ранее не использованный корректный ID и пустой черновик
- **THEN** создание и чтение по тому же ID возвращают пустой черновик с этим ID и версией 1

#### Scenario: Duplicate creation preserves the committed draft
- **WHEN** создание получает ID уже сохранённого черновика
- **THEN** возвращается конфликт и чтение продолжает возвращать исходный черновик с прежней версией

#### Scenario: Unknown identity is distinct from an empty draft
- **WHEN** чтение получает корректный, но неизвестный ID
- **THEN** возвращается признак отсутствия без черновика и версии

#### Scenario: Invalid identity
- **WHEN** создание или чтение получает пустой ID или невалидный UTF-8
- **THEN** возвращается ошибка структуры без изменения сохранённых записей

#### Scenario: Existing drafts retain their content at upgrade
- **GIVEN** файл с черновиками, созданными до введения версий
- **WHEN** хранилище открыто после обновления
- **THEN** каждый черновик читается по прежнему ID с полным прежним содержимым и версией 1

## ADDED Requirements

### Requirement: Draft replacement checks and advances the template version

Замена SHALL принимать полный кандидат для существующего ID и ожидаемую версию. Версия SHALL быть положительным целым числом в диапазоне знакового 64-разрядного числа и относиться к одному ID. Если версия совпадает, сервис SHALL атомарно заменить содержимое, сохранив ID, повысить версию ровно на один и вернуть зафиксированный снимок с новой версией. Каждое успешное сохранение SHALL повышать версию, включая повтор того же содержимого.

#### Scenario: Current version permits a complete replacement
- **GIVEN** шаблон с версией 1
- **WHEN** потребитель передаёт этот ID, ожидаемую версию 1 и полный новый черновик
- **THEN** сервис возвращает полный новый снимок с тем же ID и версией 2
- **AND** повторное открытие хранилища возвращает новый снимок и версию 2

#### Scenario: Unchanged content still advances the version
- **WHEN** с текущей ожидаемой версией передан полный снимок с исходным содержимым
- **THEN** операция сохраняет это содержимое и возвращает следующую версию

#### Scenario: Replacement follows existing draft rules
- **WHEN** полная замена содержит структурно корректный черновик с неготовым к сборке элементом, удалённой секцией, явно пустой группой или изменённым полным порядком
- **THEN** сервис применяет обычную подготовку элементов и сохраняет именно переданный полный снимок
- **AND** этот результат используется только как редактируемый черновик


#### Scenario: An element identity follows its UUID
- **WHEN** корректный новый снимок содержит другой UUID в позиции прежнего элемента
- **THEN** старый UUID отсутствует в новом снимке, а новая запись сохраняется со своим UUID
- **AND** персональные ссылки, сохранённые в снимках роутеров, остаются прежними

### Requirement: Rejected replacement preserves committed contents and version

Сервис SHALL проверять ID, ожидаемую версию и структуру кандидата до записи. Для корректного кандидата устаревшая или отличающаяся версия SHALL давать `version_conflict`. Неизвестный ID SHALL давать результат отсутствия. При отказе прежние содержимое и версия SHALL сохраняться. Диагностика SHALL исключать значения черновика.

#### Scenario: Two writers use the same snapshot version
- **WHEN** два потребителя передают различные корректные правки одного ID с одной текущей ожидаемой версией при штатном доступе к хранилищу
- **THEN** одна правка сохраняется, вторая получает `version_conflict`
- **AND** сохраняются содержимое победившей правки и одна следующая версия

#### Scenario: Stale version cannot overwrite a later save
- **GIVEN** потребитель прочитал снимок с версией 1, а другой потребитель записал версию 2
- **WHEN** первый потребитель отправляет корректную правку с ожидаемой версией 1
- **THEN** он получает `version_conflict`, а версия 2 и её содержимое по-прежнему читаются

#### Scenario: Unknown identity cannot be created through replacement
- **WHEN** корректный кандидат указывает на отсутствующий ID
- **THEN** сервис возвращает результат отсутствия и запись не появляется

#### Scenario: Invalid version or invalid draft fails before replacement
- **WHEN** ожидаемая версия отсутствует, равна нулю или отрицательна, либо кандидат имеет неверный ID, структуру или дубли UUID
- **THEN** сервис возвращает соответствующую ошибку входных данных без новой версии или частичной записи

#### Scenario: The version cannot wrap around
- **GIVEN** актуальная версия равна максимальному поддерживаемому числу
- **WHEN** передан корректный кандидат с этой ожидаемой версией
- **THEN** сервис возвращает ошибку исчерпания версии, сохраняя актуальные данные и версию

#### Scenario: Repository failure preserves the previous snapshot
- **WHEN** при обработке корректного кандидата возникает ошибка постоянной записи
- **THEN** сервис возвращает безопасную ошибку, а прежний снимок и его версия остаются доступными
