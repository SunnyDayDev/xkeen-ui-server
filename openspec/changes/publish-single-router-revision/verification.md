# Проверка C06.4

## Разработка

- Red для прикладного набора воспроизвёл отсутствие `Publish`, типов команды и результата. После реализации прошли целевые тесты `./internal/application/publication` и `./internal/storage/sqlite`, включая запуск с `-race`.
- Независимое ревью выявило неверную классификацию ответа валидатора, который одновременно менял входные байты и возвращал отказ Xray. Регрессия сначала вернула `ErrCatalogRejected` при ожидаемом `ErrValidatorUnavailable`. После проверки равенства перед разбором результата тест прошёл.
- SQLite-сценарий с тестовым валидатором независимо прошёл 20 раз. Сценарий использует два соединения и повторное открытие базы.

## Сквозная проверка

`TestSingleRouterPublicationWithIsolatedXray` запускает тот же сценарий с локальным клиентом C06.2 и настоящим Xray 26.3.27 в одноразовых Docker-контейнерах. Один прогон проверяет первое подтверждение, совпавший каталог, следующую ревизию, отказ Xray для неизвестного протокола, независимое изменение неиспользованного черновика и конфликт при изменении использованного источника. Повторное открытие SQLite подтверждает сохранность принятого шаблона, ревизии и точных байтов. Временная база и каталоги содержат только искусственные данные.

Соберите проверочный образ по инструкции [стенда](../../../lab/README.md). Запустите локальный worker с приватным Unix-сокетом и передайте его абсолютный путь тесту.

```sh
XKEEN_TEST_VALIDATOR_SOCKET="$VALIDATOR_SOCKET" go test ./internal/storage/sqlite -run '^TestSingleRouterPublicationWithIsolatedXray$' -count=1 -v
```

Первая объединённая проба C06.4 `ff8e32f` и адаптера C06.2 `d995f16` прошла. Независимый рецензент повторил её успешно. Повтор с адаптером `2f2e44d`, который сверяет смонтированные файлы непосредственно перед запуском Xray, также прошёл. В этой сборке прошли `go test ./...`, `go test -race ./...`, `go vet ./...`, строгая проверка OpenSpec и Linux-сборки ARM64/AMD64 с `CGO_ENABLED=0`.
