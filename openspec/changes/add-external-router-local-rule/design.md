## Context

Полный порядок задан B08 и хранится вместе с основанием F14. F20 действует независимо от владелецкой и агентской авторизации.

## Decisions

- GET и POST `/api/v1/routers/rules?routerId=<exact>`. GET возвращает только полный порядок UUID с происхождением и состояниями и сильный ETag точных трёх поколений по #179. Ответ не содержит исходники соседних правил.
- POST требует один If-Match, `{"afterId":"","source":"{}"}` для начала либо UUID правила, за которым выполняется вставка. Поле afterId обязательно, а пустая строка явно задаёт начало. Пропущенное или null поле отклоняется. В расчёт входят исключённые и выключенные строки. Сервер назначает UUID по F14. Правило, новый полный список и подтверждённое основание F14 сохраняются атомарно. Успех возвращает 201 и обновлённый полный порядок с новым UUID и ETag.
- Переиспользовать DraftRules.Insert, проверку коллизий всех секций, неизменные проверки B06/B08 и guarded WriteOrder. F20 и текущие версии проверяются внутри writer. Ошибки не выдают частичного правила, чужих настроек и исходников. При неизвестном результате сначала GET.

## Risks / Trade-offs

Любая операция требует актуального общего основания. После конфликта клиент перечитывает порядок.
