## Context

F05 открывает и читает список F03 из одного снимка с авторизацией. C02 готовит полный черновик и вставляет в SQLite, C03 задаёт положительную версию. Исходный экран 01 O42w4v показывает создание из раздела «Шаблоны». В F06 форма появится внутри текущего раздела на основе экрана F05 и не ведёт в будущий редактор.

## Goals / Non-Goals

**Goals:** создать один пустой черновик, обновить фактический список, сохранить введённый ID при восстановлении сессии.

**Non-Goals:** rename, отдельное отображаемое имя, принудительный UUID шаблона, копирование, редактор, внешний API и публикация.

## Decisions

1. POST /ui/v1/templates принимает только application/json с точным id, с ограничением тела 8 КиБ как у входа F03. Для неверного Content-Type и превышения лимита возвращаются 415 и 413. После подтверждения ответ 201 имеет форму {"id":"branch-east","version":"1"}. Состояния ошибок используют конверт F03, пригодный для UI. Дубликат — 409 template_exists. Чтение F05 продолжает использовать GET.
2. Браузерный сценарий разбирает cookie и проверяет CSRF текущим правилом F03. Ядро готовит пустой configuration.TemplateDraft одним путём C02. Адаптер SQLite использует тот же INSERT, что C02, и проверяет сессию по поколению и срокам в BEGIN IMMEDIATE непосредственно перед действием. Продление активности и создание фиксируются в одной транзакции. Конфликт, отзыв, истечение и ошибка откатывают изменения. F07/F08 смогут использовать тот же механизм авторизации записи и SQL-тело условной замены C03, когда их подключат.
3. Открытая форма встроена в существующий раздел. После успеха перечитывается GET F05. При неустранимой ошибке чтения подтверждение созданного ID остаётся видимым. Истечение использует оболочку F04 и состояние формы внутри текущей вкладки. Неизвестный результат не инициирует повтор записи. Закрытие формы, подтверждённый выход и уход со страницы сохраняют обычную семантику закрытия редактора F02. В Pencil нужны открытие, отправка, дубликат, успех, узкая компоновка и возвращение к форме после входа.

## Risks / Trade-offs

- Точное значение допускает различия по регистру и пробелам, как C02. Поле явно отделяет идентификатор от произвольного имени.
- Сбой ответа после коммита оставляет результат неизвестным клиенту. Повторное чтение может показать запись. Повторная ручная отправка того же ID приведёт к конфликту без изменения.
- Предел тела относится к этому браузерному конверту. Чтение существующих ID F05 остаётся доступным в полном диапазоне C02.
