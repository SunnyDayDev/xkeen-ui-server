## Context

В закреплённом S05xkeen функция load_user_ipset_family удаляет CR и комментарии, пропускает пустые строки, выделяет адреса регулярным выражением и загружает временный hash:net командой ipset restore -exist. После успеха подменяет основной набор. Загрузка IPv4 и IPv6 зависит от отдельных флагов. Режим Other сам по себе не подтверждает прозрачный перехват.

## Decisions

Синтаксис продукта строже извлечения подстрок штатным скриптом. Стандартный net/netip проверяет всю запись. Произвольные пробелы допускаются только вокруг записи/комментария. Запись с установленными битами хоста отклоняется, чтобы случайно не исключить большую сеть. Для host prefix /32 или /128 использовать одно представление обычного адреса. Для прочих диапазонов сохранять порядок, без укрупнения перекрывающихся сетей. Предлагается отклонять mapped IPv6 и /0, которые не обеспечивают однозначный результат в двух регулярных выражениях и hash:net соответственно. Проверить закреплённый IPv6 parser на каждой выдаваемой форме.

Отдельный доменный тип исключений не проходит B12 или Xray -test. Постоянные записи принадлежат шаблону и стабильному UUID; отдельная форма замены хранит персональные значения. Успешная сборка не меняет систему маршрутизации.

## Risks / Trade-offs

Владелец выбирает поведение Xray-only при наличии настроенного списка. Предложено блокировать публикацию и показывать причину. Решение ожидается. Документировать нулевой список отдельно, так как явное очищение имеет эффект на XKeen.

## Isolated evidence

Одноразовый контейнер без сети и томов с NET_ADMIN и NET_RAW успешно создал hash:net, проверил адрес диапазона документации, прочитал таблицы nat для IPv4 и IPv6. С одним NET_ADMIN legacy iptables не открывал raw socket. Запросы трафика и интеграция со штатным XKeen относятся к G09.

Штатная функция из образа создала оба набора и приняла 192.0.2.0/24, ::1, 2001:db8::/32 и полную восьмигрупповую запись IPv6. ipset v7.24 отверг /0 обеих семей и принял /32, /128. Публикуемые примеры используют документационные адреса, стенд не подключался к роутерам.

### Привязка к публикации

Подтверждение первой персональной ревизии C06 проверяет готовность кандидата этого роутера до записи. C07 считает участников по принятым назначениям, включая offline-устройства; ожидающая смена на B не делает B действующим. Для каждого участника предварительно рассчитываются собственные значения/замена и возможность устройства; перед финальной записью сравниваются все использованные версии. При выбранной владельцем блокирующей политике отказ одного участника отменяет запись всего C07, включая общий принятый снимок. При политике допуска частичного результата каждому участнику требуется явное отдельное состояние XKeen; успешный E08 для Xray сам по себе не подтверждает firewall. Обе альтернативы сохраняют атомарность C07, решение между ними ожидается в #166.

Устройство офлайн использует только ранее подтверждённые сведения о возможности, неизвестная возможность остаётся отдельным состоянием. При нуле участников C07 может сохранить принятый общий источник; доказательства исполнения на устройстве при этом нет. Сохранение незавершённого черновика разрешено независимо от политики публикации.
