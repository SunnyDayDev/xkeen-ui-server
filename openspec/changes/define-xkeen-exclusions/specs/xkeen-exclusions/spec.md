## ADDED Requirements

### Requirement: Exact authoring and bounded text substitution

Редактор SHALL сохранять исходный текст и стабильный UUID. В режиме наследования сборка SHALL разрешать ссылку `${name}` в позиции всей записи как строковое значение IP или CIDR. Имя с точкой сравнивается целиком. Комментарии и пустые строки не требуют значений. Сборка SHALL отклонять отсутствующее значение, значение с переводом строки, рекурсивную ссылку, неподдерживаемый тип и несколько записей в строке, сохраняя исходный черновик.

#### Scenario: Literal full override

- **WHEN** роутер выбирает полную персональную замену
- **THEN** записи проверяются как буквальные адреса, UUID сохраняется, исходный общий шаблон и персональные значения остаются доступны

### Requirement: Deterministic ip_exclude.lst

Сборка SHALL принять отдельный IPv4 или IPv6 адрес либо корректную сеть CIDR, пустые строки, CRLF и комментарии от знака #. После проверки всех строк она SHALL выдать файл UTF-8 с LF в порядке первых вхождений, без комментариев или повторных идентичных адресных диапазонов. Пустой явно настроенный список SHALL выдавать файл нулевой длины. Отсутствие настройки SHALL оставлять файл вне результата.

#### Scenario: Invalid address does not yield a partial file

- **WHEN** хотя бы одна запись содержит имя узла, scoped IPv6, неканонический сетевой адрес с установленными host bits, адрес с портом префикс /0 любой семьи, IPv4-mapped IPv6, повреждённый UTF-8 либо неподдерживаемую семью назначения
- **THEN** результат содержит безопасную позицию ошибки без фрагмента введённого текста, частичный файл отсутствует

#### Scenario: Separate evidence

- **WHEN** сервер собрал файл либо Xray подтвердил валидность своего JSON-каталога
- **THEN** система различает это состояние и подтверждённое применение исключений XKeen

#### Scenario: Host prefix deduplication

- **WHEN** список повторяет адрес IPv4 как /32 или адрес IPv6 как /128
- **THEN** файл содержит один обычный адрес на каждый диапазон в порядке его первого появления
