## Границы

Повторно использовать shell bootstrap G13 для ассетов установщика и сервера. Под отдельным lock проверить UID/GID, адрес, WebOrigin, PEM и связанный ключ до эффектов. Профиль хранит только значения запуска и проверяемые идентификаторы данных. Сертификат root-owned 0644. TLS-ключ root-owned 0640 с группой выделенного процесса, проверяется как обычный файл с одной ссылкой и сверяется с защищённым назначением. Ключ не передаётся в аргументах, журналах или release artifact. Обе исходные TLS-записи остаются у оператора. Серверный SQLite хранится под выделенным UID в каталоге 0700, отдельно от агента и переустанавливаемых бинарников.

Защищённая серверная служба использует ту же идентификацию экземпляра, дисциплину lock/receipt и проверку готовности текущего процесса, что агент. Готовность читает свежую отметку слушателя и выполняет отдельный TLS GET /healthz к назначенному адресу с проверкой доверенного сертификата и origin. При всех интерфейсах локальная проверка использует loopback того же семейства. Закрепить конкретный порт и убедиться, что проверяемый endpoint принадлежит текущему экземпляру. Режим init.d публикуется после готовности.

Для локальной настройки владелец запускает сохранённый серверный бинарник как назначенный UID/GID и передаёт штатный `admin setup` с установленным DB path. Посредник принимает варианты интерактивного терминала или отдельный путь файла 0600 владельца службы и сохраняет штатные ограничения F02. Внешний валидатор подключает только явная настройка с действительным серверным швом F09/F18. Не подменять отсутствие валидатора разрешением публикации.

Проверка использует HTTPS зеркало, реальные сервер, F04 UI, сессию и SQLite в ARM64 Entware. Обновление серверной базы, удаление и автоматические миграционные откаты выходят за эту задачу.
