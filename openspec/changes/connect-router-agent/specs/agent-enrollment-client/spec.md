## Purpose

Запустить агент роутера, связать его с настроенным сервером и устойчиво проверить собственную регистрацию.

## ADDED Requirements

### Requirement: Agent authenticates outbound on its configured HTTPS origin

Агент SHALL подключаться к настроенному HTTPS origin с проверкой доверия и имени. Для первого подключения он SHALL привязать рабочий ключ и проверить его через D03. Успех SHALL сохранять технический ID и оставлять агент работающим до штатной остановки. Подключение SHALL не регистрировать контакт, не подтверждать применение и не менять файлы конфигурации Xray.

#### Scenario: An agent enrolls the prepared router and remains running

- **GIVEN** агент получил действующее приглашение для подготовленного роутера
- **WHEN** запускается процесс агента и сервер принимает подключение по TLS
- **THEN** сервер D03 подтверждает действующий ключ и технический ID, а агент сохраняет привязку
- **AND** процесс остаётся доступен для штатной остановки без применения конфигурации

#### Scenario: An untrusted server cannot receive credentials

- **WHEN** сертификат не подтверждён, имя не совпадает либо URL не использует HTTPS
- **THEN** агент прекращает подключение безопасно

#### Scenario: A redirect or unexpected device identity is rejected

- **WHEN** сервер перенаправляет запрос либо ответ сообщает другой ID для сохранённой привязки
- **THEN** агент отклоняет ответ и сохраняет прежнюю идентичность без переноса секрета

### Requirement: Agent persists its credential before enrollment

Агент SHALL сохранять рабочий кандидат до первого запроса привязки. Локальная запись SHALL быть закрыта для других пользователей и привязана к исходному origin. Запись ключа и ID SHALL заменяться атомарно. Секреты SHALL поступать из закрытых файлов и отсутствовать в аргументах, URL, обычных сообщениях и ошибках.

#### Scenario: Failed local persistence blocks enrollment

- **WHEN** агент не может надёжно записать рабочий кандидат
- **THEN** запрос привязки не отправляется

#### Scenario: Concurrent processes using the same state do not create a second candidate

- **WHEN** другой процесс уже работает с тем же каталогом состояния
- **THEN** второй процесс безопасно отказывает до создания кандидата или запроса

#### Scenario: A changed server origin cannot receive the stored key

- **WHEN** рабочий кандидат или привязка сохранены для другого origin
- **THEN** агент прекращает запуск без обращения к новому origin

### Requirement: Agent recovers one pending or active registration after interruption

Агент SHALL проверять сохранённый ключ через D03 при запуске. Для ожидающего ключа подтверждённый отказ допускает точный повтор с тем же приглашением и кандидатом. Активный ключ SHALL использоваться без нового приглашения. Временный сбой допускает ограниченный отменяемый повтор с тем же состоянием.

#### Scenario: Lost enrollment response and process restart

- **WHEN** сервер зафиксировал привязку, но ответ потерян и процесс перезапущен
- **THEN** агент проверяет сохранённый кандидат и восстанавливает прежний технический ID

#### Scenario: A request that was not committed can be replayed

- **WHEN** сохранённый кандидат ожидает привязки, сервер подтвердил, что кандидат пока не действует, а приглашение ещё пригодно
- **THEN** агент повторяет запрос с тем же кандидатом

#### Scenario: A fresh launch with an active key needs no invitation

- **WHEN** агент запускается с сохранённой действующей привязкой
- **THEN** он подтверждает прежний ID без выдачи нового ключа или использования приглашения

#### Scenario: Unclear or temporary results do not replace the candidate

- **WHEN** сеть недоступна, ответ утрачен, сервер временно недоступен либо отказ нельзя подтвердить
- **THEN** агент сохраняет прежний кандидат, а допустимые повторы остаются ограниченными и отменяемыми

#### Scenario: A rejected active key requires operator recovery

- **WHEN** сервер отвергает сохранённый активный ключ
- **THEN** агент завершает подключение безопасно и сохраняет данные для восстановления
