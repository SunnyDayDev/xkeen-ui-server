## Context

C02/C03 уже читают целый черновик и условно заменяют его. C02 хранит исходный JSON элемента строкой, A08 добавляет декларации по целым ссылкам. F05/F06 предоставят список и создание пустого шаблона, F04 — удержание смонтированного состояния вкладки при выходе сессии.

## Decisions

1. **Граница одной правки.** Чтение получает идентификатор шаблона, перечень секций и UUID с метаданными, а для выбранного UUID — точный исходный текст, секцию, сохранённый порядок и версию того же снимка. Существующий элемент выбирается по UUID в области шаблона. Для подтверждённо пустого шаблона команда первого сохранения выбирает именованную группу Xray. Источник групп должен совпадать с группами Xray текущей модели B12, с явными именами `log`, `api`, `inbounds`, `outbounds`, `routing`, `rules`, `dns`, `policy`, `stats`, `observatory`, `fakedns`. Если уже заведена пустая группа, добавить в неё. Если её нет, добавить группу, сохранив существующие пустые группы. UUIDv4 генерируется на границе приложения; запись невозможна, если в шаблоне уже появился элемент. Повтор запроса после неопределённого ответа не отправляется автоматически. Удаление, перенос, смена секции и добавление дополнительных элементов остаются отдельными задачами.
2. **Точный текст и диагностика.** Транспорт передаёт исходник строкой, версия — каноническая десятичная строка положительного int64, чтобы браузер не округлял. Точный ID шаблона должен переживать URL-кодирование. API возвращает структурированный код и безопасный JSON-путь либо байтовое смещение; клиент сопоставляет смещение UTF-8 с позициями редактора, в том числе у многобайтового текста. Редактор хранит сырой буфер отдельным текстом и не делает разбор с повторной сериализацией. Если видимый ввод использует нормализованные переводы строк, буфер хранит их исходное представление и переносит правки по исходным границам. Проверки включают смешанные CRLF и LF, вставку CRLF и undo после правки в середине строки. Использовать текущую структурную семантику A08; ошибки сборки не блокируют сохранение черновика.
3. **Сохранение существующего снимка.** Прикладной сценарий читает полный снимок C02, сравнивает ожидаемую версию, строит кандидат изменения одного элемента и проверяет его правилами A08. Проверяется полный набор идентичности. Оставшиеся записи сериализуются без повторного обнаружения деклараций, включая прежние хранимые записи без ранее сохраненного определения. Повторно использовать формат `elementjson`, различив подготовку изменяемого элемента и запись неизменённых проверенных элементов. SQL CAS использует общую операцию C03. Нельзя реализовать частичную запись мимо проверки идентификаторов и общей версии.
4. **Браузерная транзакция.** Транспорт наследует origin, сессию и CSRF F03/F04. На общей границе F06 проверка активности и поколения сессии находится в той же writer-транзакции, что вставка/условная замена. Подготовка JSON и полного кандидата выполняется вне занятой writer-транзакции. SQLite получает только проверенный кандидат и условную версию, а текущая сессия заново проверяется перед записью. Контракт F06 должен дать ссылочный шов транзакционного исполнения, не заставляя вызывать отдельный публичный Replace с другой транзакцией. Сессионный материал не поступает в доменную модель. Успешная запись — только черновик C03, без вызова публикации.
5. **Макет и поведение.** Экран 02 обновляется после принятия оболочки F04 и переходов F05/F06. Нужны существующий элемент с видимым UUID, пустой шаблон с выбором секции и первым сохранением, загрузка, отсутствие, ошибка синтаксиса и конфликт с несохранённым буфером. На узком экране редактор и диагностика остаются читаемыми. Многострочное поле использует TextArea и доступную подпись, выбор — Select, действия — Button. Повторный вход использует состояния 19 и сохраняет именно этот буфер; нет записи в браузерное постоянное хранилище и нет скрытой отправки. Отдельно проверить отмену обрабатываемой асинхронной загрузки при выборе другого элемента, чтобы результаты не перемешивались.

## Состояния Pencil

Экран 23 показывает существующий элемент `SypdZ`, первое сохранение `sJ5pY`, синтаксический отказ `dBDEm`, конфликт с буфером `pFx97`, узкий экран `A8IMd`, загрузку `UdjyK`, отсутствие `GatAE` и ошибку чтения `I2axi`. Использованы существующие Select, TextArea, Button и токены. Навигация взята из совмещённых широкого и узкого состояний F06, включая F20. Проверены рендеры всех затронутых состояний.

## Авторизованное чтение

Активность и поколение браузерной сессии проверяются в том же согласованном SQLite read snapshot, из которого читаются исходный JSON, определения и версия. Просроченный или отозванный доступ возвращает отказ без содержимого. Ответы без кэша. Чтение не продлевает срок сессии.

## Risks / Trade-offs

- Точное представление при преобразовании редактора проверяется на реальном браузере, особенно для CRLF, Unicode и вставки.
- Хранение полного снимка означает конфликт даже при конкурентной правке соседнего элемента. Это ожидаемая защита C03, автоматическое слияние в F07 не вводится.
- Ограниченные HTTP-чтение и размер конверта защищают процесс на Entware; фактический бюджет и безопасная ошибка отказа уточняются в согласованном шве браузерных маршрутов.
