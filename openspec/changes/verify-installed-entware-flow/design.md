## Чистый контур

Центральный сервер и агент устанавливаются из одного синтетического зеркала с точным тегом, суммами и обычной структурой GitHub. Центральный сервер использует отдельный проверенный внешний mTLS-исполнитель через принятые флаги. Worker запускает Xray 26.3.27 в собственном одноразовом изоляторе. Только worker получает доступ к Docker. Все процессы стенда используют синтетические сертификаты и конфигурацию. Обычная установка, init.d и локальный F02 CLI проверяются по руководству G17.

Browser origin отделён от agent origin. Прозрачный TCP relay в тестовом контуре передаёт TLS агентского origin непосредственно Go-серверу. Операторский UI и внешний валидатор остаются доступны. Управление relay закрывает действующие соединения агента и новые подключения, сохраняя HTTPS-идентичность origin при восстановлении. Физические узлы и чужие сети не входят в стенд.

## Операторский сценарий

1. Установить сервер, локально настроить администратора, войти через HTTPS. Создать новый шаблон и минимальные общие секции Xray через поставляемые операции. Добавить проверяемое обязательное значение. В рабочем Xray подготовить известный исходный контрольный каталог, который соответствует требованиям G18.1.
2. Через F09 назначить шаблон, заполнить персональное значение, зафиксировать первую ревизию с действительным внешним Xray worker. Выдать приглашение через F10 и передать его во временный файл 0600. Установить управляемый агент для того же RouterID и origin. Проверить контакт и независимое последующее доказательство E08, а также фактический трафик через текущий Xray. Прямых записей подготовленных объектов в SQLite нет.
3. Оборвать агентский канал. Дождаться штатного признака offline, сохранив прежнюю подтверждённую ревизию и рабочий диск. Явно опубликовать две последовательные общие версии через F18. Проверить preview и наличие недоступного роутера, а после commit — продвижение desired при неподвижном applied. Новая версия должна менять наблюдаемую политику трафика.
4. Восстановить канал. Проверить, что агент согласует последнюю версию без отдельной доставки пропущенной, supervisor фиксирует полный текущий снимок, а сервер получает один действительный итог. Сверить Xray-трафик, сохранённое персональное значение, RouterID, итог desired/applied и контакт. Связать безопасные идентификатор попытки и курсор отчёта с единым результатом в защищённом журнале. Повтор контакта и restart не должны продвигать этот результат снова. Штатный restart сохраняет доказательство и ключ.
5. Постоянные измерения берутся из публичных UI статуса, пользовательских действий и безопасной инспекции результатов. Диагностика не печатает приглашение, пароли, bearer и PEM-ключи.

После принятия зависимостей подставить фактические селекторы UI и команды. Время естественного offline составляет до трёх минут. Убрать временные контейнеры, реле и файлы проверки. Реальный GitHub Release не создаётся.
