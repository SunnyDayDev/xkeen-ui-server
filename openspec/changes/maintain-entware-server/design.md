## Decisions

Брать release asset, версию и SHA-256 по G12. Сохранить неизменный эффективный G15/G18.2 профиль, включая UID/GID, пути TLS, bind и origins, валидатор и секреты. Изменение настроек остаётся отдельной операцией. Привязка новой сборки и проверка разрешений происходят до остановки текущей.

До переключения создать изолированный согласованный снимок работающей базы через поддерживаемый механизм #122 и проверить пробную миграцию новым закреплённым бинарником. Команды SQLite исполняются от service UID, процессы пробного допуска не слушают рабочие интерфейсы. После остановки собственной службы по pidfd повторить проверку актуальной базы и сохранить финальный резерв, включающий последние завершённые записи. Существующий SQLite-файл сохраняет рабочий путь, автоматического восстановления из исторической копии нет. Ошибка проверки перед допуском кандидата оставляет доказанно пригодную прежнюю службу доступной.

Стабильный root-owned launcher читает отдельный долговечный journal под сервисным lock. Фиксировать исходное поколение, scope и профиль, выбранный выпуск, резерв и фазу, отделяющую допуск кандидата к базе от точек подтверждения готовности и переключения. Прежняя служба может быть возобновлена, если кандидат ещё не получил доступ к базе или если согласованные метаданные доверенного выпуска доказывают совместимость формата данных с прежней сборкой и проверка подтверждает фактическую схему/целостность. Требовать одновременное выполнение причин совместимости, одного номера миграции недостаточно. Для старого G15 без такого доказательства и для неясной миграции оставить безопасную остановку с операторским указанием текущего и резервного путей. Прежний бинарник не используется для пробного запуска на рабочей базе. Каждый следующий запуск читает journal и восстанавливает только доказанное поколение, сохраняет поздние записи и не включает изменённый внешний доступ без подтверждённого профиля.

Удаление локально и явно отключает собственный init после проверки exact registration и подтверждённой остановки процесса. При неразрешимом upgrade/unknown child сохранится защищённый барьер. Под защищённым, повторяемым намерением удаляются только проверенные installer artifacts роли. SQLite, WAL/SHM, профиль, TLS, настройки внешнего валидатора и резервы исключены из удаляемого набора. Повторный install сверяет сохранённые UID/GID, настройки и выбранную совместимую сборку.

## Risks / Trade-offs

Пробная и финальная проверки требуют дополнительного места для SQLite. При нарушении совместимости новый процесс может оставить сохранённое рабочее состояние с обновлённым форматом. Автоматический rollback не запускается в этом случае. Оператор может изолированно проверить сохранённую копию по #122.
