## Purpose

Внутренние операции сервиса сохраняют полный редактируемый снимок настроек одного роутера и восстанавливают его после перезапуска.

## ADDED Requirements

### Requirement: Router draft can be stored and read by stable ID

Сервис SHALL сохранять и читать полный черновик по стабильному ID роутера. ID роутера и шаблона SHALL быть непустыми строками корректного UTF-8 и сравниваться точно. Чтение неизвестного корректного ID SHALL сообщать об отсутствии записи. Снимки разных роутеров SHALL быть независимы.

#### Scenario: Draft survives reopening the database

- **WHEN** снимок роутера сохранён, хранилище закрыто и тот же файл открыт снова
- **THEN** чтение по ID возвращает сохранённые ID и отображаемое название роутера, ID выбранного шаблона и полные настройки

#### Scenario: Unknown ID has no saved draft

- **WHEN** внутренний сервис получает запрос чтения по корректному ID без записи
- **THEN** он сообщает об отсутствии снимка

### Requirement: Router draft preserves editable configuration states

Сохранение SHALL сохранять полный персональный порядок с различением отсутствующего и пустого списка. Персональные значения SHALL сохраняться при любом режиме, а исключения и отключения SHALL храниться отдельно. Присутствующее буквальное JSON-значение `null` в собственном или локальном содержимом SHALL сохраняться как значение. Сохранение и чтение SHALL сохранять исходные байты поддержанных JSON-полей.

#### Scenario: Replacement and exclusion retain independent state

- **WHEN** один общий элемент исключён, его переопределение содержит режим полной замены с JSON `null` и ранее записанные персональные значения, а его UUID есть в полном порядке
- **THEN** чтение возвращает все эти данные и ту же позицию UUID

#### Scenario: Section and disabled state are retained

- **WHEN** снимок содержит записи для нескольких секций и отключённые правила и входы
- **THEN** при чтении каждая запись возвращается с исходной секцией, а отключения сохраняются отдельно от исключений и порядка

#### Scenario: Inherited order and explicit empty order round-trip

- **WHEN** два снимка сохранены с отсутствующим и соответственно явным пустым персональным порядком
- **THEN** чтение различает оба состояния

#### Scenario: Local literal content keeps its bytes

- **WHEN** сохранены локальный JSON `null` и локальный JSON с точным числом и форматированием
- **THEN** чтение возвращает соответствующие исходные байты

### Requirement: Stored JSON fields respect the editing mode

Локальный элемент и полная замена SHALL содержать одно синтаксически корректное JSON-значение. Режим переменных SHALL сохраняться без собственного содержимого. Каждое присутствующее персональное значение SHALL быть синтаксически корректным JSON. Проверка типов, обязательных значений и запрета null при сборке относится к действующему контракту переменных.

#### Scenario: Missing content or unexpected inactive payload is invalid

- **WHEN** снимок передаёт локальный элемент или замену без JSON либо режим переменных с собственным JSON
- **THEN** запись отклоняется без изменения прежнего снимка

#### Scenario: Semantic validation waits for assembly

- **WHEN** персональное значение содержит синтаксически корректное JSON null либо тип, недопустимый для текущего определения переменной
- **THEN** снимок сохраняется и чтение возвращает исходное значение

### Requirement: A router draft write is atomic and independent of publication

Полный снимок SHALL заменяться целиком. При ошибке SHALL оставаться доступен предыдущий снимок либо сохраняться отсутствие записи. Сервис SHALL проверять структуру одного снимка и SHALL NOT автоматически удалять ссылки или публиковать черновик. Готовность к сборке SHALL проверяться отдельными операциями. Диагностика SHALL исключать значения переменных и сырое содержимое.

#### Scenario: An unready draft remains editable

- **WHEN** сохранён структурно корректный черновик с незаполненным значением либо ссылкой на исчезнувший элемент выбранного шаблона
- **THEN** он читается с прежними данными и ссылками и не публикуется

#### Scenario: Failed replacement preserves the previous snapshot

- **WHEN** сохранение следующего снимка завершается ошибкой
- **THEN** предыдущее состояние роутера доступно целиком и состояние других роутеров сохраняется

### Requirement: Draft read returns a complete independent result

Успешное чтение SHALL возвращать полный независимый снимок. Повреждение найденной записи SHALL давать безопасную ошибку, отличимую от отсутствия записи, без частичного снимка и сохранённых значений.

#### Scenario: A damaged snapshot is visible

- **WHEN** запись для запрошенного ID существует, но её структура повреждена
- **THEN** чтение возвращает безопасную ошибку без полного или частичного снимка
