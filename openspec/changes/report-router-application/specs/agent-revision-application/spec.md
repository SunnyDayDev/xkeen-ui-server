## ADDED Requirements

### Requirement: A terminal application outcome produces one durable delivery record

Доверенный исполнитель SHALL связывать пригодный для отправки устойчивый исход с той попыткой, которая проверила полные рабочие данные. Получение, подготовка и незавершённое намерение сами по себе SHALL сохранять серверное подтверждение прежним.

#### Scenario: Hot and restart proof reach the same reporting boundary
- **WHEN** диск, соответствующий работающий процесс и свежий трафик доказаны для целого каталога и исход записан устойчиво
- **THEN** область и постоянный ID попытки однозначно выбирают локальный исход для отправки
- **AND** повторное чтение или доставка этого исхода не перезапускает службу и не меняет его статус

#### Scenario: Rollback failure and historical evidence
- **WHEN** восстановление успешно вернуло прежнюю базу или завершилось подтверждённой ошибкой
- **THEN** передаётся безопасный результат неуспешной попытки с номером целевой ревизии
- **AND** историческая применённая ревизия не повышается; неопределённый runtime отражается отдельно

#### Scenario: Durable success is no longer provable
- **WHEN** сохранён успешный исход, но актуальные работающий процесс, диск или трафик больше не доказаны
- **THEN** история и наблюдаемое состояние различаются
- **AND** агент не подтверждает успех впервые и отдельно отражает потерю доказательства
