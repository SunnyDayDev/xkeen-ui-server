## ADDED Requirements

### Requirement: Application delivery confirms one immutable outcome per attempt

При отправке локального устойчивого результата E08 агент SHALL сохранять соответствие между постоянным ID исхода, курсором D06 и неизменным телом отчёта. Координация отчёта SHALL сохранять независимый контакт.

#### Scenario: Commit, enqueue, accepted and acknowledged are recoverable
- **WHEN** процесс прерван между локальным исходом, назначением курсора, серверным принятием и локальным подтверждением
- **THEN** новый владелец продолжает ту же доставку по защищённой записи
- **AND** один исход не получает второй курсор и повтор не изменяет принятую ревизию повторно

#### Scenario: Ambiguous local or network evidence does not advance status
- **WHEN** запись повреждена, сервер возвращает конфликт текущего курсора либо полномочие больше не подтверждено
- **THEN** агент не выделяет новый курсор неподтверждённому исходу и не переобозначает его как успех
- **AND** поздний отчёт не отменяет более свежий результат

#### Scenario: Runtime proof is lost before delivery
- **WHEN** после локального успеха текущий runtime больше не подтверждён
- **THEN** ожидающий успех не отправляется как новое применение
- **AND** ранее доказанный исторический номер сохраняется, а безопасный отдельный диагностический исход сообщает неизвестный runtime

## MODIFIED Requirements

### Requirement: The agent retains and recovers its report boundary

Агент SHALL атомарно сохранять ожидающий отчёт и курсор перед передачей. При потере подтверждения SHALL повторяться те же поля, если разрешено продолжение доставки по правилам проверки доказательства E08. До первого нового отчёта после запуска или восстановления агент SHALL сверять аутентифицированную серверную границу. Новый номер SHALL превосходить обе устойчивые границы. Отправке ожидающей записи SHALL предшествовать подтверждение её устойчивости. Хранилище сервера SHALL сохранять границу при замене полномочия.

#### Scenario: A lost response preserves the pending report across restart
- **WHEN** сервер принял отчёт, но агент не получил подтверждение перед завершением процесса, а повтор соответствует правилам проверки E08
- **THEN** агент повторяет сохранённый отчёт без второго эффекта
- **AND** новое событие не заменяет ещё не подтверждённую запись

#### Scenario: A valid working key recovers the cursor without a synthetic success
- **WHEN** агент утратил локальную запись, а его ключ остался действующим
- **THEN** он считывает последнюю последовательность своего роутера
- **AND** не отправляет утраченный результат E08 на основании одного курсора

#### Scenario: Replacement keeps the router report boundary
- **WHEN** рабочий ключ заменён с сохранением технического ID
- **THEN** новое поколение читает ту же серверную границу, а прежнее полномочие получает отказ

#### Scenario: An older restored local state cannot allocate already acknowledged cursors
- **WHEN** после запуска целая локальная копия отстаёт от аутентифицированной границы сервера
- **THEN** следующий новый отчёт получает номер выше серверной границы
- **AND** существующий ожидающий отчёт повторяется в исходном виде при допустимом продолжении доставки

#### Scenario: Reopening does not bypass a pending durability failure
- **WHEN** ожидающая запись видна после сбоя синхронизации каталога
- **THEN** агент подтверждает устойчивость записи до её отправки
