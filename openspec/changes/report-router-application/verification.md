# Приёмка E08

[Issue #89](https://github.com/SunnyDayDev/xkeen-ui-server/issues/89) подключает устойчивый результат применения к D06. Запускаются синтетический владелец, штатный агент, отдельный supervisor, закреплённый Xray и серверные обработчики с TLS и SQLite.

## Результаты и разрывы

| Проверка | Наблюдавшийся результат |
| --- | --- |
| Первые тесты координатора | Red на отсутствующих контрактах переходов, затем Green. При сохранении подтверждения тест выявил изменение ожидающей записи через общую ссылку до успешного сохранения. Исправление прошло race. |
| Поздняя потеря доказательства | Поведенческий Red при утрате runtime во время чтения курсора. Повтор проверки после ожидания и записи очереди блокирует первую передачу устаревшего успеха. Ранее принятый курсор может только подтвердить точный повтор. |
| Устойчивый локальный исход и ответ | Новый владелец читает готовый или назначенный исход через защищённый журнал. Потеря ответа и ошибка записи локального подтверждения повторяют те же поля. Различены неотправленный успех, уже принятое сообщение и новая диагностика. |
| Прежние версии | Бинарник агента из принятого E07 работает в старом режиме. Новый агент с тем же профилем тоже не отправляет E08. Старый клиент получает безопасный отказ от включённого E08 до рабочих эффектов. Согласованное включение сохраняет прежнюю привязку. Целевой тест защищает старый pending и аутентифицированную границу. |
| Сквозная публикация | Штатный C06 собирает персональные данные и фиксирует каталог SQLite. Тестовый центральный адаптер передаёт закреплённому Xray точные байты, локальный supervisor повторяет проверку с изоляцией E02. Readback на устройстве сравнивается с фактически опубликованными файлами. |
| Принятый отчёт с потерянным ответом | TLS-стенд теряет ответ только после реального принятия SQLite. Повтор после перезапуска агента и supervisor сохраняет точные байты отчёта, последовательность, локальную попытку, PID и привязку. |
| Горячая ревизия и устойчивый конфликт | Следующий C06-снимок горячо меняет трафик. PID остаётся прежним. Временный 409 не продвигает серверный статус и сохраняет запись. Отдельные heartbeat и watch продолжаются. После снятия конфликта принимается тот же отчёт. |
| Неудачный откат и перезапуск | После реального терминального E04 `rollback_failed` и недоступности D06 сохраняется ожидающий отчёт. Перезапуск открывает только доставку. После восстановления D06 сервер сохраняет применённую ревизию 3, наблюдает желаемую 4 и показывает неизвестный runtime. Штатный Xray не запускается. |

Первый сквозной прогон выявил состязание с отчётом и пропуск новой ревизии до обычного таймера. После разведения допуска одной ожидающей мутации и общей блокировки очереди/эффектов сквозной повтор прошёл. В тесте используются настоящие C06, TLS и SQLite. Код тестового адаптера центральной проверки ограничен синтетическим каталогом, отдельным каталогом и локальным закреплённым бинарником. Физические роутеры, установка, миграция серверного диска из устаревшей копии и потеря питания вне этого испытания.

## Воспроизведение

Из корня репозитория в среде Go 1.27.1 и локального [стенда Entware](../../../../lab/README.md):

```sh
go test ./...
go test -race ./...
go vet ./...
XKEEN_LAB_REPORTS=1 sh lab/check-agent-preparation.sh
```

Команда собирает текущего агента и старый агент из принятого E07, запускает одноразовый Linux ARM64 контейнер без внешней сети, включает правила защиты API E07, использует отдельные UID и временные рабочие каталоги. Поддерживаемый путь распространяется на версии профиля, а G11/G12–G15 определяют установку и обновление.
