## Decisions

Разделить авторизацию и SQL-проекцию F11: браузер сохраняет прежнюю проверку сессии, внешний GET проверяет F20 permit в том же read-only transaction. Оба используют общий SQL источник G04/G05 с полным точным ID и сортировкой BINARY. Наружу передаются ровно `routerId`, `name`, `templateId`, `contact`, `desiredRevision`, опциональные `appliedRevision`, `runtime`, `recovery`. Канонические десятичные версии сериализуются строками. `runtime` использует D06/F11 verified/unknown, поле `recovery` содержит только `rollback_failed` при сохранённом последнем отчёте с таким исходом. Контакт offline не продвигает applied. Ревизии, рабочие ключи, настройки и каталоги не входят в выдачу. Параметры запроса и HTTP-методы, кроме GET, отклоняются. No-store сохраняется.

## Risks / Trade-offs

Открытый F20 по явной настройке допускает тот же список метаданных. Детальная диагностика для точного номера и неопределённость исторических свидетельств описываются в #196 отдельно.
