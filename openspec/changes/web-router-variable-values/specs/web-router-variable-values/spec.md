## Purpose

Редактировать значения переменных роутера в авторизованной браузерной области центрального сервера.

## ADDED Requirements

### Requirement: Personal values can be edited without changing inherited content

Браузер SHALL позволять менять значения одного общего элемента в черновике выбранного роутера. Сервер SHALL сверять идентичность элемента, использованный шаблон, действующую сессию и версию черновика. Изменение SHALL сохранять наследуемый JSON и режим.

#### Scenario: A router intentionally uses or inherits a definition
- **WHEN** владелец задаёт значение объявленной переменной либо возвращает наследование дефолта
- **THEN** меняется только соответствующая часть выбранного черновика, а принятая ревизия остаётся прежней

#### Scenario: A newer draft or selected template prevents stale writes
- **WHEN** изменилась версия черновика, использованный шаблон или полномочие браузера
- **THEN** сохранение отклоняется целиком, открытые значения остаются доступны владельцу


#### Scenario: An operator chooses a shared element from the router overview
- **WHEN** владелец открывает видимый роутер и выбирает запись общей секции по UUID
- **THEN** форма показывает определения исходного принятого элемента и персональные значения выбранного роутера
- **AND** введённые ранее значения других элементов и недействующие сохранённые значения остаются в черновике

#### Scenario: An incompatible draft or content mode remains intact
- **WHEN** персональный черновик ожидает другое назначение либо выбранный элемент находится в режиме полной замены
- **THEN** сценарий редактирования переменных не переключает шаблон или режим, и не переписывает персональный черновик

#### Scenario: Visibility or the accepted source changes while the editor is open
- **WHEN** в момент фиксации роутер скрыт из обзора, принят другой снимок либо действующее назначение изменилось
- **THEN** прежняя форма не может сохранить значения на устаревшем основании
- **AND** открытый буфер сохраняется для явного продолжения после перечитывания


#### Scenario: Explicit inheritance differs from a personal JSON literal
- **WHEN** владелец оставляет один дефолт унаследованным и вводит точный JSON в персональное поле другого определения
- **THEN** для первого имени снимается персональное значение, а для второго сохраняются точные байты, включая тип и точность числа
- **AND** допустимый для хранения литерал, несовместимый с B01, показывается как неготовый к сборке отдельно от синтаксической ошибки
