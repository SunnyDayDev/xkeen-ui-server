## Decisions

1. `POST /api/v1/templates` принимает один объект `{"id":"example-template"}` с точным ID. Сохранить порядок и ответ существующего GET коллекции. Запрос использует HTTPS, F19/F20 и маскирование отключённого API. В защищённом режиме требуется действующий bearer F20. Cookie веб-сессии и реквизиты агента не являются внешним допуском.
2. Применить строгий разбор ограниченного JSON тела, точного ключа, без query и без неявного преобразования пробелов/регистра. Передать пустой черновик из той же модели приложения, что и F06. SQLite writer проверяет текущий permit и вставляет только отсутствующий ID в той же транзакции. Конфликт возвращает `409 template_exists`.
3. Успех возвращает 201 с точным `id`, строковой `version: "1"` и `Location` на существующий ресурс F21. Обычный указатель не содержит секрета. При неопределённом ответе клиент может проверить наличие точной записи, не принимая это за доказательство, кто её создал.
4. Потребительская проверка проходит через настоящий TLS listener и SQLite: выключено, открыто, защищено, отозванный токен, конкурентный Create одного ID, громоздкое или ошибочное тело, точное чтение F21 и пустой черновик. Для отозванного permit проверяется отказ именно внутри writer, даже если исходный допуск прошёл.

## Risks / Trade-offs

Открытый F20 разрешает эти действия любому клиенту с доступом по HTTPS в соответствии с настройкой владельца. Точный ID сохраняет уже действующую семантику C02.
