# Проверка E07

На чистом одноразовом ARM64-контейнере LinuxKit 7.0.14 с Entware, Xray 26.3.27 и временными синтетическими рабочими файлами выполнен `XKEEN_LAB_HOT=1 sh lab/check-agent-preparation.sh`. Тест запускает настоящие server/SQLite, agent, локальный supervisor, worker и Xray. Проверены следующие сценарии.

| Событие | Наблюдаемый результат |
| --- | --- |
| Первое подключение без защищённой истории | E03 сменил PID и закрепил происхождение запуска |
| Попытка непривилегированного чтения RoutingService и соединения через SOCKS Xray | В обоих случаях увеличился счётчик нужного REJECT, запросы завершились отказом |
| Совместимое второе изменение | Горячая замена сохранила PID/start tick, все файлы совпали с целевыми байтами; две постоянные пробы и третья изменяемая прошли |
| Переоткрытие supervisor | Сохранились PID и ID попытки; защищённая проекция и трафик прошли повторную проверку |
| Холодный запуск из устойчивого каталога | Новый процесс показал ожидаемый результат трёх проб с тем же ID попытки |
| Журнал старого boot/netns и недоступная третья проба | Смоделирована прежняя инкарнация в закрытом журнале. Лишний процесс завершён без открытого SOCKS listener; после восстановления пробы новый процесс подтвердил тот же профиль и попытку |
| Потеря поведенческого подтверждения после реальной замены | E04 полностью восстановила прежнее содержимое и трафик с новым PID; целевая ревизия не зафиксирована |
| SIGKILL supervisor после реальной смены, до ответа | На диске остались прежние файлы, в runtime действовало новое правило. Принятый E05 startup gate восстановил прежнее состояние по hot_dispatch и исходному ID попытки |
| Повторное открытие трёх фаз журнала | Отдельный тест реального дискового журнала проверил hot_dispatch, hot_verified, hot_files, восстановление через E04 и отказ для несовместимой ожидаемой проекции |

Red получен для отсутствующих горячих фаз, смешанного boot/profile fingerprint, приёма некорректной проекции журнала и ещё не интегрированного E05 startup gate. Прочие ветви проверены как регрессионные сценарии. Ограничения стенда и требования к локальной сетевой политике описаны в [руководстве агента](../../../../docs/router-agent.md). Реальные роутеры не подключались.

На объединённой базе E05 дополнительно прошли native `go test ./... -count=1`, `go test -race ./internal/agent/restart -count=1` и прежний отдельный E03/E04/E05 ARM64-профиль (`XKEEN_LAB_APPLICATION=1`). Ревью A01 выявило и повторно проверило устранение ошибки привязки к старой сетевой инкарнации при холодном запуске.
