# Проверка D06

- Red для SQLite выявил отсутствие слоя отчётов. Green подтвердил раздельный контакт, точный срок 179/180 секунд после повторного открытия, отклонение неизвестной ревизии другой области и отзыв поколения. Целевой SQLite тест прошёл 20 раз с race.
- Red HTTPS показал отсутствие маршрута. Green подтвердил пустой контакт, защищённое чтение курсора, точный конфликт и строгие числа.
- Red очереди показал отсутствие локального сохранения и отправителя. Green подтвердил устойчивый pending, точный повтор и выделение выше серверной границы. Управляемые часы показали два интервала ровно по 60 секунд при заблокированной доставке отчёта.
- Независимое ревью выявило три воспроизводимых дефекта. До исправления запоздалый отчёт снимал неопределённость, видимый результат неудачной синхронизации очистки терял pending, а явный null принимался. После адресных исправлений регрессии и независимый повтор с race прошли.
- Процессный тест `TestProcessContactQueueAndCursor` использует настоящий сервер TLS и SQLite, перезапуск сервера, переоткрытие приватной локальной очереди, повтор без нового эффекта, heartbeat и отзыв. Тест прошёл на хосте и в Entware aarch64 на статическом Go-бинарнике в Docker с `--network none`. Использовались синтетические данные и сертификат. Загрузка и фактическое применение Xray не служили источником статусов.
- Прошли `go test ./...`, `go test -race ./...`, `go vet ./...`, строгий OpenSpec и Linux ARM64/AMD64 без cgo.

Для Entware собрать Linux ARM64 `./cmd/xkeen-ui-server` и бинарник его тестов. Передать их как read-only файлы контейнеру `xkeen-router-lab:dev` с `XKEEN_TEST_SERVER_BINARY` и запустить `-test.v -test.run '^TestProcessContactQueueAndCursor$'`.
