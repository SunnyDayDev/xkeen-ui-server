## Окружение и исходная проверка

- Найден ранее установленный SDK: `go version go1.27.1 darwin/arm64`; используется `GOTOOLCHAIN=local` и временные кеши вне репозитория.
- Исходный `go test ./... -count=1` в песочнице не прошёл из-за `bind: operation not permitted` в существующих процессных/lifecycle тестах. Это ограничение loopback, не Red.
- Повтор исходного набора с разрешённым loopback: оба существующих пакета прошли.

## Фактические циклы

| Задача / тест | До логики | После логики и форматирования |
| --- | --- | --- |
| 1.2 `TestConstantTemplate` | Red: заглушка вернула nil JSON, проверка получила EOF | Green: новый JSON семантически сохраняет константу; nil и пустая map |

Целевые запуски: `go test ./internal/configuration -run <TestName> -count=1`; повторные проверки пакета: `go test ./internal/configuration -count=1`. Ошибки сборки не засчитываются как Red.

- 2.1 `TestRootTypes`: все пять случаев Red (вернулась строка-ссылка), затем Green после поиска корневой ссылки и декодирования значения; повтор всего пакета после gofmt прошёл.

- 2.2: `TestObjectTypes` Red (ссылки в полях сохранились) → Green с обходом объектов; затем `TestNestedValues` Red (ссылки внутри массива сохранились) → Green с обходом массивов. После каждого шага gofmt и весь пакет прошли.

- 2.3 `TestExactNames`: изоляция двух наборов сразу Green; варианты другого регистра и имени `server` дали Red (ссылка оставалась без ошибки), затем Green с `unknown_variable`.
- 2.4 `TestExactNumbers`: исходный Green, поскольку UseNumber введён при разборе константы; Red не заявляется. Точное сравнение через big.Rat различает округлённые целое/дробь и считает 1e3 равным 1000. Большое целое, длинная дробь и 1e400 сохранены в константах и подстановке. Повтор всего пакета прошёл.

- 3.1 `TestInvalidJSON`: 15 случаев Red (нет позиции либо принят лишний/неиспользуемый JSON) → Green после общего разбора всех входов с безопасной позицией и проверкой конца ввода. Весь пакет после форматирования прошёл.

- 3.2 `TestDuplicateKeys`: шесть Red (дубликат молча заменял первое значение) → Green после обхода токенов с отдельным набором ключей объекта. Unicode-эквивалентные ключи, вложенность, массив и экранированный путь проверены; `TestSeparateObjectKeys` сразу Green. Проверка грамматики через RawMessage предшествует обходу токенов и сохраняет исходные смещения. Весь пакет после gofmt прошёл.

- 3.3 `TestUnknownLocation`: три Red (нет Path) → Green с JSON Pointer для вложенного поля, корня и экранированных ключей/индекса. После gofmt весь пакет прошёл.

- 3.4 `TestInputsAndDiagnostics`: все шесть сценариев сразу Green; входы сохраняются при успехе/ошибке, выход имеет отдельные байты, выдаваемые диагностики не содержат демонстрационного значения. Red не заявляется: необходимые свойства уже получены на предыдущих шагах.

- Регрессионная проверка при ревью: `TestInvalidJSON/invalid_utf8` дала три Red — стандартный декодер заменял недопустимый байт символом замены или принимал неиспользуемое значение. Добавлена проверка UTF-8 с безопасной позицией; целевой случай и весь пакет после gofmt Green. Это уточнение проверки неправильного JSON, не реализация синтаксиса B02.

- Ревью 4.1: пакет импортирует только bytes, encoding/json, errors, strconv, strings и unicode/utf8; I/O, глобальных изменяемых данных и подключения к HTTP нет. Дополнительный тест Unicode-имён, отсутствия нормализации и допустимых JSON-пробелов сразу Green. Покрытие пакета после проверки UTF-8 — 100% statements; это не заявление о полноте B01/B02.

## Оставшиеся границы и статусы

`SubstituteValues` принимает подготовленные значения и не является полной `ResolveElement`. B01/B02 остаются отдельной работой: выбор дефолтов, обязательность, определения, соответствие объявленному типу, полный запрет null и полный синтаксис ссылок/экранирования. Успех A06 не разрешает публиковать конфигурацию без этих проверок.

На этапе локальной реализации issue #7 оставалась открытой до публикации кода и артефактов. Реализация A06 проверена полностью в согласованной области; итоговые сведения о публикации, CI и закрытии записываются в issue #7 после слияния PR. Change **архивирован 2026-09-08** в `2026-09-08-add-whole-value-substitution`; основная спецификация синхронизирована и проверена до перемещения каталога.
