# Методика F01

## Context

Веб-интерфейс проектируется поверх готовых прикладных операций. Макет хранится в Pencil. Первый сервер развёртывается в Docker или Entware ARM64 и собирается на Go без cgo.

## Decisions

- Пробу провести с одним набором HTML-действий. Во всех трёх вариантах ввод остаётся в текстовом поле при перестановке, запрос статуса обновляет область сообщения, а действия доступны с клавиатуры.
- Собирать браузерные файлы в отдельном временном каталоге с закреплёнными npm-зависимостями. Считать по файлам полный объём и сумму gzip. Собирать одинаковый Go-хост со статическими файлами каждого варианта и минимальным контрольным HTML.
- Запускать целевой ARM64 ELF в чистом Alpine и в стенде Entware. Контейнеры не публикуют порты, работают без внешней сети и получают только бинарник через read-only монтирование.
- Сверить `Tokens`, общие компоненты и сценарии редактора, порядка и проверки изменений через чтение Pencil. Синтетическая проба проверяет технические свойства и не заменяет проверку будущего UI по макету.

## Risks / Trade-offs

- Размер пробы характеризует минимальный набор. Редактор JSON, просмотр различий, шрифты, иконки и загрузка больших конфигураций потребуют отдельных измерений.
- Docker использует собственное ядро. Размер и совместимость физического устройства требуют самостоятельной проверки.
- Встраивание связывает версии серверного бинарника и браузерных файлов. Шаги сборки Node/npm относятся к CI и машине разработчика. Поставляемый процесс — Go-бинарник.

## Open Questions

Согласование стека владельцем, требования к браузерам, окончательный редактор и обработка входа, логаута и CSRF. Эти решения относятся к будущим задачам интерфейса.
