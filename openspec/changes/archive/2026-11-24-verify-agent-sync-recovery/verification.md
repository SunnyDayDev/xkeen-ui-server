# Приёмка восстановления синхронизации D08

[Issue #75](https://github.com/SunnyDayDev/xkeen-ui-server/issues/75) проверяет существующий транспорт D01 и реализацию D05–D07. Производственный код не менялся. Тесты запускают производственный процесс агента и серверные HTTP-обработчики через TLS с временной SQLite. Точки отказа находятся на границе тестового HTTPS-стенда. Для теста используется отдельный синтетический роутер и три каталога с различимыми байтами.

| Условие | Проверка |
| --- | --- |
| Watch отвечает 503, чтение доступно | После двух публикаций штатная сверка через 60 секунд получает точные файлы ревизии 3. |
| Разрыв соединения с последующим перезапуском | Стенд закрывает TLS-соединение и останавливает дочерний процесс, затем фиксирует ревизии 2 и 3. Новый процесс без приглашения использует ту же локальную привязку и получает полный снимок 3. |
| Возраст контакта 179 и 180 секунд | Управляемые часы сервера подтверждают соответственно связь и отсутствие связи. Новый контакт переводит статус обратно в «на связи». |
| Прерванный ответ после восстановления, затем устаревшие подсказки | Короткое тело с заявленной большей длиной оставляет предыдущую полную копию. После загрузки ревизии 3 две подсказки запускают чтение старого корректного ответа, проверенная копия остаётся побайтно прежней. |
| Отзыв ключа | После возобновления реального watch агент получает подтверждённый отказ, останавливается и сохраняет проверенную копию. |
| Статус применения | Желаемая ревизия 3 и новый контакт не меняют применённую ревизию и текущую попытку. |

Для границы отсутствия связи используются часы репозитория контактов. Минутная сверка проходит по настоящему таймеру процесса. Первый прогон обнаружил недостаточное окно ожидания выхода после отзыва на фоне увеличенной задержки между запросами watch. В тесте теперь отдельно ожидается следующий реальный запрос watch и затем завершение процесса. Подтверждённых дефектов синхронизации в этом прогоне не обнаружено.

## Результат

Оба сценария прошли в Entware ARM64. Сверка при недоступном watch заняла 60,05 секунды, сценарий разрыва и перезапуска — 15,47 секунды. Независимое ревью повторило оба сценария с детектором гонок и отдельно повторило уточнённую проверку прерванного ответа с корректным ETag и последующего отзыва.

## Воспроизведение

Быстрый случай входит в обычный `go test ./...`. Для проверки реальной минуты задайте `XKEEN_TEST_RECOVERY_MINUTE=1`. При доступной локальной сборке [стенда Entware](../../../../lab/README.md) выполните из корня репозитория:

```sh
build=$(mktemp -d)
trap 'rm -rf "$build"' EXIT
CGO_ENABLED=0 GOOS=linux GOARCH=arm64 go build -trimpath -o "$build/agent" ./cmd/xkeen-agent &&
CGO_ENABLED=0 GOOS=linux GOARCH=arm64 go build -trimpath -o "$build/server" ./cmd/xkeen-ui-server &&
CGO_ENABLED=0 GOOS=linux GOARCH=arm64 go test -c -o "$build/recovery.test" ./cmd/xkeen-ui-server &&
docker run --rm --platform linux/arm64 --network none --read-only --user 1000:1000 \
 --tmpfs /tmp:rw,noexec,nosuid,nodev,mode=1777 --cap-drop ALL --security-opt no-new-privileges \
 --mount "type=bind,src=$build,dst=/probe,readonly" \
 -e XKEEN_TEST_SERVER_BINARY=/probe/server -e XKEEN_TEST_AGENT_BINARY=/probe/agent \
 -e XKEEN_TEST_RECOVERY_MINUTE=1 \
 --entrypoint /probe/recovery.test xkeen-router-lab:dev -test.run '^TestProcessRouterAgentRecovery' -test.v -test.timeout 2m
```

D08 проверяет локальную копию желаемой ревизии и серверный учёт связи. Проверку каталога на роутере, рабочие файлы Xray, рестарт, горячую замену, откат и подтверждение применения покрывают отдельные задачи E01–E08. Физические устройства в испытании не использовались.
