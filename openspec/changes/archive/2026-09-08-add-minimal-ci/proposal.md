## Why

После завершения HTTP-каркаса A03 существующие проверки запускаются вручную: push и pull request ещё не дают автоматического результата тестов и сборки. [A04, issue #5](https://github.com/SunnyDayDev/xkeen-ui-server/issues/5) добавляет минимальный CI перед дальнейшим развитием ядра; зависимость [A03, issue #4](https://github.com/SunnyDayDev/xkeen-ui-server/issues/4) закрыта.

## What Changes

- Добавить один GitHub Actions workflow на push веток и pull request с одним Linux AMD64 job и правами `contents: read`.
- Использовать toolchain из `go.mod`, проверять форматирование Go, синтаксис скрипта запуска, существующие тесты, `go vet` и гонки.
- Собирать сервер без cgo для Linux AMD64 и ARM64; бинарники остаются временными результатами job.
- Сделать провал проверки видимым в статусе job и журнале именованного шага; подтвердить успешный и намеренно неуспешный запуск на GitHub.
- Включить защиту `main`/`master`: изменения через PR, обязательный CI для актуальной базы, запрет force push и удаления, без bypass. Активировать после регистрации проверки GitHub Actions и проверить блокировку PR при её провале.
- Документировать состав CI, команды для локального повторения и фактические результаты проверки.
- Закрепить правило: продуктовые specs описывают поведение сервиса; процессы разработки и архитектурные принципы оформляются в правилах проекта и отдельной документации.

## Capabilities

### New Capabilities

Нет. CI относится к процессу разработки и не добавляет продуктовых возможностей сервиса.

### Modified Capabilities

Нет. Существующие specs не изменяются. Для этого change задано `skip_specs: true`: состав CI и критерии проверки описаны в design и tasks; процессные требования не переносятся в основные спецификации.

## Impact

- Будущие изменения: `.github/workflows/ci.yml`, отдельный `docs/ci.md`, ссылки и статус в `README.md`, `docs/server-skeleton.md` и `docs/roadmap.md`, отчёт `verification.md` этого change. Правило разделения продуктовых specs и процессов закрепляется в `AGENTS.md` и применимых rules `openspec/config.yaml`.
- Внешние зависимости среды CI: GitHub-hosted Linux runner, официальные actions checkout/setup-go и Go toolchain. Go-модуль и runtime сервера не получают новых зависимостей.
- Настройки GitHub: ruleset для `refs/heads/main` и `refs/heads/master`. Защита включена в объём по дополнительному запросу пользователя; её параметры и проверка будут описаны в `docs/ci.md` и отчёте change.
- Код HTTP-сервера, его контракты, UI и макеты не изменяются. Новый набор интеграционных тестов, автоматизация Entware/XKeen/Xray-стенда и публикация релизов, образов или бинарников находятся вне задачи.
- Это предложение планирует реализацию; сам workflow и подтверждённый запуск на GitHub ещё предстоят. Issue #5 остаётся открытой до выполнения критериев и проверок.
