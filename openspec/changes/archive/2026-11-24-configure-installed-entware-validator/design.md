## Решение

Установщик принимает те же конкретные параметры F09/F10. Сценарий Entware использует внешнего исполнителя HTTPS mTLS. Неполный набор параметров, несовместимый origin и ошибочные PEM блокируются. Входные файлы проверяются через открытые дескрипторы. CA и сертификат копируются в защищённый root-owned профиль, клиентский приватный ключ получает режим 0640 root:server. Профиль хранит идентификаторы точных байтов и пути доверенных локальных копий. Секреты не помещаются в argv, env, ответы или отчёт.

Проверка точного профиля перед каждым стартом защищает от подмены файлов. Раздельные browser origin, origin исполнителя и внешний agent origin передаются только принятыми аргументами серверного CLI. Отсутствие параметров остаётся стандартным поведением G15. Готовность HTTPS подтверждает сервер, состояние валидатора определяется F09 при публикации. Владельцу доступен локально настроенный F10, который может выдать приглашение другому HTTPS-адресу.

Независимый worker запускается согласно C06.2, держит Docker доступ у себя. Проверить реальные Entware и Docker G10, успешный и отказавший mTLS запрос, запрет публикации без исполнителя и точное наблюдаемое значение F10.
