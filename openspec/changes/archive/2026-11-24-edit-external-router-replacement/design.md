## Context

F13 сохраняет свой исходник через B05. Возврат удаляет собственный JSON и восстанавливает сохранённые значения. Полный сброс удаляет переопределение целиком. #179 вводит отдельную защищённую операцию записи персонального черновика и проверку полного ETag.

## Decisions

- `GET` и `PATCH /api/v1/routers/replacement?routerId=<exact>&elementId=<uuid>`. GET возвращает точные координаты, версионное основание, текущий режим, наличие переопределения и свой JSON при его наличии. Ответ не раскрывает неактивные значения. Сильный ETag связывает эту выдачу со всеми тремя поколениями и точным ресурсом.
- `{"action":"replace","source":"null"}` сохраняет полный буквальный JSON, включая текст ссылок переменных. `{"action":"variables","confirm":true}` возвращает режим переменных без удаления их сохранённых значений. `{"action":"reset","confirm":true}` удаляет оба вида персональных данных элемента. Последние два не принимают source. Замена требует присутствия строки source и отклоняет поле confirm. Отсутствие явного подтверждения, JSON null вместо строки и лишние поля отклоняются.
- F13/B05 остаётся общим переходом. F20 повторно проверяется вместе с видимостью и C04 CAS в одной транзакции. Не меняются UUID, общий шаблон, исключения, локальные правила и полный порядок. Потеря ответа разрешается свежим GET. Выпуск желаемой ревизии отдельный.
- Переиспользовать точные условные ответы #179. Ошибки синтаксиса дают безопасный код и положение, без исходного JSON. Возврат в неподходящем режиме даёт конфликт.

## Risks / Trade-offs

Подтверждение связано точным ETag с теми данными, которые клиент прочёл. Новый запрос после конфликта должен снова предъявить подтверждение.
