# C01 — проверка реализации

Дата проверки — 2026-11-24. Связанные критерии — [issue #36](https://github.com/SunnyDayDev/xkeen-ui-server/issues/36).

## Критерии приёмки

| Критерий | Фактический результат |
| --- | --- |
| Создание до открытия HTTP | Процесс стартует с новой SQLite; при первом положительном ответе `/healthz` база существует, а после повторного старта в журнале ровно одна v1. На одновременно занятом порту и неподдерживаемой базе процесс сообщает ошибку базы. |
| Перезапуск сохраняет данные и версию | Тест реального бинарника записывает строку `demo.example` в отдельную тестовую таблицу, завершает сервер через SIGTERM с кодом 0 и повторяет запуск с тем же файлом. После второго запуска значение и версия читаются. |
| Видимая ошибка и атомарность | Ошибка открытия каталога и неподдерживаемая версия дают код 1 и диагностику в stderr без события `listening`. При неудачной тестовой миграции v2 откатываются создание таблицы, изменение ранее записанного значения и регистрация версии. Режим только для чтения и ошибка записи проверены отдельно. |
| Целевая проверка и документы | Локальные тесты и изолированная ARM64-проба прошли. Команды запуска и эксплуатации описаны в [документации сервера](../../../../docs/server-skeleton.md#хранилище-c01). |

## Red и Green

- Адаптер открытия — тесты нового файла, точного пути с пробелами и специальными символами, неверного файла и повторного чтения были написаны первыми. Red зафиксирован на отсутствовавшем `Open`; после добавления адаптера тесты прошли. Дополнительный тест буквального пути через симлинк и `..` сначала получил SQLite `unable to open database file`; после устранения различий разрешения пути прошёл.
- История и откат — ранний вариант принимал базы без истории и с неверной историей. Новый сценарий отката не компилировался до появления тестируемого применения набора миграций. После проверки версии и транзакционного применения все сценарии прошли. Сто последовательных повторов теста одновременного первого открытия прошли.
- Аргументы и процесс — до правки справка не включала `--db-path`. До подключения адаптера сервер начинал HTTP без создания файла, а при занятом порту сообщал об ошибке bind, игнорируя непригодную базу. После подключения SQLite тесты аргументов, остановки, повторного запуска и ошибок прошли. Первый запуск тестов процесса в песочнице не мог открыть loopback; Red подтверждён отдельно с доступным loopback.
- Независимое ревью выявило открытие существующего файла только для чтения и приём триггера на журнале. Оба сценария воспроизведены до исправления. После проверки фактического режима соединения и отказа от журнала с триггером тесты прошли.

## Команды и результаты

- Go 1.27.1 на Darwin ARM64. `go test ./... -count=1`, `go vet ./...`, `CGO_ENABLED=1 go test -race ./... -count=1`, `go mod verify`, проверка `gofmt`, `sh -n lab/check-server-storage.sh`, `git diff --check` и строгая проверка OpenSpec прошли.
- `CGO_ENABLED=0 GOOS=linux GOARCH=arm64 go build -trimpath ./cmd/xkeen-ui-server` и аналогичная сборка AMD64 прошли. Проверка ELF подтвердила ожидаемые архитектуры, отсутствие `PT_INTERP` и `PT_DYNAMIC`. Размер ARM64 — 15 307 199 байт, AMD64 — 16 098 193 байт.
- `sh lab/check-server-storage.sh` прошла в изолированном `xkeen-router-lab:dev` под непривилегированным пользователем. Среда — Linux 7.0.14-linuxkit aarch64, Entware busybox 1.38.0-5 и libc 2.27-12, встроенная SQLite 3.53.4 через `modernc.org/sqlite` v1.58.0. SQLite содержит исправление WAL-reset. [Документация SQLite](https://sqlite.org/wal.html#the_wal_reset_bug).
- Единичное измерение на временной ФС контейнера. Первая доступность HTTP с новой базой за 24,6 мс при пике 15 476 КиБ резидентной памяти. Повторный запуск с одной тестовой строкой за 23,3 мс при пике 14 520 КиБ. Commit одной строки занял 67 мкс, откат тестовой миграции v2 — 134 мкс. Старт измерен до опроса `/healthz`, память — по `VmHWM`. Результат ограничен этой пробой. Рабочий накопитель и ядро физического роутера требуют отдельной проверки.

Первый Linux CI достиг таймаута `TestLauncher` при сборке SQLite с холодным кэшем. Предварительная сборка тестового бинарника теперь использует параметры launcher (`-trimpath`, `CGO_ENABLED=0`), поэтому проверка HTTP больше не ждёт отдельную компиляцию SQLite.
