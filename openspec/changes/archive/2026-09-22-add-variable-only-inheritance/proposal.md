## Why

B02 собирает переменные одного элемента, но не связывает персональные значения с исходным шаблоном и UUID. B04 добавляет эту границу, чтобы изменения общего JSON и дефолтов наследовались без потери персональных значений, а настройки чужого источника не применялись и не игнорировались молча.

Связь с трекером: B04 из [обзорной issue #1](https://github.com/SunnyDayDev/xkeen-ui-server/issues/1) и [roadmap](../../../../docs/roadmap.md). Принятый контракт — [B03, issue #18](https://github.com/SunnyDayDev/xkeen-ui-server/issues/18); зависимости реализованы в [B01 #14](https://github.com/SunnyDayDev/xkeen-ui-server/issues/14), [B02 #16](https://github.com/SunnyDayDev/xkeen-ui-server/issues/16) и [A08 #9](https://github.com/SunnyDayDev/xkeen-ui-server/issues/9). Реализация отслеживается в [issue B04 #19](https://github.com/SunnyDayDev/xkeen-ui-server/issues/19). Обзорная #1 не закрывается по результату B04.

## What Changes

- Добавить чистую сборку одного существующего общего элемента для роутера: актуальный элемент, контекст владельцев и необязательные персональные значения с явной ссылкой «шаблон + UUID».
- Проверять источник до сборки: другой шаблон даёт `source_mismatch`, другой UUID — существующую `element_id_mismatch`; ошибочная ссылка не превращается в отсутствие настройки, даже при пустом наборе значений.
- Использовать B02 для текущего JSON, определений, дефолтов и персональных значений. Не материализовать дефолты в персональном состоянии, не исправлять и не удалять значения при ошибках.
- Возвращать независимое содержимое с идентичностью источника либо безопасные ошибки с владельцем/позицией, без частичного результата.
- Проверить наследование при изменении шаблона, дефолта и определений через TDD/BDD; после реализации обновить сведения о доступных возможностях.

## Capabilities

### New Capabilities

Нет.

### Modified Capabilities

- `configuration-content-inheritance`: уточнить ошибку несовпадения источника и контракт отдельной сборки наследуемого элемента в режиме переменных. Правила B03 о полной замене, переключении, сбросе, локальных элементах и исключениях сохраняются для последующих задач.

## Impact

- Ядро `internal/configuration`: узкие типы источника/персональных значений, операция наследования, диагностика и тесты. Существующие `AssembleElement`, `PrepareValues`, модель `Element` и формат `elementjson` сохраняют свои контракты.
- Зависимости: стандартная библиотека и существующее ядро; без новых библиотек и I/O.
- Документация после реализации: `README.md`, `AGENTS.md`, `docs/architecture.md`, `docs/configuration-model.md`, `docs/prototype.md`, `docs/roadmap.md` — точный статус B04, без обещания полной сборки.
- Вне объёма: B05/B06, наборы переопределений и `duplicate_override`, порядок, проекция `_xkeenUiId`, каталог Xray, БД, HTTP/API, UI, агент, публикация, удаление источника и смена профиля. Успешная сборка элемента не подтверждает готовность конфигурации устройства.
