# Проверки #178

Штатный серверный процесс с HTTPS и временной SQLite до подключения маршрута возвращал 404 вместо 200. После подключения потребитель прошёл чтение и A → B → A, отклонение изменённого входа и повторной квитанции, отказ каталога и чтение назначения после потерянного ответа. Синтетический Unix-исполнитель отвечает по настоящему протоколу валидатора и позволяет изменить F20 непосредственно после проверки каталога. Отзыв сначала давал 401 вместо ожидаемого 404, затем тест прошёл с неизменным назначением. Сохранённое значение по умолчанию проверяется синтетическим маркером.

Отдельный регрессионный тест потребителя воспроизвёл приём некорректного preview без values и с явным receipt. Набор требует JSON-массив values для обоих действий и разрешает непустой receipt только при confirm. Проверены отказ запроса без bearer в защищённом режиме, отказ старой квитанции с новым рабочим токеном F20 и отсутствие успеха при позднем скрытии роутера или истечении квитанции.

Сводка порядка вычисляется G02 по той же паре снимков, что и подготовленная ревизия. Сценарий потребителя требовал order и сначала получил ответ без этого поля. После добавления сводки тест прошёл. Равные файлы, сохранённый локальный порядок, старые координаты и необходимость значений дополнительно покрывают сценарии G02. Настоящий Xray проверялся независимо в G02. Синтетический исполнитель в тесте внешнего обработчика служит для проверки конкурентных изменений.
