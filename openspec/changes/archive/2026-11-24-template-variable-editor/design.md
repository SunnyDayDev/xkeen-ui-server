## Context

A08 сохраняет точные имена, порядок и структуру записанных определений. Модель `VariableDefinition` содержит только Name, Type и Default. Nil отличает отсутствующее значение, а пустая после Unicode White_Space строка имеет ту же семантику незаполненности при сборке. C03 и F07 используют версию полного шаблона.

## Decisions

1. **Область формы.** F08 показывает упорядоченные определения выбранного элемента и изменяет их Type и Default. Новые целые ссылки в сыром JSON объявляет F07 через A08. Поля идентичности и имена существующих определений защищены от подмены текущей операцией. Редактирование персональных значений или массовое изменение других элементов остаётся отдельной задачей. Хранить и показывать существующее определение даже после исчезновения ссылки. Признак наличия ссылки использует общий обход A08 без вывода о происхождении записи.
2. **Обязательность и ошибки.** Управление необязательностью происходит за счёт заполненного допустимого дефолта. Без него требуется персональное значение, даже для неиспользуемого определения; отдельного boolean нет. Пустое текстовое поле допускает явное отсутствие дефолта, а JSON `""` остаётся сохранённой пустой строкой. Недопустимый заполненный дефолт получает отдельную ошибку вместо обещания наследования. Типы string, number, boolean, object, array берутся из B01. Допустимые `false`, `0`, `{}`, `[]` и Unicode-пробелы показываются точно.
3. **Встроенная проверка.** При чтении и после сохранения прикладной слой получает чистую диагностику названий, повторов, типов, структуры дефолта, несовместимости и `null`. В домене выделить общие части существующего B01 без изменения порядка проверок для текущих вызовов. Не звать `PrepareValues` с пустыми персональными значениями ради UI: ранний `missing_value` не является ошибкой определения и скрывает другие дефекты. Синтаксически невалидный дефолт всегда блокирует запись через A08, структурно корректный дефолт с ошибкой сборки может быть сохранён и остаётся видимым. Диагностика ограничена кодом и позицией, типом или безопасным путём и не содержит исходных значений.
4. **Транспорт и сохранение.** Использовать scoped read и общий защищённый сценарий записи F07. Контракт принимает версию полного шаблона, UUID и изменения строк в сохранённом порядке. Проверяются область, порядок и имена исходных определений, включая старые дубликаты с позициями; это исключает перенос редакторских данных в другой элемент. Дефолт передаётся как JSON-текст без разбора клиентом в IEEE-754, отсутствие отдельно от текста `null`. Формат A08 может нормализовать запись дефолта с тем же точным JSON-значением и категорией отсутствия; исходный JSON самого элемента сохраняется байт-в-байт. Прикладная команда меняет только определения выбранного элемента, применяет A08 для него (при явном сохранении может дописаться отсутствовавшее определение из прежнего JSON) и сохраняет целый снимок через C03 без повторной подготовки соседей. Шов F06/F07 проверяет действующую сессию в writer-транзакции. Конфликт не объединяется автоматически.
5. **Макет и поведение.** Дополнить экран 02 через FormField, Select, TextArea и Button. Нужны состояния нового автоопределения, смены типа и пустого дефолта, заполненного дефолта, неиспользуемого определения, синтаксического отказа и отдельной диагностики сборки. На узком экране подпись обязательности и ошибка остаются рядом с редактируемым дефолтом. F04 удерживает локальные поля после истечения, после входа инициируется только явное новое сохранение.

## Состояния Pencil

Экран 23б использует актуальную навигацию F07. Переход «Переменные» добавлен к существующему элементу в широком и узком состоянии F07. Обратный переход ведёт к открытому исходному тексту. Варианты: ссылка и пустой начальный дефолт `vcU4k`, смена типа `ojnGl`, заполненный дефолт `mFFuA`, неиспользуемое определение `rqnlM`, синтаксический отказ `d6k9e`, ошибка типа черновика `AdPNq`, узкий экран `J0P2Ma` и отсутствие определений `mi6NG`. Рендерены все восемь состояний и затронутый узкий экран F07.

## Авторизованное чтение

Активность и поколение браузерной сессии проверяются в том же согласованном SQLite read snapshot, из которого читаются исходный JSON, определения и версия. Просроченный или отозванный доступ возвращает отказ без содержимого. Ответы без кэша. Чтение не продлевает срок сессии.

## Risks / Trade-offs

- Строгое применение готовности B01 на сохранении уничтожило бы возможность исправлять черновик постепенно. Проверка структуры и сообщение о готовности остаются разными результатами.
- C03 специально конфликтует при конкурентном изменении сырого JSON и определения в двух вкладках. Это сохраняет определения от перезаписи устаревшей операцией и позволяет F08 пользоваться одной версией F07.
