## ADDED Requirements

### Requirement: A failed live attempt restores its own durable previous generation

После отказа незавершённой попытки с устойчивым намерением агент SHALL восстанавливать только точную прежнюю генерацию, указанную в защищённом журнале, под прежним рабочим барьером. Предыдущий каталог, метаданные и профиль SHALL использоваться целиком. Смена желаемой ревизии и доступность сети SHALL NOT определять право на откат.

#### Scenario: An optional file disappeared before the restart failed
- **WHEN** отказ целевой попытки оставил допустимую смесь файлов без прежнего необязательного файла
- **THEN** откат восстанавливает полный прежний набор и его метаданные, запускает только его и подтверждает его фактическую работу

#### Scenario: Conflicting files cannot be overwritten by rollback
- **WHEN** живой каталог, процесс или закреплённая копия противоречат доверенному намерению
- **THEN** восстановление блокирует перезапись и сохраняет обнаруженные доказательства

#### Scenario: A completed apply does not roll back because reporting failed
- **WHEN** новая база уже надёжно зафиксирована, а подтверждение серверу не доставлено
- **THEN** локальный откат не запускается

### Requirement: Rollback outcomes distinguish recovered runtime from historical confirmation

Откат SHALL признаваться завершённым после доказательства точного прежнего диска, процесса и трафика и устойчивой фиксации. Последняя исторически подтверждённая ревизия SHALL сохраняться отдельно от результата целевой попытки и текущего доказанного runtime.

#### Scenario: A previous local baseline has no server revision
- **WHEN** откат к первоначальной локальной базе успешно завершён
- **THEN** агент подтверждает восстановление локально без назначения ей номера желаемой ревизии и без сообщения applied для целевой попытки

#### Scenario: A failed or uncertain rollback keeps the start barrier
- **WHEN** восстановление, повторное доказательство или фиксация отката не завершены надёжно, либо исход записи нового commit неизвестен
- **THEN** агент удерживает безопасный барьер, сохраняет журнал и обе копии, а текущее runtime остаётся неопределённым
- **AND** последняя подтверждённая ревизия остаётся доступной как история

#### Scenario: Interrupted recovery differs from terminal rollback failure
- **WHEN** защищённый журнал содержит прерванный откат либо устойчиво зафиксированный отказ отката
- **THEN** прерванный откат сохраняет право на ограниченное разрешение той же попытки при старте
- **AND** зафиксированный отказ исключает автоматические повторные рестарты

#### Scenario: A saved rollback result does not restart twice
- **WHEN** сохранённый результат уже подтверждает откат этой попытки
- **THEN** повторное обращение возвращает сохранённый исход без ещё одного изменения рабочего процесса
- **AND** сохранённый результат сам по себе не подтверждает текущее runtime после последующей попытки или внешнего изменения

#### Scenario: An identical failed desired revision needs an explicit safe retry
- **WHEN** автоматический цикл снова получает точный тег цели уже подтверждённого отката
- **THEN** агент оставляет прежнюю базу и рабочий процесс
- **AND** новая желаемая ревизия использует обычный допуск, а та же цель может получить одну повторную попытку после явного локального разрешения с привязкой к исходу отката
