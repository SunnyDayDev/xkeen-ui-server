## Ход Red/Green

- 1.2: `TestRestoreElement` — Red (nil вместо элемента), затем Green. `TestInvalidElementID` — Red для десяти вариантов неверного ID, затем Green с проверкой канонического UUIDv4.
- 1.3: `TestUpdateElementIdentity` — последовательные Red для отсутствия обновления, неотклонённого mismatch и неверного кода для ошибочного исходного ID; после минимальных изменений Green. После gofmt весь пакет A06/A08 проходит.
- 1.4: `TestExactSourceRoundTrip` — Red (пустой результат Encode), затем Green с текстовым содержимым в оболочке.
- 1.5: `TestDefinitionRoundTrip` — Red (определения потеряны), затем Green для пяти типов, отсутствующего/пустого/null-дефолта и точных чисел. `TestStoredContentShapes` сразу Green: общий строковый round-trip уже сохраняет массивы, примитивы и метку; это регрессионное подтверждение, не отдельный Red.
- 1.6: `TestStoredJSONIntegrity` — Red для синтаксиса/UTF-8/дублей в содержимом и дефолтах, затем Green. `TestRecordIntegrity` — Red для неполных/неверных оболочек, неявно принимаемых полей и повторных ключей, затем Green. Уже отклонявшиеся формы отмечены регрессией. Общий парсер перенесён без изменения правил; целевые тесты A06 и весь набор конфигурации проходят после gofmt.
- 2.1/2.2: `TestReferenceDeclarations` — Red (нет объявлений) для обычного объекта, корня, вложенных повторов и точных Unicode-имён; затем Green с `string`/`""` и одним объявлением каждого имени.
- 2.3: `TestDeclarationSyntax` — Red для ошибочно объявленных частичных/пустых/невалидных имён; затем Green. Экранирование JSON, буквальные ссылки, ключи и дефолты сразу соответствовали выбранной границе обхода и проверены как регрессия.
- 2.4: `TestExistingDefinitionsAndRepeatedSave` — Red (повторное объявление сбоку от настроенного), затем Green с сохранением имеющихся настроек.
- 2.5/2.6: `TestReferenceEditLifecycle`, `TestRestoreDoesNotDiscoverOrRepair`, `TestDecodeDoesNotDiscover` сразу Green после реализации дополнения списка: исчезновение/возврат, явное удаление, переименование, сохранение ошибочных определений и чтение без обнаружения подтверждены как регрессия. Искусственный Red не создавался. После gofmt весь набор проходит.
- 3.1: `TestTemplateIdentitySet` — Red (дубликат не найден), затем Green; пустой/уникальный набор и неизменность входа проверены.
- 3.2: `TestRouterIdentityCollisions` — Red для локального повтора, исключённого общего и нового общего элемента; затем Green с обеими позициями/владельцами.
- 3.3: `TestIdentitySetBoundaries` — Red для неверного ID/контекста/позиции, затем Green. Независимые владельцы и замена исходной записи сразу проходили как регрессионные случаи. После gofmt весь набор проходит.
- 4.1: `TestDraftStorage` — Green как регрессия: неготовые состояния сохраняются без исправления, одинаковые ключи разных объектов разрешены; полная сборка не вызывается.
- 4.2: `TestElementInputIsolation` — Red (общий список/буфер и запись в резервную ёмкость входного slice), затем Green после копирования. `TestElementStructuralStringsAndContext` — Red для неверного контекста и UTF-8 метаданных, затем Green. `TestKnownIdentityInRecordError` — Red (известный UUID пропал из ошибки структуры), затем Green. `TestStorageSafeDiagnosticsAndIsolation` подтвердил безопасные ошибки и независимость буферов. После gofmt весь набор проходит.
- 4.3: `TestElementEditingLifecycle` — PASS: объявление → чтение → смена типа/дефолта → удаление ссылки → проверка кандидатного набора → повторное чтение. UUID и настройки сохранены, исходный текст каждого состояния точный; БД/UI/сборка не используются.
