## ADDED Requirements

### Requirement: Local content is literal JSON

Локальное содержимое при выборе набора одного роутера SHALL приниматься как готовый JSON с собственным внешним UUID, без определений и значений переменных. Все корневые JSON-типы, включая `null`, и вложенный `null` SHALL допускаться. Строки `${name}`, `$$` и частичные ссылки SHALL оставаться буквальными; объявления и подстановка переменных SHALL NOT выполняться. Содержимое SHALL сохраняться побайтово, включая неизвестные поля, запись чисел и порядок массивов; служебная метка SHALL NOT добавляться или интерпретироваться.

Ввод SHALL содержать один JSON-корень, корректный UTF-8 и уникальные ключи объектов на любой глубине. Отсутствующий/пустой/пробельный ввод, неверный синтаксис, несколько корней и неверный UTF-8 SHALL давать `invalid_json`; повторные ключи SHALL давать `duplicate_json_key`. Ошибка SHALL относиться к локальному элементу роутера с источником `content`. Исправление ввода или fallback к общему элементу SHALL NOT выполняться. Допустимость для позиции Xray SHALL проверяться отдельно; запрет `null` в сборке переменных SHALL оставаться прежним.

#### Scenario: Local strings and exact JSON remain unchanged

- **WHEN** локальный JSON содержит `{"tag":"demo","extension":["${host}","$$","https://${host}",9007199254740993,1e+03]}` с дополнительным форматированием
- **THEN** содержимое результата побайтово совпадает с вводом, `host` не объявляется и не подставляется
- **AND** общий элемент с таким же `tag` и другим UUID остаётся отдельным элементом

#### Scenario: Local JSON supports every root type

- **WHEN** локальный элемент содержит один из JSON-корней `null`, `false`, `443`, `"${host}"`, `[]` или `{"nested":[null]}`
- **THEN** каждый вариант успешно выбирается как содержимое локального элемента с его UUID
- **AND** JSON `null` не обозначает отсутствие элемента

#### Scenario: Malformed local JSON blocks the whole selection

- **WHEN** один локальный элемент содержит отсутствующий, пустой, пробельный, синтаксически неверный JSON, несколько корней либо неверный UTF-8
- **THEN** выбор возвращает `invalid_json` без выбранного набора
- **AND** ошибка указывает владельца-роутер и позицию этого элемента без раскрытия ввода

#### Scenario: Duplicate local keys are rejected at any depth

- **WHEN** локальное содержимое содержит `{"extension":{"x":1,"x":2}}` либо ключи с одинаковым декодированным именем
- **THEN** выбор возвращает `duplicate_json_key` без результата и без исправления содержимого

### Requirement: Router selection checks the complete identity and binding set

Выбор SHALL принимать полный переданный набор общих элементов одного выбранного шаблона, самостоятельных локальных элементов одного роутера, переопределений и исключений. Контексты владельцев/позиций, UUID, уникальность самостоятельных элементов и ссылки SHALL проверяться до сборки какого-либо содержимого и применения исключений. Общие и локальные элементы SHALL проверяться во всех переданных позициях, включая исключённые и отключённые; вызывающая сторона SHALL передавать полный набор. Уникальность SHALL следовать `configuration-element-identity`, без генерации/смены ID, удаления записей или слияния по тегу.

Переопределения и исключения SHALL ссылаться на существующий общий элемент выбранного шаблона по паре «шаблон + UUID». Корректная ссылка на другой шаблон SHALL давать `source_mismatch`; корректная ссылка на выбранный шаблон и UUID, отсутствующий среди общих элементов, SHALL давать `source_not_found`. Наличие такого UUID только среди локальных элементов SHALL NOT удовлетворять ссылку. Некорректный контекст/идентификатор шаблона SHALL давать `invalid_element_record`, неканоничный UUID — `invalid_element_id`. Другой шаблон SHALL диагностироваться до поиска UUID в выбранном шаблоне.

Повторные переопределения SHALL давать `duplicate_override`, повторные исключения — `duplicate_exclusion`, с обеими позициями; одно переопределение и одно исключение одного источника SHALL допускаться. Режим каждого переопределения SHALL быть известным даже под исключением; неизвестный режим SHALL давать `invalid_element_record`. Проверка SHALL NOT применять правило «последняя запись побеждает». Отсутствие источника SHALL NOT инициировать очистку персонального состояния или превращение его в локальный элемент. Порядок независимых ошибок не гарантируется.

#### Scenario: Identity collisions are detected before exclusions

- **WHEN** локальный UUID совпал с общим, исключённым на роутере, либо повторился среди локальных или общих элементов, в том числе в разных секциях полного набора
- **THEN** выбор возвращает `duplicate_element_id` с обеими позициями без результата
- **AND** содержимое и исключение не позволяют скрыть коллизию

#### Scenario: A new shared element can conflict with an existing local element

- **WHEN** ранее допустимый набор пересобирается с новым общим элементом, UUID которого занят локальным
- **THEN** выбор возвращает `duplicate_element_id`, не меняя UUID и персональные данные

#### Scenario: Invalid metadata fails even for an empty or excluded selection

- **WHEN** владельцы пустого набора некорректны либо UUID/позиция исключённого общего элемента или его ссылки невалидны
- **THEN** выбор возвращает `invalid_element_record` либо `invalid_element_id` до проверки содержимого
- **AND** невалидные UUID и контексты не копируются в диагностику

#### Scenario: A foreign template cannot supply a binding

- **WHEN** переопределение либо исключение ссылается на другой шаблон, независимо от наличия такого UUID в выбранном шаблоне
- **THEN** выбор возвращает `source_mismatch` без результата и без fallback

#### Scenario: Missing shared sources are rejected without cleanup

- **WHEN** переопределение либо исключение ссылается на выбранный шаблон и корректный UUID, которого нет среди общих элементов, даже если он есть среди локальных
- **THEN** выбор возвращает `source_not_found` с позицией ссылки и корректным UUID
- **AND** исходная ссылка и её персональные данные остаются неизменными

#### Scenario: Repeated bindings are errors rather than last write wins

- **WHEN** переданы два переопределения одного источника либо два исключения одного источника
- **THEN** выбор возвращает соответственно `duplicate_override` либо `duplicate_exclusion` с обеими позициями
- **AND** повторное переопределение под исключением также отклоняется

#### Scenario: An exclusion can coexist with one override

- **WHEN** для существующего общего элемента переданы одно корректное переопределение и одно исключение
- **THEN** привязки принимаются, элемент отсутствует в выбранном наборе, персональные данные сохраняются

#### Scenario: Unknown modes are not hidden by exclusions

- **WHEN** переопределение исключённого общего элемента содержит неизвестный режим
- **THEN** выбор возвращает `invalid_element_record` без результата

### Requirement: Excluded content does not participate in assembly

После успешной проверки полного набора идентичностей и привязок исключённый общий элемент SHALL отсутствовать в выбранном наборе. Его исходный JSON, определения, дефолты, персональные значения и собственный JSON SHALL NOT собираться или проверяться как активное содержимое. Исключение SHALL NOT удалять или менять эти данные и SHALL сохранять силу при повторном выборе и изменении общего содержимого. Снятие исключения SHALL возобновлять выбор текущего режима с его обычной проверкой; сброс переопределения SHALL сохранять исключение по существующему контракту.

#### Scenario: Excluded inherited errors do not block other elements

- **WHEN** исключённый общий элемент содержит ошибочный сырой JSON, определения/дефолты либо незаполненные обязательные значения, а остальные включённые элементы корректны
- **THEN** выбор успешно возвращает только остальные элементы без ошибок содержимого исключённого блока
- **AND** его UUID продолжает участвовать в проверке полного набора

#### Scenario: Exclusion hides an invalid replacement without destroying it

- **WHEN** исключение скрывает режим полной замены с некорректным собственным JSON и неготовыми сохранёнными значениями
- **THEN** выбор не возвращает ошибок этого содержимого и не меняет его
- **AND** после снятия исключения та же полная замена даёт обычную ошибку своего JSON без перехода к шаблону

#### Scenario: Repeated selection preserves exclusion across template edits

- **WHEN** после успешного выбора изменён JSON исключённого общего элемента с прежним UUID и выбор вызван с тем же исключением
- **THEN** элемент по-прежнему отсутствует, а локальные элементы сохраняют содержимое
- **AND** выбор для другого роутера без исключения использует изменённый общий элемент

#### Scenario: Removing an exclusion restores the current mode

- **WHEN** исключение снято без изменения корректного переопределения в режиме переменных либо полной замены
- **THEN** элемент возвращается с персональными значениями и актуальным шаблоном либо с собственным JSON соответственно
- **AND** источник и UUID остаются прежними

#### Scenario: Reset under exclusion does not resurrect the element

- **WHEN** переопределение полностью сброшено, а исключение сохранено
- **THEN** повторный выбор не возвращает элемент и не восстанавливает удалённые персональные данные
- **AND** после снятия исключения используется актуальный шаблон; отсутствие обязательного значения даёт `missing_value`

### Requirement: Router selection returns an independent unordered content set

Успешный выбор SHALL возвращать набор включённых элементов, адресуемых по внешнему UUID. Для каждого элемента SHALL быть различимы локальное либо общее происхождение, а для общего — источник и выбранный режим. Каждый включённый общий элемент SHALL использовать существующий контракт выбора одного элемента, локальный — контракт буквального JSON. Пустые входные списки и исключение всех общих элементов при отсутствии локальных SHALL давать успешный пустой набор, отличимый от ошибки.

Ошибка любого включённого содержимого либо метаданных SHALL возвращать отсутствие всего результата и хотя бы одну конкретную ошибку. Входы SHALL оставаться неизменными, изменяемые данные результата SHALL быть независимыми от входов и других элементов результата. Диагностика SHALL сохранять сведения существующих проверок: код, валидные владельца/позицию, корректный UUID, источник ошибки, известное имя переменной, ожидаемый тип, путь/смещение и вторую позицию конфликта, где применимо. Значения, сырой JSON, дефолты и невалидные UUID/контексты SHALL NOT раскрываться.

Выбор SHALL NOT задавать итоговый порядок, менять настройку порядка, интерпретировать поля включения/выключения внутри JSON, проверять межэлементные ссылки или Xray, добавлять служебную метку, публиковать или применять конфигурацию. Самостоятельная семантика отключения не задаётся этой операцией: переданные элементы остаются в области выбора, если для общего элемента нет явного исключения.

#### Scenario: Mixed content uses the existing active branches

- **WHEN** набор содержит общий элемент по дефолтам, общий с персональными значениями, общий с полной заменой и самостоятельный локальный
- **THEN** каждый UUID получает соответствующее содержимое и происхождение; переменные обрабатываются только в наследуемых ветвях
- **AND** `null` локального или полной замены допустим, а `null` активного шаблона или его данных переменных даёт `null_not_allowed` без результата

#### Scenario: Empty selection is a successful value

- **WHEN** при корректных владельцах все списки пусты либо все общие элементы исключены и локальных нет
- **THEN** возвращается успешный пустой набор без ошибок

#### Scenario: A late content failure yields no partial result

- **WHEN** несколько включённых элементов корректны, а ещё один имеет ошибку переменной либо JSON
- **THEN** результат всего набора отсутствует, ошибка содержит сведения соответствующей ветви и позицию
- **AND** исходные элементы, переопределения и исключения не меняются

#### Scenario: Results and diagnostics do not retain mutable input data

- **WHEN** вызывающая сторона меняет буфер входного JSON/значения после успешного выбора либо изменяет содержимое одного элемента результата
- **THEN** ранее полученный результат либо исходные данные соответственно не меняются, соседний результат независим
- **AND** ошибки не содержат значений или сырого JSON

#### Scenario: Selection does not invent routing order or disable semantics

- **WHEN** общие и локальные правила переданы в другом порядке или содержат пользовательское поле `enabled: false`
- **THEN** набор по UUID сохраняет содержимое и происхождение; это поле само по себе не исключает элемент
- **AND** операция не назначает положение локального правила и не объявляет конфигурацию готовой для Xray
