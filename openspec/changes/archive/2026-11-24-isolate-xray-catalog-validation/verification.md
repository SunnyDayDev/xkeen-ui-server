# Проверка C06.2

[C06.2 #51](https://github.com/SunnyDayDev/xkeen-ui-server/issues/51) поставляет серверный порт и двухстороннюю проверку Xray для [C06 #49](https://github.com/SunnyDayDev/xkeen-ui-server/issues/49). C06.4 отдельно использует порт в операции фиксации.

## Red и Green

- Первая компиляция тестов на точный состав и независимость файлов, привязку ответа, три исхода, доверие транспорта и завершение процесса показала отсутствие порта/протокола. После добавления контракта тесты ещё не компилировались из-за отсутствующих реализации протокола и исполнителя. После реализации целевой пакет прошёл.
- Тест парсера зафиксировал принятие неоднозначного сообщения с ключами, отличающимися регистром. Ограниченная точная схема устранила ошибку.
- Тест размера первоначально получил «отказ каталога» вместо «недоступен». Отдельный тест первоначально принял Unix socket в доступном для записи каталоге. После правок оба прошли. Для второго теста первоначальная ошибка длины пути Darwin не считалась Red; ошибка поведения воспроизведена на коротком пути.
- Повторный локальный вызов первоначально прошёл после изменения прав каталога за счёт уже открытого соединения. Канонический проверенный адрес и проверка нового соединения при каждом вызове исправили результат.
- Проба известной ошибки конфигурации с кодом 23 первоначально дала недоступность. Подтверждённые категории отказа отделены от ошибок ресурсов и неоднозначного выхода.
- Тесты PID 1 зафиксировали отсутствие управления временем исполнения. После реализации подтверждены передача кода 23, код 124 по локальному дедлайну и код 125 при невозможности запуска. Тест отсутствующей проверки файлов внутри runtime затем привёл к сверке манифеста непосредственно в read-only mount до `-test`.
- Сценарии реального Xray, временных mTLS-удостоверений, одновременных вызовов, очистки и переполнения вывода дополняют эти Red/Green. Их результаты приведены ниже как интеграционные и регрессионные проверки.

## Выполненные проверки

- `go test -count=1 ./...`, `go vet ./...`, `go test -race -count=1 ./internal/validation ./cmd/xkeen-validator-run`, `sh -n lab/check-validator.sh` прошли.
- `sh lab/check-validator.sh` прошёл с Xray 26.3.27, linux/arm64, Go 1.27.1 и Docker Desktop LinuxKit aarch64. Реальный Xray принял шесть положительных файлов B12 и отверг отрицательный набор. Успешно прошли дополнительный файловый журнал в одноразовом tmpfs, очистка искусственного оставшегося задания и проверка тем же worker по mTLS от непривилегированного Entware aarch64-клиента.
- Проверены недоверенная CA, другой клиент той же CA, отбрасывание перенаправления, несовпадающие профиль/метка/digest, изменение байтов и дополнительные файлы. Выполнены отмена активного запроса, отказ при занятости, ограничение вывода и возврат безопасной ошибки при внутренней ошибке с искусственным секретом.
- Независимый ревьюер повторил целевые Go-тесты, реальный стенд и запуск CLI через Unix socket. Остановка по SIGTERM завершилась успешно, постоянного вывода и оставшихся каталогов задания не обнаружено. В сборке C06.4 отдельно повторена интеграционная проверка с этим исполнителем.
- Строгая проверка change и затронутой capability прошла. Общее `openspec validate --all --strict` сохраняет предупреждения в ранее существующих незатронутых требованиях длиной более 500 символов. Они не являются результатом C06.2.

Полноценная проверка совместимости с физическими ядрами роутеров и реальными внешними системами не проводилась. Привилегии Docker Engine есть только у оператора worker. Исполнитель, которому оператор разрешил расшифровать каталог, остаётся доверенной стороной. Лабораторная поставка не содержит дополнительных GeoIP/GeoSite-данных. Данные профиля при необходимости включаются в закреплённый образ оператором. Трафик и работающее применение на устройстве проверяет агент последующих этапов.
