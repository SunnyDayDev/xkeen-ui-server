## Context

F19 определил независимые переключатели и один токен с немедленным отзывом. Начальный режим закрыт. F03 управляет входом, временем действия и защитой запросов владельца.

## Decisions

Выделить один агрегат настроек с монотонным поколением. Хранить только SHA-256 32 случайных байтов токена, канонический base64url без дополнения. Если настройки отсутствуют, инициализировать закрытый режим и пустой verifier. Любая успешная замена или изменение доступа делает ранее выданное свидетельство допуска устаревшим. Изменение состояния через интерфейс владельца требует ожидаемой версии, проверенного F03 origin и защищённого запроса. SQLite writer повторно проверяет живую сессию и версию. Операции реализуют GET/PATCH /ui/v1/settings/external-api и POST /ui/v1/settings/external-api/token. Версия в JSON для веб-адаптера, состояние без секрета при GET. Не повторять мутацию автоматически.

Внешний middleware покрывает /api/v1 и его потомков. Выключенный API даёт 404, отсутствующий или неверный токен в защищённом режиме — общий 401 c Bearer challenge. Открытый режим сохраняет доступ без токена. Для браузерной записи проверяется Origin, а реальный HTTPS проверяется независимо от forwarded headers. Полученное приложение передаёт свидетельство актуального поколения в адаптер операции F21/F22; подтверждение записи F22 выполняется в той же SQLite-транзакции, что и CAS C03.

## Risks / Trade-offs

После потери единственного показа требуется ручная замена у всех клиентов. Секрет существует только в ответе и памяти открытого компонента, ответы no-store, текущая страница убирает показ при истечении сессии. Настройкам нужен пользовательский путь из работающей оболочки.
