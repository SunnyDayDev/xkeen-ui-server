## Context

Показать текущий вход и реальные зависимости. Запретить выключение и удаление используемого входа при отказе B10 в серверной команде. Сохранить только валидный условный черновик; общее удаление для этого роутера сохраняет исключение. Используются F15, B06, B10, C04.

## Decisions

Вход из карточки обзора: `/ui/routers/inbounds?routerId=<exact>`. Чтение и запись используют защищённое основание черновика F12 и согласованный полный порядок F14/F15. Выбор входов и правил переиспользует B06, а проверка команды использует B10 `GuardInboundChange` для одного UUID. Проверяются итоговые ссылки `inboundTag`, включая персональные значения, полную замену и локальные правила. Недоказанный состав и ошибки формы или неоднозначности блокируют эффект; отсутствие ссылки на этот вход не делает готовым остальной черновик.

Выключение хранит UUID в `DisabledInbounds`. Удаление общего входа создаёт исключение B06 только для этого роутера, сохраняя исходный общий элемент и данные переопределения. Удаление локального входа удаляет запись из секции `inbounds`. Удаление в обоих случаях снимает прежнюю отметку выключения для того же UUID. Подтверждение удаления показывает последствия и требует отдельного действия. Тот же C04 writer сверяет видимость, сессию, активное назначение, принятую версию и поколение персонального черновика. Состояние неизвестного исхода требует явного чтения; приложение не повторяет команду автоматически.

## HTTP и данные экрана

Внутренний `GET /ui/v1/routers/inbounds?routerId=<exact>` возвращает доступные входы и основание C04. При выборе входа добавляется `elementId=<uuid>` для точного запроса зависимостей этого входа. Признак выключения учитывает общий шаблон и настройки роутера. Имя отображается по эффективному тегу, при его отсутствии используется UUID. Для выключенного входа без вычисленного тега используется UUID. Уже исключённый общий вход недоступен для повторного удаления.

`POST` по адресу с точным UUID принимает `action=disable` либо `action=remove` и ранее прочитанное основание. Сервер заново выбирает снимок, сравнивает поколение, применяет B10 и передаёт условную запись тому же C04 writer, который повторяет проверку сессии и поколений. При B10 `inbound_in_use` ответ указывает стабильные UUID и безопасные позиции правил. Исходный JSON и личные значения в ответе об ошибке не возвращаются.

## Матрица проверки

- Сохранённые локальные правила и буквальные правила с полной заменой блокируют соответствующий UUID входа по итоговому `inboundTag`; B10 остаётся единственным анализатором.
- Выключенное и исключённое правило не удерживает вход. Его неготовый JSON не разбирается. Для выключенных общих правил и входов учитывается и отметка шаблона.
- Косвенная чужая ссылка оставляет черновик неготовым к публикации; ошибочная форма или неоднозначность состава дают безопасное состояние без команды.
- Изменение принятой версии, переключение сессии, скрытие роутера или одно параллельное сохранение между проверкой и writer блокирует устаревшую операцию. Успешные выключение и удаление не меняют остальные группы, порядок и применённую ревизию.

## Risks / Trade-offs

Сетевой отказ и неполное доказательство не подтверждают изменение. Места ошибок и безопасные диагностические результаты сверяются с актуальными входами на штатном сервере.
