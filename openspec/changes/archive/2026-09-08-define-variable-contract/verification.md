# Проверка A05: контракт переменных

Дата: 2026-09-08. Задача: [issue #6](https://github.com/SunnyDayDev/xkeen-ui-server/issues/6). Результат — согласованный контракт и документация. Подстановка и её тесты относятся к будущим A06/B01/B02.

## Сверка критериев

| Критерий issue | Подтверждение |
| --- | --- |
| Точное имя и точка | `Element scoped exact variable names`: отдельные области элементов, чувствительность к регистру и полный поиск `server.address` |
| Типы | `Typed whole value substitution`: пять типов, корневое и вложенное значение, точные числа, отказ от преобразования числовой строки |
| Дефолты и обязательность | `Missing values and defaults`: отсутствие/Unicode trim, дефолт, обязательное неиспользованное определение, false/0/пустые коллекции и сохранение непустых строк |
| Null, экранирование, частичная интерполяция | Отдельные требования `Null is rejected`, `Literal escaping and unsupported interpolation`, `Substituted data is not a new template` |
| Диагностика и сохранность | `Atomic result and safe diagnostics`: полный результат или ошибки, неизменность входов, отсутствие значений в диагностике |
| Артефакты и целевая проверка | Proposal, design, delta spec, tasks и этот отчёт; результаты ниже |
| Согласованная документация | Обновлены модель конфигурации, раздел переменных и открытых вопросов прототипа, результат A05 и границы B01/B02 в roadmap |

## Выполненные проверки

- `openspec validate define-variable-contract --strict` — успешно до архивирования.
- `openspec validate --specs --strict` — 3 спецификации прошли, 0 ошибок. CLI выдал информационные замечания о длине некоторых требований; это не ошибки валидации.
- `git diff --check` — код 0 для отслеживаемых изменений. Новые файлы отдельно проверены на завершающий перевод строки и отсутствие концевых пробелов.
- Целевая проверка документов временным Python-скриптом: JSON-блоки разобраны через `json.loads`; локальные ссылки проверены по существованию целей, якоря — по заголовкам Markdown; во всех сценариях есть WHEN/THEN. До добавления этого отчёта проверены 8 Markdown-файлов, 32 ссылки (3 якоря) и 6 JSON-блоков.
- Основная спецификация сравнена с delta: Purpose и все 7 требований/22 сценария совпадают; заголовок delta заменён на основной `Requirements`, существующие capabilities не изменены.
- При ручной сверке содержимого и поиске локальных пользовательских путей/характерных префиксов токенов частных данных не обнаружено. Примеры используют демонстрационные домены и значения.
- Сценарии распределены между A06/B01/B02. Контроль JSON и точности относится к A06; определения, заполненность и типы — к B01; null и оставшийся синтаксис — к B02. Диагностика и отсутствие частичного результата проверяются для ошибок каждого этапа.

Тесты поведения Go, Red/Green, запуск Xray и проверки UI не выполнялись: код и макет не менялись. В design предусмотрены отдельные контрактные циклы Red → Green → Refactor для будущей реализации. Эти проверки документов не доказывают работу сборщика.
