# Проверка Docker-сервера G10

[Issue #105](https://github.com/SunnyDayDev/xkeen-ui-server/issues/105) проверена на Linux ARM64 и AMD64 с временными ресурсами Docker. Тест сначала получил штатный Red при отсутствии Dockerfile. После добавления образа обе архитектуры собраны и запущены.

Процесс работал с UID/GID 65532, read-only корнем и отдельным именованным томом. Новый том прошёл миграции до первого `healthz`. В отдельном TLS-запуске использовался синтетический сертификат с проверяемым DNS-именем. Запрошены `/ui/` и JS по точному хешированному адресу из HTML. До локальной команды с файлом 0600 получен `setup_required`. После настройки удалось войти. Новый контейнер с тем же томом принял существующую cookie и повторную проверку пароля. Штатный SIGTERM на каждом этапе завершился кодом 0.

```sh
sh lab/check-server-image.sh
XKEEN_TEST_SERVER_PLATFORM=linux/amd64 sh lab/check-server-image.sh
```

Контекст сборки содержит Go и встроенный UI. В тесте пароль, ключ TLS и cookie создаются отдельно от контекста и удаляются после прогона. Стенд не подключает валидатор Xray и физические устройства. Образ собран и проверен локально. Публикация образа и выпуск остаются отдельными решениями владельца.

Независимое ревью подтвердило границы сборочного контекста, владение томом, прямой TLS и фактическую проверку встроенного ресурса.
