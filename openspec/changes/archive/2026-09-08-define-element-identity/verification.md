# Проверка контракта идентичности A07

Дата: 2026-09-08. Задача: [issue #8](https://github.com/SunnyDayDev/xkeen-ui-server/issues/8), change `define-element-identity`.

## Результат ревью

Пользователь принял подготовленный change к выполнению A07. Сверены семь требований и 25 сценариев в [delta spec](specs/configuration-element-identity/spec.md). Приняты UUIDv4 в канонической записи, внешний источник идентичности, независимые `tag`/`ruleTag`, единая метка `_xkeenUiId`, область владельца и безопасная обработка конфликта. Новых продуктовых требований сверх подготовленного предложения не добавлено.

| Критерий issue #8 | Артефакты и проверяемое покрытие |
| --- | --- |
| Стабильный ID отдельно от Xray-тегов, уникальность, смена тега, произвольный JSON | `Stable external element UUID`, `Identity uniqueness within an owner`, `Overrides retain source identity`, `Xray tags are independent of element identity`; сценарии дубликатов между секциями/локальными элементами и смены `primary-proxy` на `backup-proxy` |
| Артефакты и фактическая целевая проверка | Proposal, design, delta spec, tasks; в разделе 5 [design](design.md) записаны версия, базовый JSON, команда и результаты 13 проб Xray |
| Согласованная документация и явно открытые решения | Обновлены `docs/configuration-model.md`, `docs/prototype.md`, `docs/roadmap.md`; копирование/импорт, порядок, граф зависимостей, новые позиции/версии и UI остаются отдельной работой |

## Проверка совместимости

Перечень позиций в spec сверён с таблицей и фактическими входами в design: вход, выход, правило, `log`, `dns`, `routing`, `policy`, `stats`, пул FakeDNS и `observatory`. Все десять проб с UUID и базовая проба дали код 0 и `Configuration OK.`. Контрпример `policy.levels._xkeenUiId = {}` дал ожидаемый код 23. `dns.hosts._xkeenUiId = "192.0.2.99"` был принят как запись DNS, что исключает использование этой позиции для служебной метки.

Проверки выполнены при подготовке этого change на Xray 26.3.27 ARM64 в изолированном стенде. При выполнении A07 версия, поля и позиции не менялись, повторный запуск не требовался. Это проверки загрузки конфигурации и сверка исходников, не проверки трафика, перезапуска XKeen, firewall или горячего API. Рабочие файлы стенда и реальные устройства не изменялись.

## Передача в будущую реализацию

Таблица раздела 6 design сверена с roadmap: A08 получает чтение/сохранение модели и дубликаты, B03–B06 — переопределения и объединённый набор, B07–B08 — ссылки порядка, B09–B12 — теги, зависимости, проекцию и полный конфиг. Генерация при создании и транзакционное применение инвариантов остаются будущим прикладным сценариям. Контракты границ определяют входы, результаты и ошибки; ядро не зависит от БД, HTTP и запуска Xray.

Для каждого малого сценария кода предусмотрены отдельные контрактные тесты, подтверждённый Red, минимальная логика для Green и рефакторинг с повторной проверкой. Подстановка A06, её диагностические строковые ID и тесты не изменены. Go-тесты, сборки и Red/Green в A07 не выполнялись: код поведения не менялся. Макеты не изменялись; будущий UI проходит Pencil и визуальную проверку до тестов/кода и повторную визуальную сверку после реализации.
