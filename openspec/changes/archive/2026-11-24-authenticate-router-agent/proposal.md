## Why

Серверу требуется установить личность установленного агента по полномочиям уже подготовленного роутера. [D03 / issue #65](https://github.com/SunnyDayDev/xkeen-ui-server/issues/65) реализует серверную часть [D02 / issue #60](https://github.com/SunnyDayDev/xkeen-ui-server/issues/60) на выделенном канале [D01 / issue #59](https://github.com/SunnyDayDev/xkeen-ui-server/issues/59).

## What Changes

- D03.1 добавляет внутренние операции выдачи, погашения, точного повтора, замены и отзыва. SQLite хранит проверочные значения и связывает их с действующей идентичностью роутера. Первое приглашение использует подтверждённое назначение и первую желаемую ревизию C06.
- D03.2 добавляет два ограниченных маршрута агента для привязки и проверки действующего рабочего ключа. Сервер открывает эти маршруты при явно настроенном TLS; существующий запуск с HTTP health check доступен.
- Рабочий ключ разрешает запросы только в области собственного роутера. Операторские поверхности и внешний API остаются в области F/G, получение конфигурации и контакт в D05/D06. D04 использует серверный контракт с настоящим TLS.

## Capabilities

### New Capabilities

- `agent-server-enrollment` — транспортный контракт привязки и чтения собственной идентичности, включение защищённого серверного входа и безопасные ошибки. Инварианты срока, назначения и ключей определяет D02.

## Impact

Затронуты прикладной слой идентификации, SQLite, HTTP-адаптер и конфигурация Go-каркаса. План состоит из двух проверяемых этапов. D03.1 сохраняет существующие снимки и ревизии при миграции. D03.2 связывает порт с существующим запуском, health check и штатной остановкой. Пользовательские UI и установщик относятся к другим задачам.
