## Why

После выбора Go в [A01](../../../../docs/server-stack-research.md) проекту нужен первый запускаемый процесс центрального сервера. [A03 / issue #4](https://github.com/SunnyDayDev/xkeen-ui-server/issues/4) даст проверяемую основу для следующих возможностей: старт, проверку доступности и штатное завершение.

## What Changes

- Добавить Go-модуль и исполняемый сервер на стандартной библиотеке, без сторонних runtime-зависимостей.
- Предоставить одну команду локальной сборки и запуска, а также запуск готового бинарника. Адрес по умолчанию — `127.0.0.1:8080`, переопределение через `--listen`.
- Добавить `GET /healthz` с ответом `200` и JSON `{"status":"ok"}` как проверку доступности HTTP-процесса.
- Обрабатывать ошибки старта и сигналы SIGINT/SIGTERM: освобождать listener, завершать текущие запросы в пределах установленного срока и возвращать различимые коды завершения.
- Проверить поведение по циклам TDD/BDD, собрать `linux/arm64` без cgo и выполнить отдельную пробу жизненного цикла в существующем Entware-образе.
- Обновить инструкцию запуска и статус реализации, сохранив различие между каркасом, лабораторной проверкой и поддержкой физического роутера.

## Capabilities

### New Capabilities

- `server-lifecycle`: локальный запуск Go-сервера, настройка listener, HTTP-проверка доступности, ошибки и завершение процесса, проверка Linux ARM64 в Entware-стенде.

### Modified Capabilities

Нет. Требования `router-lab` сохраняются; проба сервера использует отдельный контейнер существующего образа.

## Impact

Области реализации: `go.mod`, `cmd/xkeen-ui-server/`, `internal/server/`, `scripts/run-server.sh` и целевые тесты. Документация: README, архитектура, план работ и инструкция проверки каркаса. Ход реализации отражён в [tasks](tasks.md), фактические проверки — в [verification](verification.md).

В change не входят БД и миграции, CRUD, авторизация, UI, протокол агента, установщик/`init.d`, CI, продуктовый Docker-образ, публикация и подключение физических устройств. SQLite будет подключаться в C01; минимальные проверки GitHub Actions относятся к A04. Новых экранов нет, изменение макетов не требуется.
