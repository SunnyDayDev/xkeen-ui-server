## Purpose

Определить первый проверяемый жизненный цикл центрального сервера: локальный запуск, HTTP-проверку доступности и завершение процесса с явным результатом, включая отдельную проверку в Entware aarch64.

## ADDED Requirements

### Requirement: Foreground launch and listen configuration

The server SHALL run in the foreground. После установки документированной версии Go команда `sh scripts/run-server.sh` из корня репозитория SHALL собрать и запустить сервер без настройки БД и других служб. Готовый бинарник SHALL запускаться непосредственно и принимать те же аргументы. Адрес по умолчанию SHALL быть `127.0.0.1:8080`; `--listen` SHALL принимать IPv4 или IPv6 literal с числовым портом от 0 до 65535 в формате `host:port`. Порт 0 SHALL выбирать свободный порт средствами ОС. Конфигурация этого каркаса SHALL задаваться аргументами командной строки.

#### Scenario: Default local launch

- **WHEN** разработчик выполняет команду локального запуска без аргументов при свободном `127.0.0.1:8080`
- **THEN** сервер работает в foreground и принимает HTTP-запросы на `127.0.0.1:8080`
- **AND** скрипт запуска передаёт управление серверному процессу и возвращает его код завершения

#### Scenario: Explicit listener and allocated port

- **WHEN** сервер запущен с `--listen 127.0.0.1:0`
- **THEN** он принимает запросы на выделенном ОС loopback-порту
- **AND** после успешного открытия listener сообщает фактический адрес и порт в stderr

#### Scenario: Explicit IPv6 listener

- **WHEN** в среде с IPv6 сервер запущен с `--listen [::1]:0`
- **THEN** он принимает запросы на выделенном IPv6 loopback-порту и сообщает фактический адрес

### Requirement: Startup failure and command help

The server SHALL reject неверные аргументы с кодом 2 и пояснением в stderr до открытия listener. Ошибка открытия listener или неожиданная ошибка обслуживания SHALL завершать процесс с кодом 1 и диагностикой в stderr. The server SHALL NOT сообщать об успешном открытии listener при ошибке bind. `--help` SHALL показывать параметры и значения по умолчанию, возвращать код 0 и не запускать listener.

#### Scenario: Invalid invocation

- **WHEN** передан неизвестный флаг, позиционный аргумент, пустой `--listen`, адрес без порта, hostname вместо IP literal или порт вне диапазона
- **THEN** процесс завершается с кодом 2 и пояснением ошибки, не открывая listener

#### Scenario: Address already occupied

- **WHEN** другой процесс удерживает указанный адрес и порт
- **THEN** сервер завершается с кодом 1, сообщает ошибку bind и не сообщает об успешном старте
- **AND** существующий listener продолжает работать

#### Scenario: Help without starting

- **WHEN** выполнен запуск с `--help`
- **THEN** вывод описывает `--listen` и его значение по умолчанию, код завершения равен 0 и listener не открывается

### Requirement: Process health endpoint

The server SHALL отвечать на `GET /healthz` кодом 200, `Content-Type: application/json` и JSON-объектом `{"status":"ok"}` без дополнительных полей. Форматирование JSON и завершающий перевод строки не являются частью контракта. Этот ответ SHALL означать только доступность HTTP-процесса и SHALL NOT подтверждать работу БД, агентов, Xray или применение ревизии. Методы кроме GET для точного пути `/healthz` SHALL получать 405 и `Allow: GET`. Неизвестные пути SHALL получать 404.

#### Scenario: Health without product configuration

- **WHEN** работающий сервер без БД и подключённых устройств получает `GET /healthz`
- **THEN** ответ имеет код 200, JSON content type и единственное поле `status` со значением `ok`

#### Scenario: Unsupported method or route

- **WHEN** клиент отправляет HEAD или POST на `/healthz`, либо GET на `/` или `/healthz/`
- **THEN** метод для `/healthz` получает 405 с `Allow: GET`, а неизвестный путь получает 404
- **AND** последующий `GET /healthz` продолжает возвращать успешный ответ

### Requirement: Graceful and bounded termination

The server SHALL начинать остановку при SIGINT или SIGTERM: прекращать приём новых соединений, ожидать завершения уже обслуживаемых запросов не более 5 секунд и освобождать listener. Успешная штатная остановка SHALL давать код 0. Если срок ожидания истёк, сервер SHALL принудительно закрыть оставшиеся соединения, сообщить ошибку и завершиться с кодом 1. Завершение обслуживания вследствие штатной остановки SHALL NOT считаться неожиданной ошибкой.

#### Scenario: Stop an idle server

- **WHEN** запущенный сервер без активных запросов получает SIGINT или SIGTERM
- **THEN** процесс завершается с кодом 0 и его адрес доступен для нового запуска

#### Scenario: Finish an in-flight request

- **WHEN** начинается остановка при уже обслуживаемом запросе, который завершается до истечения 5 секунд
- **THEN** клиент получает завершённый ответ, новые соединения не принимаются и остановка завершается успешно

#### Scenario: Shutdown deadline exceeded

- **WHEN** активный запрос не завершается за 5 секунд после начала остановки
- **THEN** его соединение принудительно закрывается, процесс завершает остановку с кодом 1 и диагностикой об истечении срока

### Requirement: Reproducible checks and bounded compatibility claims

The project SHALL предоставлять воспроизводимые команды проверок HTTP-контракта, ошибок запуска и остановки реального бинарника, а также сборки Linux ARM64 без cgo. Отдельная лабораторная проба SHALL проверять старт, `/healthz`, SIGTERM, код 0 и повторный запуск в Entware aarch64. Она SHALL использовать изолированный контейнер без конфигураций реальных устройств, публикации портов и изменения рабочих volumes стенда. Результат SHALL фиксировать команды, версии, архитектуру и фактический исход; сборка SHALL NOT считаться проверкой запуска, а Docker-проба SHALL NOT считаться подтверждением работы на физическом роутере.

#### Scenario: Entware lifecycle probe

- **WHEN** Linux ARM64-бинарник проверяется в отдельном контейнере Entware aarch64
- **THEN** проверка подтверждает доступность `/healthz`, код 0 после SIGTERM и доступность после нового запуска
- **AND** отчёт указывает фактическую среду и оставшиеся ограничения, а временный контейнер удаляется

#### Scenario: Required verification environment unavailable

- **WHEN** нужный toolchain или среда выполнения отсутствуют и проверку выполнить невозможно
- **THEN** результат явно отмечается как невыполненный, связанные задачи остаются незавершёнными и поддержка среды не заявляется
