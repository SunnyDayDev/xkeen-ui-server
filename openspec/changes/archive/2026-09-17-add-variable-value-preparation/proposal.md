## Why

A08 сохраняет определения переменных, а A06 подставляет готовые значения; между ними отсутствует проверка определений, обязательности и выбор дефолтов. B01 из [обзорной issue #1](https://github.com/SunnyDayDev/xkeen-ui-server/issues/1) и [плана разработки](../../../../docs/roadmap.md) заполняет этот промежуток после завершённых [A06, #7](https://github.com/SunnyDayDev/xkeen-ui-server/issues/7) и [A08, #9](https://github.com/SunnyDayDev/xkeen-ui-server/issues/9).

Реализация отслеживается в [B01, issue #14](https://github.com/SunnyDayDev/xkeen-ui-server/issues/14), выделенной из #1 перед началом кода. Реализация завершена, issue #14 закрыта; фактические результаты — в [отчёте](verification.md). Change архивирован 2026-09-17 после проверенной синхронизации дельты.

## What Changes

- Добавить отдельную операцию подготовки значений одного элемента: определения и персональные JSON-значения преобразуются в полный набор выбранных значений либо ошибки без частичного результата.
- Проверять точные имена, пять допустимых типов, дубликаты определений и значения для необъявленных имён, включая неиспользуемые определения.
- Отсутствующее или пустое после Unicode White_Space персональное значение заменять заполненным дефолтом; если его нет, возвращать `missing_value`. Непустые строки сохранять без обрезки; типы не преобразовывать.
- Проверять каждый заданный дефолт независимо от персонального значения; неверный дефолт нельзя скрыть персональным значением, неверное персональное значение — дефолтом.
- По согласованному уточнению объёма проверять `null` в персональных значениях и дефолтах уже в B01, рекурсивно, с `null_not_allowed`. `null` в сыром шаблоне и оставшийся синтаксис ссылок остаются B02.
- Сохранить независимость от редактирования: операция не создаёт определения, не меняет сохранённый элемент и не делает успех подготовки подтверждением готовности полной конфигурации.

## Capabilities

### New Capabilities

Нет новых capability-путей.

### Modified Capabilities

- `configuration-variables`: добавить контракт отдельной подготовки значений, применяющей согласованные правила A05 к определениям, персональным значениям и дефолтам до подстановки. Существующие требования полной сборки и контракт низкоуровневой A06 сохраняются.

## Impact

- Будущая реализация затронет `internal/configuration` и его тесты, используя существующие `VariableDefinition`, `Issue` и строгий JSON-разбор. Новые внешние зависимости, БД и работающий роутер не нужны.
- Сохранение A08 продолжит допускать структурно корректные черновики с незаполненностью, `null` и семантически ошибочными определениями. `SubstituteValues` останется операцией подстановки подготовленных значений.
- При реализации обновляются статус и границы B01/B02 в `docs/configuration-model.md`, `docs/roadmap.md`, README и связанных описаниях текущего состояния. На этапе предложения создавались только артефакты change. При реализации обновлены код, тесты и документация; основные specs дополнены при синхронизации перед архивированием 2026-09-17.
- Вне объёма: сырой шаблон и его полный синтаксис, полная сборка/публикация, UI и макеты, HTTP/API, хранилище, наследование, UUID и проекция метки Xray. UI-проверка Pencil этому изменению не требуется.
- Задачи разделены на небольшие циклы проверки определений, выбора значений, запрета `null`, диагностики и интеграции; весь объём не обещается как одна сессия на 60–90 минут.
