# Приёмка контролируемого перезапуска E03

[Issue #83](https://github.com/SunnyDayDev/xkeen-ui-server/issues/83) проверяет установку полной текущей ревизии для выделенного прямого Xray. Supervisor использует предшественников E01/E02 для долговременного намерения, доверенной рабочей базы и изолированной проверки кандидата.

## Проверки

| Случай | Свидетельство |
| --- | --- |
| Отсутствие координатора, журнала, HTTPS-адаптера и привязанного сокета | Первые целевые тесты зафиксировали Red для отсутствующих контрактов. Green прошёл под детектором гонок после их реализации. |
| Смена желаемой ревизии или отзыв между чтениями | Два запроса через реальный TLS и локальный переход во время проверки. Рабочих эффектов и устойчивого намерения нет. Отдельно проверены неподходящий сертификат, чужой ID и локально подставленный ETag. |
| Точный резерв и долговечность | Регрессия JSON воспроизвела Red для пробелов, перевода строки и `<`. После перехода к lossless-представлению новый процесс считывает прежнюю и целевую конфигурации без кешей D05/E02. Внедрённая ошибка fsync до rename сохраняет прежнюю запись. После rename требуется повторный барьер перед чтением. Отмена до намерения оставляет каталог прежним, после намерения сохраняет доказательства. |
| Два последовательных применения | Entware ARM64 запускает настоящий foreground-агент с отдельным UID, root supervisor, точный Xray 26.3.27 с отдельным runtime UID/GID и серверные обработчики с TLS и SQLite. Ревизия 2 блокирует проверочную цель и добавляет точный `06_extra.json` с режимом 0640. Следующая публикация будит D07, ревизия 3 удаляет дополнительный файл и снова пропускает цель. Положительный контроль и посторонний файл сохраняются. Проверка связывает listening-сокет SOCKS с аттестованным PID и отдельно отклоняет socket другого процесса. Повторный запуск агента с текущей ревизией не меняет PID и журнал. |
| Доверенная граница старта | Обычный запуск той же подтверждённой базы выдаёт аттестацию нового процесса с прежним ID попытки. Квитанция в изменяемом агентом состоянии не влияет на запуск. Подмена inode каталога при совпадающем пути и байтах отклоняется. Незавершённое намерение и частично заменённый каталог блокируют запуск; новый владелец читает сохранённые доказательства. |

## Воспроизведение

Из корня репозитория в среде Go 1.27.1 с локальным образом [стенда Entware](../../../../lab/README.md):

```sh
go test -race ./internal/agent/restart ./internal/agent/localvalidation
XKEEN_LAB_APPLICATION=1 sh lab/check-agent-preparation.sh
```

Команда поднимает одноразовый контейнер Linux ARM64 без внешней сети, монтирует тестовые бинарники только для чтения и использует одноразовый рабочий каталог. Она использует отдельный entrypoint. Автозапуск XKeen и внешний вызов `S05xkeen` отсутствуют в поддерживаемом режиме, все штатные старты идут через supervisor с эксклюзивным журналом. Для проверок чужого UID добавлен `CAP_SYS_PTRACE`, а `no_new_privs` обязателен. Xray запускается с проверенного дескриптора под ограниченным UID/GID.

Сквозной сценарий дополнил проверки после реализации портов. Независимое ревью повторило нативные race-тесты и Entware-сценарий. Полный нативный набор Go, детектор гонок, vet и строгая проверка OpenSpec выполнены. Подтверждение серверу остаётся отдельной задачей E08. В зазоре между созданием процесса и долговременной записью его идентичности неизвестный процесс блокирует новый штатный старт. Автоматический откат и разрешение незавершённых попыток относятся к E04/E05. Физические роутеры и потеря питания вне проверки.
