## ADDED Requirements

### Requirement: The administrator can append an element to an existing template draft

После полного авторизованного чтения непустого шаблона администратор SHALL иметь отдельное действие создания общего элемента в поддерживаемой секции. Явное сохранение SHALL создавать новый UUIDv4 и хранить точный исходный JSON с определениями по A08. Сохранение SHALL проверять веб-сессию и ожидаемую версию в транзакции C03.

#### Scenario: Another routing rule is appended
- **WHEN** администратор выбирает секцию правил и явно сохраняет допустимый исходный JSON
- **THEN** новый элемент появляется в той же секции и становится последним в полном общем порядке
- **AND** новый UUID открывается для редактирования, а прежние UUID, порядок, содержимое и определения сохраняются

#### Scenario: Additional groups can be populated
- **WHEN** заполненный шаблон получает первый элемент в другой поддерживаемой секции
- **THEN** новый элемент сохраняется вместе с существующими секциями и не меняет принятую или желаемые ревизии

#### Scenario: A singleton section already has an element
- **WHEN** действие создания запрошено для занятой секции единичной кратности B12
- **THEN** запись отклоняется без изменений, а текущий элемент остаётся доступен для редактирования

#### Scenario: An append loses a race or generates a colliding UUID
- **WHEN** версия изменилась, полномочия утрачены или новый UUID совпал с существующим в шаблоне
- **THEN** добавление не создаёт частичной записи и редактор оставляет буфер для явного продолжения

#### Scenario: A save outcome is unknown or the editor is canceled
- **WHEN** серверный ответ потерян либо оператор закрыл буфер до отправки
- **THEN** интерфейс не отправляет новую команду автоматически и для неизвестного исхода предлагает перечитать сохранённое состояние
