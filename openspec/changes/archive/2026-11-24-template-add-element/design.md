## Context

F07 различает пустой шаблон и недоступный снимок; CreateFirstElement требует, чтобы весь черновик был пуст. Сохранение существующего элемента определяется его UUID. F08 меняет определения уже сохранённого элемента.

## Decisions

1. На подтверждённом непустом снимке редактор открывает новый буфер отдельным действием. Видимый переход не заменяет открытые несохранённые данные без явного решения. Использовать текущий редактор точного текста, секции Xray из F07 и маршрут выбранного элемента после успешной записи. Существующий протокол первого сохранения сохраняет прежний смысл.
2. Секции с набором принимают дополнительные элементы. Уже занятые секции единичной кратности B12 остаются доступны через редактирование; прямой запрос на вторую запись получает безопасный отказ. Неразрешённые ссылки, произвольные поля JSON, значимые числа и пробелы по-прежнему допустимы в черновике по A08.
3. Подготовить независимый кандидат из полного авторизованного снимка. Новый UUIDv4 проверяется на коллизию среди всех секций. Новый элемент получает определения A08; существующие записи, включая прежние неполные, копируются без повторной подготовки. Существующие секции сохраняются; при добавлении правила его UUID дописывается в полный общий порядок без перестановки остальных.
4. Переиспользовать C03 replace и F03 guard. Подготовка выполняется до короткой транзакции. Одно условное сохранение повторно проверяет поколение сессии и ожидаемую версию. Неопределённый ответ требует чтения состояния перед новым явным действием; пакетная запись и автоматический повтор отсутствуют.
5. Через Pencil обновить редактор F07/F08. Проверить широкий и узкий экран, запуск добавления, точный JSON, доступные секции, ошибку и конфликт, успешное открытие нового UUID. Проверить настоящий браузер с HTTPS и SQLite.

## Risks / Trade-offs

Конфликт сохраняет буфер, потому что другой оператор мог изменить кратность и порядок. После явного перечитывания выбор секции оценивается по новой версии; прежнюю команду редактор не переотправляет.
