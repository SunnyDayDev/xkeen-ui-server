## Context

F02 #74 определяет единственного локального администратора, источник первоначального секрета, прямой TLS и отдельную браузерную область. F03 добавляет серверную операцию. F04 использует её состояние и реализует отображение.

## Decisions

1. **Локальный вход владельца.** Подкоманды `xkeen-ui-server admin setup` и `admin reset` принимают обычный путь SQLite через `--db-path` и опциональный `--password-file`. Без файла нужен интерактивный терминал с отключённым эхом и подтверждением. Файл открывается только для чтения, проверяются обычный тип записи, отсутствие ссылки/дополнительных ссылок, владелец и права 0600. Допускается обычное завершающее LF или CRLF. Приватный файл подготовлен оператором и сохраняется. Пароль не проходит через аргументы, окружение, печатаемые ошибки или API настройки. Первоначальная команда создаёт запись единожды. Сброс требует существующего администратора и меняет проверку и поколение вместе с отзывом старых сессий.
2. **Проверочное значение и бюджет.** Проверять весь ввод без обрезки или обязательных классов символов. Проектный минимум 15 символов и максимум 1024 байта UTF-8. Используется стандартный Argon2id с уникальной случайной солью и версионированными затратами. Ориентир RFC для ограниченной памяти — 64 МиБ, три прохода, четыре линии. Измерить на Entware ARM64 и указать фактическое решение. Только одна проверка пароля на экземпляр одновременно и короткий глобальный лимит попыток. Ожидание тяжёлого вычисления не удерживает SQLite writer-транзакцию. Генерация администратора повторно проверяется при выдаче сессии, поэтому ранее проверенный пароль не обходит конкурентный сброс. [RFC 9106](https://www.rfc-editor.org/rfc/rfc9106.html), [ориентир длины пароля](https://pages.nist.gov/800-63-4/sp800-63b.html).
3. **Серверная сессия.** Передаваемый случайный токен содержит 32 случайных байта, SQLite хранит его SHA-256 digest, поколение, абсолютный срок и время последнего явного действия. Сроки 30 минут без действия и 12 часов от входа. Принятый выход отзывает только переданную сессию. После входа выдаётся новая host-only cookie `__Host-xkeen_session` с Path=/, Secure, HttpOnly и SameSite=Lax. Если тот же браузер прислал действующую прежнюю cookie при входе, выдача заменяет её серверную запись. Сброс отзывает все. Сроки сверяются по серверным часам при каждом допуске. Закрытая вкладка и фоновый просмотр не продлевают срок. Токен CSRF выводится из ключа cookie с отдельным HMAC-контекстом и возвращается авторизованным ответом одного origin. Он не предоставляет права без соответствующей сессии.
4. **Маршруты.** Явный `--web-origin` активирует F03 только с настроенной парой TLS. Защищённые маршруты принимают реальный TLS и настроенный Host; forwarded-заголовки не удостоверяют канал. `GET /ui/v1/session` возвращает `setup_required`, `signed_out` либо `active` и CSRF при активной сессии. `POST /ui/v1/login` принимает строгий небольшой JSON с паролем, метод и Origin обязательны. `POST /ui/v1/logout` и `POST /ui/v1/session/activity` требуют активной сессии, Origin и `X-CSRF-Token`. Последний маршрут отражает явное действие пользователя. Фоновые опросы F04 используют чтение состояния без продления. Сессионные изменения подтверждают срок и поколение в writer-транзакции. Будущие изменяющие UI-операции используют ту же повторную проверку в момент записи. Непригодный пароль, исчерпание попыток, отсутствие настройки, недоступность, прекращение сессии и CSRF-отказ кодируются фиксированными безопасными результатами. Ответы без кэширования и без разрешения CORS.
5. **Границы кода.** Приложение владеет сроками и поколением, адаптер SQLite — атомарными переходами, HTTP — TLS/Origin, cookie и форматами. Команды установки используют то же приложение и таблицы. Маршруты агента и внешний API не получают браузерные полномочия. F04 рендерит ответ и реализует удержание открытого буфера, F03 не вводит UI-статические данные, формы, навигацию и сохранение других сущностей.

## Проверенный макет

Экран 17 содержит вход с фокусом пароля, отправку, неверный пароль, ограничение попыток, недоступный сервер и завершённый выход. Экран 18 показывает локальную настройку через терминал или приватный файл без захвата установки. Экран 19 показывает истечение с несохранённым буфером, узкий экран и восстановленное редактирование с ручным сохранением. Повторно использованы FormField/Input/Button. До кода проверены рендеры и независимое ревью. F04 отвечает за клавиатурное поведение, password manager, HTML и браузерные тесты.

## Risks / Trade-offs

- Тяжёлая проверка пароля ограничивается одним заданием, чтобы не вытеснять агентский канал на Entware. Подтвердить измерением при действующем HTTPS и SQLite.
- Процессное ограничение повторов дополняет защищённый доступ, но не гарантирует доступность входа при постоянном потоке запросов. Изменение срока сессий или модели обхода требует отдельного контракта.
