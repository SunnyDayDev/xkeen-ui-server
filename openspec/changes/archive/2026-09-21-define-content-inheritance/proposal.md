## Why

B03 из [плана разработки, issue #1](https://github.com/SunnyDayDev/xkeen-ui-server/issues/1) определяет наследование содержимого перед реализацией B04–B06. После [A07 #8](https://github.com/SunnyDayDev/xkeen-ui-server/issues/8) и [B02 #16](https://github.com/SunnyDayDev/xkeen-ui-server/issues/16) есть контракт идентичности и сборка переменных одного элемента, но ещё не определено, как выбирать содержимое для роутера и сохранять персональные данные при смене режима.

Задача: [B03, issue #18](https://github.com/SunnyDayDev/xkeen-ui-server/issues/18), связанная с обзорной #1 и строкой B03 в [roadmap](../../../../docs/roadmap.md). На этапе proposal отдельной issue не было; она создана при выполнении change. Это контракт будущего поведения, а не реализация B04–B06.

## What Changes

- Описываем наследование актуального содержимого и определений шаблона, с персональными значениями либо без них.
- Закрепляем полную замену готовым собственным JSON без подмешивания полей, определений и значений шаблона; внешний UUID сохраняется.
- Сохраняем персональные значения при переходе к собственному JSON; в этом режиме они не участвуют в сборке. При возврате проверяем их по актуальным определениям.
- Различаем переключение режима, полный сброс переопределения и отмену несохранённой правки. Полный сброс удаляет собственный JSON и персональные значения блока; недостающие обязательные значения после сброса дают ошибку сборки.
- Описываем самостоятельный локальный элемент и сохраняемое исключение общего элемента по ссылке на шаблон и UUID.
- Сохраняем независимость содержимого от порядка и отделяем выбор источника от проверки готовности конфигурации к применению.

## Capabilities

### New Capabilities

- `configuration-content-inheritance`: выбор общего или собственного содержимого, сохранение значений при смене режима, полный сброс, локальные элементы и исключения общих элементов.

### Modified Capabilities

Нет. Новая capability использует правила `configuration-element-identity`, `configuration-element-storage` и `configuration-variables`, не меняя самостоятельные операции A08/B01/B02. Политика проверки собственного JSON не расширяет область запрета `null` из контракта переменных.

## Impact

В текущем change создаётся контракт будущего продуктового поведения, поэтому `skip_specs` не используется. Код, тесты функций, форматы HTTP/БД, зависимости Go, основной набор specs и макет не меняются на этапе proposal.

Завершение B03 включает ревью, согласование предметных документов и передачу сценариев в отдельные реализации B04–B06. Их будущая доменная логика относится к `internal/configuration`; `elementjson` остаётся адаптером записи одного элемента, а не форматом состояния роутера.

Порядок B07/B08, зависимости B09–B11, проекция `_xkeenUiId` и каталог B12, хранение C04, публикация, агент и UI не входят в B03. Удаление исходного элемента из самого шаблона, смена профиля, сохранение неактивного черновика собственного JSON и политика `null` для готовой полной замены остаются явно отделёнными вопросами последующих контрактов. B03 не обещает готовность всего сборщика или интерфейса.
