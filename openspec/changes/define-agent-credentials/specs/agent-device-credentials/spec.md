## Purpose

Связать агент с подготовленным роутером, ограничить право доступа одним устройством и сохранить управляемость регистрации при повторах, замене и отзыве ключа.

## ADDED Requirements

### Requirement: Enrollment is issued for one prepared router

Первичное приглашение SHALL выдаваться отдельной авторизованной операцией для конкретного роутера после подтверждения первого назначения и принятия первого проверенного каталога. Оно SHALL иметь ограниченный срок и разрешать только привязку одного рабочего ключа этого роутера через канал D01.

#### Scenario: An unready router cannot be enrolled
- **WHEN** обязательные значения не заполнены либо первое назначение с проверенной желаемой ревизией ещё не принято
- **THEN** первое приглашение не выдаётся, а редактируемые данные сохраняются

#### Scenario: A pending invitation is scoped and expires
- **WHEN** приглашение просрочено, отозвано, заменено либо использовано для другой цели или роутера
- **THEN** запрос отклоняется без создания ключа и без раскрытия данных устройства

### Requirement: Enrollment binds one credential atomically and replays safely

Новый рабочий ключ SHALL сохраняться агентом перед отправкой запроса. Сервер SHALL погашать приглашение и привязывать рабочий ключ атомарно. Повтор SHALL возвращать только результат прежней привязки для того же приглашения и того же кандидата, пока приглашение допускает повтор и привязка всё ещё действует.

#### Scenario: Lost response does not create another device
- **WHEN** сервер зафиксировал первое подключение, но ответ потерялся, а агент перезапустился
- **THEN** сохранённый рабочий ключ подтверждает действие привязки или агент повторяет точный запрос
- **AND** ID устройства и принятые настройки остаются прежними, второй ключ не создаётся

#### Scenario: Competing candidates cannot both redeem one invitation
- **WHEN** с одним действительным приглашением одновременно переданы разные кандидаты рабочего ключа
- **THEN** не более одного кандидата получает рабочие полномочия
- **AND** попытка с другим кандидатом не заменяет победивший ключ

#### Scenario: Exact retry cannot revive a previous credential
- **WHEN** истёк срок повтора, ключ был заменён или полномочия отозваны
- **THEN** повтор погашения не восстанавливает прежнее право и не выдаёт действующий секрет

### Requirement: An agent key authorizes only its device synchronization

Сервер SHALL определять область роутера по действующему ключу. Рабочий ключ SHALL разрешать только операции D01 своего устройства. Ключ, приглашение, учётные данные UI и полномочия внешнего API SHALL иметь отдельные области. Сервер SHALL возвращать безопасные отказы без секрета и чужих данных.

#### Scenario: One agent cannot use another device or management operations
- **WHEN** действующим ключом запрашиваются ревизия другого роутера, управление шаблоном или выпуск приглашения
- **THEN** операция отклоняется, состояние другого устройства и данные управления остаются прежними

#### Scenario: Management switches do not alter agent access
- **WHEN** внешний API выключен либо работает без авторизации
- **THEN** действующий агентский ключ работает в своём канале
- **AND** доступ к внешнему API сам по себе не даёт полномочий D01 или D02

### Requirement: Explicit replacement and revocation control the credential lifecycle

Повторная установка с сохранённым действующим ключом SHALL сохранять регистрацию. Управляемая замена SHALL атомарно активировать новый ключ и прекратить действие старого. Отзыв SHALL прекращать действие ключа и ранее выданных приглашений без удаления технической идентичности роутера.

#### Scenario: Reinstallation with persisted state preserves identity
- **WHEN** переустановка сохранила действующий ключ и состояние отчётов агента
- **THEN** агент подключается как тот же роутер без нового приглашения и без обнуления порядка отчётов

#### Scenario: Loss of the stored key requires authorized recovery
- **WHEN** рабочий ключ утрачен
- **THEN** сервер разрешает восстановление только после явного выпуска полномочия в области прежнего роутера
- **AND** после замены порядок новых отчётов учитывает последний принятый курсор прежней регистрации

#### Scenario: Revocation stops pending authorization effects
- **WHEN** рабочий ключ отозван по явной команде
- **THEN** новые запросы отклоняются, а ожидающий запрос не получает последующий сигнал по устаревшим полномочиям
- **AND** ранее выпущенное приглашение не может автоматически восстановить право

#### Scenario: Removing a row from the device list is not a credential operation
- **WHEN** устройство убирают из видимого списка по правилам G04/G05
- **THEN** действующий ключ и технический ID сохраняются
- **AND** следующий допустимый контакт может восстановить видимость без выдачи нового ключа

### Requirement: Credential material is kept confidential

Сервер SHALL хранить проверяемое представление ключей и приглашений, без доступной для повторной выдачи открытой копии. Агент SHALL сохранять нужный секрет локально с доступом службы. Передача SHALL выполняться только по проверенному TLS. Диагностика, URL и обычные журналы SHALL исключать секреты.

#### Scenario: Verification storage does not return the original secret
- **WHEN** оператор читает метаданные действующего ключа либо повторяет выпуск команды просмотра
- **THEN** доступна безопасная информация о записи
- **AND** восстановление доступа осуществляется заменой, исходный рабочий ключ не раскрывается
