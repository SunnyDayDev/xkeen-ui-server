## Purpose

Браузер готовит первое назначение и первую желаемую ревизию проверенного роутера.

## ADDED Requirements

### Requirement: First router preparation requires explicit verified confirmation

Браузер SHALL требовать выбранный шаблон, действительные персональные значения и явное подтверждение. Сервер SHALL атомарно фиксировать первое назначение и проверенную желаемую ревизию. Приглашение SHALL требовать отдельной команды.

#### Scenario: Invalid or incomplete input preserves the preparation buffer
- **WHEN** отсутствует обязательное значение, каталог отклонён, Xray недоступен либо исходный снимок изменился
- **THEN** назначение и желаемая ревизия не появляются, исправляемый буфер остаётся открытым

#### Scenario: Successful initial confirmation opens enrollment
- **WHEN** владелец явно подтверждает проверенный каталог и текущий снимок при действующей сессии
- **THEN** появляется подготовленный роутер со стабильным ID, и доступен переход к отдельному подключению

#### Scenario: An accepted source takes precedence over edits

- **WHEN** выбранный шаблон имеет принятый снимок и отдельно сохранённый более новый черновик
- **THEN** форма и проверяемый каталог используют принятый снимок
- **AND** более новый черновик не принимается при подготовке роутера

#### Scenario: A draft is accepted for the first time

- **WHEN** принятого снимка и действующих назначений нет и владелец подтверждает актуальный черновик
- **THEN** принятый снимок, первое назначение и первая ревизия сохраняются одним эффектом

#### Scenario: Personal input is scoped to an element

- **WHEN** разные UUID в шаблоне имеют одинаковое имя переменной
- **THEN** значение и допустимый дефолт определяются отдельно для каждого UUID
- **AND** тип и точность исходного JSON сохраняются, а ошибка не раскрывает введённые данные

#### Scenario: The authorizing session ends during validation

- **WHEN** отзыв или истечение браузерной сессии опережает фиксацию проверенного каталога
- **THEN** сервер сообщает об утрате доступа и не сохраняет назначение или ревизию
- **AND** повторный вход возвращает буфер без автоматической отправки

#### Scenario: Confirmation is unavailable without an isolated verifier

- **WHEN** проверяющий Xray не настроен либо недоступен
- **THEN** подготовка сообщает о недоступности и не фиксирует каталог

#### Scenario: A lost response does not produce a second router

- **WHEN** подтверждение с уже выданным ID получило неопределённый ответ
- **THEN** владелец может перечитать результат по прежнему ID
- **AND** браузер не создаёт новый ID и не повторяет подтверждение автоматически
