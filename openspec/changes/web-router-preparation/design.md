## Context

F09 добавляет реальную подготовку из браузера. F05 предоставляет список шаблонов. C04 умеет хранить имя и персональный снимок, C06 атомарно фиксирует первое назначение и первую желаемую ревизию после проверки C06.2. Серверный listener пока подключает только чтение желаемых ревизий.

## Decisions

1. **Веб-путь.** Из обзора открыть точный маршрут /ui/routers/connect. Чтение /ui/v1/routers/prepare с одним templateId использует браузерную сессию и один SQLite snapshot. Подходящий уже принятый снимок имеет приоритет. Черновик выбирается только для поддерживаемого первого принятия. В форме видны ID шаблона, вид источника и точная версия. Снимок для формы отдаёт определения в области UUID элемента, без полного исходника элемента. При изменении шаблона смена источника заметна.
2. **Идентичность и значения.** При открытии операции сервер выделяет случайный UUIDv4 будущего роутера без записи. Вкладка хранит его вместе с буфером и сохраняет при смене шаблона, повторном входе и неопределённом исходе. Имя роутера занимает существующее поле Name активного C04 снимка, миграция не нужна. Одноимённые определения у разных UUID независимы. Явные значения передаются JSON-текстом и проверяются B01 с определениями, типами и дефолтами выбранного снимка. Незаполненное поле означает наследовать допустимый дефолт либо требует исправления. JavaScript не превращает числа во float. Контракт исключает чуждые UUID, лишние и повторные определения.
3. **Подтверждение и гонки.** POST /ui/v1/routers/prepare явно подтверждает имя, ID, выбранный источник, версию и персональные значения. HTTPS origin, F03 cookie и CSRF проверяются до обработки. Кандидат строится в режиме SourceCandidate, ConfirmAccepted либо ConfirmInitial C06, без отдельной записи C04. Xray работает вне SQLite writer. Внутри общего writer проверяются живое поколение сессии, сроки и все ожидания C06. Только успешный commit добавляет активный снимок и желаемую ревизию и вызывает уже существующий после-коммитный сигнал. После таймаута защищённое чтение с одним routerId показывает фактически зафиксированный результат или его отсутствие. Вкладка не повторяет POST сама.
4. **Валидатор.** Проводка применяет существующую C06.2 проверку в том же закреплённом профиле. Оператор задаёт один из режимов: абсолютный защищённый Unix socket локального worker через `--validator-socket` либо явно заданный HTTPS origin выделенного worker через `--validator-origin` с отдельной CA `--validator-ca` и клиентской mTLS парой `--validator-client-cert` и `--validator-client-key`. Противоречивые и неполные настройки обнаруживаются до HTTP. Нет настройки либо доступного исполнителя — подтверждение завершается безопасной недоступностью, другие браузерные маршруты работают. Отклонённый каталог, ошибки входа и истёкшая сессия дают различимые безопасные ответы без содержимого конфига и ключей.
5. **Пользовательские состояния.** Экран 09 с переходом из 00, состояния выбора, пустого списка, наследуемого и обязательного поля, отправки, отказа, конфликта, подтверждения и узкая компоновка. При отказе или повторном входе буфер остаётся в той же вкладке без автоотправки. Итоговый экран даёт стабильный ID и сохранённую первую ревизию. F10 использует фактический подготовленный роутер и предоставит отдельное действие выдачи приглашения.

## Risks / Trade-offs

- Без внешней проверки невозможна фиксация. Лабораторный сквозной тест использует заранее изолированный C06.2 исполнитель, а не физический роутер.
- Сетевой таймаут не подтверждает результат. Чтение по уже выделенному ID восстанавливает состояние без новой публикации. Опоздавшие ответы после смены источника, маршрута или сессии игнорируются.
- Отзыв сессии за время Xray может остановить фиксацию, поэтому чтения перед проверкой не считаются окончательным авторизационным решением.
