## Context

G02 связывает результат с точными версиями, персональными входами, актуальной применимостью и результатом серверной проверки Xray. F20 допускает открытый режим при явной настройке. Реквизиты управления доступом, регистрации и устройств не входят в ответы операции.

## Decisions

1. Один ресурс `/api/v1/routers/profile-switch?routerId=…&templateId=…`. GET возвращает действующий ID, цель, состояние выбора и только метаданные запрашиваемых переменных. После потери ответа текущая цель может уже быть активной: GET возвращает этот факт без подготовки повторной смены. Идентификаторы запрашиваются ровно один раз. Пути, имена файлов, режимы валидации и внутренние полномочия не принимаются от клиента.
2. POST со строгим JSON и отдельным значением action для preview или confirm. Preview принимает явные изменения целевых переменных, показывает проверенные последствия (первый выбор/восстановление, изменение каталога и желаемой ревизии), выдаёт ограниченную по времени квитанцию. Confirm требует ту же цель, те же точные изменения и квитанцию. Для stale/expiry требуется новый preview. Отмена до confirm не меняет состояние. Успех показывает серверное назначение и желаемый номер. Состояние применения определяется E08.
3. Использовать принятый адаптер допуска F20 и сервис G02. Подписанная квитанция отдельной аудитории связывает доказательство G02, permission generation и срок. Секреты и присланные значения не включаются в тело квитанции и не появляются в диагностике. Проверить допустимость только реального Origin на мутациях по F19, HTTPS, no-store, скрытые роутеры, пределы тела, точные ID и строгий JSON. G02 получает повторную проверку текущего F20, видимости роутера, срока и точного состояния в writer. Поздняя проверка защищает также выдачу preview. Данные C04 и принятые файлы сервер использует внутри процесса. Проверка Xray и проверка применимости обхода обязательны по G02.
4. Точные Go-типы и отображение кодов ошибок фиксируются после интеграции G02. Числа версий в JSON передаются каноническими десятичными строками. Конфликт или потеря ответа не вызывают автоматического повтора confirm.

## Verification

Настоящий потребитель использует обычный HTTPS listener и SQLite, проверяет тело каждого ответа с синтетическими маркерами и сравнивает хранимый desired, назначения, оба персональных снимка и историю до и после ошибок. Отзыв или ротация F20 и истечение проверяются между работой валидатора и writer.
