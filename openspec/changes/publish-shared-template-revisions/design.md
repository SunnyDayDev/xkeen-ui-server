## Context

C05 задаёт атомарное принятие общего шаблона. C06.1 готовит независимый B12-каталог и пересчитывает персональный порядок. C06.2 проверяет точные файлы закреплённым Xray. C06.3 хранит неизменяемые общие снимки, действующие настройки и точные желаемые ревизии отдельно от черновиков. C06.4 добавляет одиночную оркестрацию. Перед реализацией сверяем фактические сигнатуры принятой C06.

## Decisions

1. **Одна явная команда шаблона.** Команда передаёт точный ID, ожидаемую версию редактируемого шаблона, ожидаемую версию принятого снимка (0 означает отсутствие) и явно выбирает сохранённый источник либо полный кандидат общей правки. Сохранённая версия принимается без дополнительного повышения версии C03. Переданный кандидат получает расчётный номер следующей версии и проходит ту же подготовку черновика A08/C03 до подготовки каталогов. Переиспользовать чистую часть подготовки C03/A08, выделив её из внутренней реализации C03 при необходимости. При подготовке не вызывать пишущий `Replace`: для общей правки запись черновика принадлежит пакетной транзакции. При успешной записи кандидат и принятый снимок совпадают с использованными данными и версией. Ошибка, конфликт или исчерпание версии не изменяют черновик. Если сохранение подтверждает ранее показанный предпросмотр, команда также передаёт точное наблюдавшееся множество роутеров и токены их активных состояний и ревизий. Перед подготовкой сверить их с полученным снимком. Внутренний вызов без отдельного предпросмотра привязывается к состоянию, согласованно прочитанному в начале команды. Для уже принятой той же версии повтор использует прежний неизменяемый снимок, не переписывая его.
2. **Порт группового снимка.** Прикладной пакет определяет отдельный узкий порт с `ReadTemplateGroup` и `CommitTemplateGroup` либо эквивалентными именами по принятой C06. Групповое чтение возвращает шаблон и принятый снимок, а также полные действующие данные, основание порядка, текущие ревизии и токены всех участников. В SQLite один короткий read transaction получает версии шаблона и подтверждённые ID через индекс `active_router_publications(template_id)`. Прочитанный набор упорядочивается точно по ID. Несогласованная хранимая запись даёт ошибку до вызова внешнего процесса. Черновики C04, состояние связи и агентский статус не читаются. Для ожидающего A→B источником остаётся действующая запись A.
3. **Подготовка пакета вне блокировки записи.** Для каждого участника передать выбранный общий снимок, активные настройки и основу в C06.1. B08 пересчитывает полный порядок до применения исключений и отключений. Неизвестную базу и устаревшие ссылки нельзя скрыть, а отключённый или полностью заменённый элемент не оправдывает пропуск участника. Переиспользовать проверяющий порт C06.2 и чистое сопоставление проверенных каталогов C06.4. Проверяется каждый готовый каталог перед успешным commit, включая равный прежнему. При обнаружении ошибки команда может прекратить дальнейшую подготовку и возвращает безопасную ошибку с ID и стадией. Даже если файлы равны, новое основание и полный порядок входят в план. При нуле участников структурная подготовка общего шаблона остаётся обязательной, каталога и запуска Xray нет. Отсутствие валидатора либо безопасной среды его запуска не блокирует команду без участников.
4. **Одна транзакция на шаблон.** `CommitTemplateGroup` проверяет согласованность ID и уникальность планов, заново читает полный список назначений в write transaction, сравнивает его с ожиданием и отклоняет несовпадение. Затем проверяет обе общие версии, поколение активного снимка и желаемую ревизию каждого роутера. Пустое множество сверяется так же. Все сравнения и записи выполняются в одной транзакции с ранним захватом блокировки SQLite. При допустимых ожиданиях можно сохранить новую версию черновика и добавить принятую копию, обновить активные порядки и основания, добавить только отличающиеся желаемые ревизии. Для копии существующей версии использовать именно проверенную строку C03. Переиспользовать кодеки, узкие функции проверки и записи C06.3, принимающие текущую транзакцию. Одиночный `Store.Commit` не вызывается, поскольку он сам владеет транзакцией. Отказ любого SQL-шага откатывает всё. Ожидающий C04-черновик не участвует в записи и не блокирует её при независимой правке.
5. **Результат и доставка.** Успех после commit возвращает принятый ID и версию шаблона, затем стабильный список (ID роутера, номер желаемой ревизии, изменился ли каталог). Формат C06.3 и локальная последовательность номера сохраняются. События доставки определяет D01, а источником сигнала являются только успешно зафиксированные изменившиеся ревизии. Частичных успешных результатов и сигналов у отклонённого пакета нет.

## Risks / Trade-offs

- Полный пакет держит снимки и точные файлы до записи. Для первой версии ограничить параллелизм подготовки, чтобы не умножать использование Xray и памяти на Entware. Скрыто разбивать пакет на независимые commits нельзя.
- Блокировка записи держится только во время повторной сверки и записи, поэтому между чтением и записью возможен конфликт. Проверка полного множества обнаруживает фантомы, а токены участников — изменение записей сохранившихся членов. Устаревший запрос не перепускается автоматически.
- Новая миграция не предполагается: индекс, неизменяемые записи и отдельное активное состояние уже есть в C06.3. Потребность в изменении схемы подтверждается тестом и пересматривается отдельно. Смена профиля G01/G02 не эмулируется необъявленной записью.

## Migration Plan

C07.1 добавляет согласованное групповое чтение/фиксацию поверх схемы C06.3 после принятия C06. C07.2 добавляет типизированную команду и проверку реальным валидатором. Сосуществование одиночной и групповой операций проверяется независимыми подключениями к одной базе, отдельно для изменения релевантных токенов, независимого черновика и появления первого назначения.
