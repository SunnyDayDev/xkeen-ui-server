# entware-installation Specification

## Purpose

Определить безопасную установку, обслуживание и удаление компонентов проекта на Entware ARM64 из конкретного выпуска или из проверочного зеркала.

## Requirements

### Requirement: Installation is bound to an explicitly trusted release

Установщик SHALL получать явно выбранную версию, доверенную сумму манифеста и предсказуемые имена файлов для выбранной роли. Перед изменением рабочей установки SHALL проверяться полное скачивание и целостность каждого необходимого файла.

#### Scenario: An invalid or incomplete download preserves the installation

- **WHEN** версия недоступна, манифест не совпадает с доверенной суммой или один из файлов не подтверждён
- **THEN** действующие файлы, служба и данные сохраняются без изменений

### Requirement: Installation explicitly binds service role and ownership

Для агента транспорта, агента с применением и центрального сервера SHALL явно определяться рабочая роль, полномочия, состояние и поддерживаемая среда. Компонент SHALL стартовать через закреплённый путь init.d после локальных проверок.

#### Scenario: Unavailable runtime capability blocks application

- **WHEN** выбранный профиль применения не может доказать требуемые возможности ядра и владельцев рабочего процесса
- **THEN** установщик блокирует этот профиль до смены действующей установки

#### Scenario: A fresh server preserves its administrator setup boundary

- **WHEN** сервер установлен впервые с явным прямым TLS
- **THEN** первоначальный пароль задаётся локально через терминал или приватный файл, а SQLite создаётся в назначенном постоянном каталоге

### Requirement: Upgrades and removal protect persistent state

Обновление SHALL менять поколение исполняемых файлов только после полной подготовки и сохранять привязку агента, настройки и состояние SQLite. Удаление SHALL останавливаться при неопределённом владении службой.

#### Scenario: An unsuccessful candidate restores a compatible previous generation

- **WHEN** новое поколение не стало готово и прежняя версия доказуемо совместима с фактическим состоянием
- **THEN** возвращаются прежний исполняемый набор, эффективный профиль, регистрация и пригодная служба; постоянные данные сохраняются

#### Scenario: Database compatibility is unproved

- **WHEN** переход мог изменить формат SQLite и совместимость прежней сборки неизвестна
- **THEN** прежний бинарник не запускается автоматически, текущее состояние и резерв сохраняются для решения владельца

#### Scenario: Service removal keeps durable data

- **WHEN** владелец подтверждает удаление установленной службы
- **THEN** удаляется только управляемая регистрация и исполняемые файлы, ключи и данные остаются доступными владельцу

### Requirement: A fresh transport installation manages one identified Entware service

Первичная установка транспортного агента SHALL закреплять конкретный выпуск, HTTPS origin, непривилегированного пользователя и приватное состояние. Служба SHALL подтверждать готовность после аутентификации. Действия init.d SHALL управлять только подтверждённым экземпляром.

#### Scenario: An agent enrolls from an explicitly trusted release

- **WHEN** владелец выбирает полный проверенный выпуск для ARM64, допустимую роль, приватное приглашение и доверенный HTTPS origin
- **THEN** агент запускается штатным init.d, подтверждает подключение, сохраняет рабочий ключ в постоянном каталоге и сохраняет привязку после штатного stop/start

#### Scenario: The host or existing service does not admit a fresh installation

- **WHEN** архитектура неподдерживаемая, роль не доказана, состояние неоднозначно или регистрация занята
- **THEN** установщик сообщает отказ без переключения существующей службы, а init.d не сигнализирует чужому процессу

#### Scenario: A candidate does not become ready

- **WHEN** проверенный агент не подтвердил аутентификацию при первом запуске
- **THEN** установка сообщает отказ, неподтверждённая служба не остаётся включённой, а приватное состояние, необходимое для повторного подключения, сохраняется

### Requirement: Transport-agent updates retain service identity and operating settings

Установленная служба SHALL обновляться до явно выбранного проверенного выпуска, сохранив HTTPS origin, CA, UID/GID и сохранённый ключ. Точный повтор установленного выпуска SHALL оставлять текущий экземпляр без перезапуска.

#### Scenario: An incomplete update leaves the current agent running

- **WHEN** загрузка файла нового выпуска прерывается либо ожидаемая сумма не совпадает
- **THEN** прежний процесс, профиль, поколение и приватное состояние остаются действующими

#### Scenario: A verified successor authenticates with the previous key

- **WHEN** новый проверенный выпуск допускается к установке, старый процесс штатно остановлен и новый запущен
- **THEN** новая служба подтверждает аутентификацию для того же RouterID, а приватное состояние и эффективный профиль сохраняются

#### Scenario: A failed update returns to the previous confirmed generation

- **WHEN** новый выпуск не подтверждает запуск
- **THEN** прежнее поколение возвращается только при доказанном отсутствии чужого или неопределённого процесса
- **AND** ошибка запуска и результат локального восстановления сообщаются отдельно, ключ и настройки остаются сохранёнными

#### Scenario: An interrupted update is resolved before automatic startup

- **WHEN** служба запускается после прерывания смены поколения
- **THEN** продолжение использует защищённую запись о старом и новом поколениях, сохраняет подтверждённое поколение и блокирует запуск при неопределённом состоянии

### Requirement: A fresh Entware server runs with explicit TLS and durable state

Установщик SHALL получать проверенный ARM64 выпуск, явный HTTPS origin, адрес слушателя, сертификат и приватный TLS-ключ. Сервер SHALL запускаться как выделенный непривилегированный пользователь. SQLite SHALL сохраняться в отдельном приватном каталоге.

#### Scenario: An installed server exposes the web shell over direct TLS

- **WHEN** владелец подтверждает корректный выпуск, TLS, роль и адрес
- **THEN** служба отвечает на HTTPS health, отдаёт встроенные HTML и ассет, а локальная настройка администратора использует штатный пароль из терминала или приватного файла владельца процесса

#### Scenario: Restart keeps the same administrator and database

- **WHEN** владелец останавливает и снова запускает подтверждённую службу через её регистрацию
- **THEN** она использует тот же SQLite, HTTPS, настройки и учётную запись администратора
- **AND** каталог агента и его собственная служба не изменяются

#### Scenario: Wrong TLS configuration prevents a confirmed install

- **WHEN** входная TLS-пара, адрес либо подтверждение слушателя некорректны
- **THEN** новая служба не включается в init.d и чужой процесс продолжает работать

### Requirement: Controlled application is an explicitly provisioned Entware role

Установка роли применения SHALL выбирать конкретный проверенный выпуск и согласованные root-owned локальные параметры с подтверждённым делегированием. Рабочий Xray, supervisor и агент SHALL получать отдельные полномочия. Неподтверждённая среда SHALL завершаться отказом до активации.

#### Scenario: An attested baseline enables the installed application service

- **WHEN** владелец подтверждает защищённый профиль с точным RouterID, origin, CA, ядром и первоначальным рабочим Xray
- **THEN** зарегистрированная служба запускает supervisor и агента в нужном порядке, сохраняет журнал и использует доказательство штатного supervisor при следующих стартах

#### Scenario: Mismatched capabilities or authority preserve the existing service

- **WHEN** среда, прошивка, привязка процесса или доверенный параметр не совпадают
- **THEN** установщик сообщает отказ без переключения существующей службы и без утверждения о применении

#### Scenario: Contact is reported separately from application

- **WHEN** установленный агент подключён, но нет действительного доказательства E08
- **THEN** сервер может показать контакт, а ревизия не отмечается применённой

### Requirement: The installed server explicitly pins remote validation and agent origin

Первичная установка сервера Entware SHALL принимать полный набор доверия к явно выбранному исполнителю HTTPS mTLS и независимый публичный agent origin. Приватный ключ SHALL оставаться в защищённых файлах. Неполные параметры SHALL отклоняться до включения службы.

#### Scenario: An installed server verifies publication against the chosen external worker

- **WHEN** владелец задал действительный HTTPS origin исполнителя и выделенную CA и клиентскую пару
- **THEN** F09 подключается к этому исполнителю по mTLS, а F10 показывает отдельно настроенный agent origin

#### Scenario: No executor is configured

- **WHEN** сервер установлен без конфигурации исполнителя
- **THEN** HTTPS и веб-консоль доступны, публикация сохраняет отказ при недоступности валидатора

### Requirement: Agent removal preserves its identity

Локальное удаление агента SHALL явно выбирать установленную роль, останавливать только подтверждённые процессы и удалять только собственную регистрацию и проверенные исполняемые файлы. Приватный ключ, настройки, применённый каталог, журнал и серверная история сохраняются.

#### Scenario: An installed transport role is removed

- **WHEN** владелец подтверждает удаление транспортного агента и принадлежность службы доказана
- **THEN** его запуск отключён, подтверждённый процесс остановлен, собственные исполняемые файлы удалены и проверенный повторный install может восстановить связь с прежним RouterID

#### Scenario: A managed role is removed with a proven stopped runtime

- **WHEN** владелец подтверждает удаление управляемого агента и журнал, файлы и идентичность Xray подтверждены под барьером запуска
- **THEN** принадлежащие установке процессы агента, supervisor и Xray остановлены, launcher роли снят, рабочие файлы Xray и материал безопасного возврата сохранены
- **AND** прежний механизм запуска восстанавливается только отдельным подтверждённым действием владельца при доказанной совместимости

#### Scenario: Ownership or runtime is uncertain

- **WHEN** обнаружен посторонний процесс, неожиданные файлы, неопределённое состояние перехода или непроверенный guard
- **THEN** удаление сообщает причину и сохраняет действующую защиту, а посторонний процесс и его файлы сохраняются

#### Scenario: An interruption occurs during removal

- **WHEN** процесс прерван после записи намерения
- **THEN** повтор удаляет только оставшиеся подтверждённые файлы, обычный запуск запрещён до завершения и каталог приватных данных сохраняется
