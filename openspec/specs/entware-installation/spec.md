# entware-installation Specification

## Purpose

Определить безопасную установку, обслуживание и удаление компонентов проекта на Entware ARM64 из конкретного выпуска или из проверочного зеркала.

## Requirements

### Requirement: Installation is bound to an explicitly trusted release

Установщик SHALL получать явно выбранную версию, доверенную сумму манифеста и предсказуемые имена файлов для выбранной роли. Перед изменением рабочей установки SHALL проверяться полное скачивание и целостность каждого необходимого файла.

#### Scenario: An invalid or incomplete download preserves the installation

- **WHEN** версия недоступна, манифест не совпадает с доверенной суммой или один из файлов не подтверждён
- **THEN** действующие файлы, служба и данные сохраняются без изменений

### Requirement: Installation explicitly binds service role and ownership

Для агента транспорта, агента с применением и центрального сервера SHALL явно определяться рабочая роль, полномочия, состояние и поддерживаемая среда. Компонент SHALL стартовать через закреплённый путь init.d после локальных проверок.

#### Scenario: Unavailable runtime capability blocks application

- **WHEN** выбранный профиль применения не может доказать требуемые возможности ядра и владельцев рабочего процесса
- **THEN** установщик блокирует этот профиль до смены действующей установки

#### Scenario: A fresh server preserves its administrator setup boundary

- **WHEN** сервер установлен впервые с явным прямым TLS
- **THEN** первоначальный пароль задаётся локально через терминал или приватный файл, а SQLite создаётся в назначенном постоянном каталоге

### Requirement: Upgrades and removal protect persistent state

Обновление SHALL менять поколение исполняемых файлов только после полной подготовки и сохранять привязку агента, настройки и состояние SQLite. Удаление SHALL останавливаться при неопределённом владении службой.

#### Scenario: An unsuccessful candidate restores a compatible previous generation

- **WHEN** новое поколение не стало готово и прежняя версия доказуемо совместима с фактическим состоянием
- **THEN** возвращаются прежний исполняемый набор, эффективный профиль, регистрация и пригодная служба; постоянные данные сохраняются

#### Scenario: Database compatibility is unproved

- **WHEN** переход мог изменить формат SQLite и совместимость прежней сборки неизвестна
- **THEN** прежний бинарник не запускается автоматически, текущее состояние и резерв сохраняются для решения владельца

#### Scenario: Service removal keeps durable data

- **WHEN** владелец подтверждает удаление установленной службы
- **THEN** удаляется только управляемая регистрация и исполняемые файлы, ключи и данные остаются доступными владельцу

### Requirement: A fresh transport installation manages one identified Entware service

Первичная установка транспортного агента SHALL закреплять конкретный выпуск, HTTPS origin, непривилегированного пользователя и приватное состояние. Служба SHALL подтверждать готовность после аутентификации. Действия init.d SHALL управлять только подтверждённым экземпляром.

#### Scenario: An agent enrolls from an explicitly trusted release

- **WHEN** владелец выбирает полный проверенный выпуск для ARM64, допустимую роль, приватное приглашение и доверенный HTTPS origin
- **THEN** агент запускается штатным init.d, подтверждает подключение, сохраняет рабочий ключ в постоянном каталоге и сохраняет привязку после штатного stop/start

#### Scenario: The host or existing service does not admit a fresh installation

- **WHEN** архитектура неподдерживаемая, роль не доказана, состояние неоднозначно или регистрация занята
- **THEN** установщик сообщает отказ без переключения существующей службы, а init.d не сигнализирует чужому процессу

#### Scenario: A candidate does not become ready

- **WHEN** проверенный агент не подтвердил аутентификацию при первом запуске
- **THEN** установка сообщает отказ, неподтверждённая служба не остаётся включённой, а приватное состояние, необходимое для повторного подключения, сохраняется
