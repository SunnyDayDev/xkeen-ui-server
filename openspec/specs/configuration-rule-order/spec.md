# configuration-rule-order Specification

## Purpose

Определяет порядок общих и локальных правил одного роутера по стабильным UUID и числовым позициям, включая обновления шаблона и явную границу сохранения перед публикацией ревизий.

## Requirements

### Requirement: Template and router use ordered rule ID lists

Шаблон SHALL задавать упорядоченный список UUID своих правил маршрутизации. Полный список одного роутера SHALL содержать каждый общий UUID выбранного шаблона и каждый локальный UUID роутера ровно один раз. UUID общего правила SHALL сохранять ссылку на шаблон независимо от позиции и режима содержимого. В списке SHALL учитываться исключённое общее правило: исключение скрывает его только из видимого результата, а снятие исключения возвращает на прежнюю позицию. Порядок SHALL NOT определяться Xray-тегами, JSON-полями, порядком записей B06 или значениями переменных.

При отсутствии персонального порядка последовательность общих правил SHALL следовать актуальному шаблону. Успешная операция SHALL возвращать независимый полный список и видимую после исключений последовательность с происхождением правил. Пустой список SHALL быть успешным результатом.

#### Scenario: Initial order follows template
- **WHEN** шаблон содержит общие правила A, B, C с разными корректными UUID, а у роутера нет локальных правил и персонального порядка
- **THEN** полный и видимый порядок роутера равен A, B, C

#### Scenario: Shared and local rules share one list
- **WHEN** шаблон содержит A, B, а роутер вставил локальное L на позицию 1
- **THEN** полный порядок равен A, L, B; L остаётся локальным, A и B сохраняют связь с шаблоном

#### Scenario: Exclusion does not delete position
- **WHEN** полный порядок равен A, B, L, общее B исключено, затем исключение снято
- **THEN** при исключении виден порядок A, L, а после снятия снова A, B, L

#### Scenario: Empty order is valid
- **WHEN** шаблон и роутер не содержат правил маршрутизации
- **THEN** возвращается успешный пустой список

### Requirement: Rules can be inserted and moved by index

Позиции полного списка SHALL нумероваться с нуля. Вставка нового локального правила SHALL принимать индекс от 0 до длины списка включительно и сдвигать последующие правила вправо. Перемещение существующего общего либо локального правила SHALL принимать индекс в списке после изъятия перемещаемого правила и помещать его на этот индекс; остальные правила сохраняют относительный порядок. Изменение позиции SHALL NOT менять UUID, содержимое, происхождение, режим переопределения, персональные значения или исключение. Попытка вставить уже присутствующий UUID SHALL отклоняться, а не создавать второй экземпляр.

#### Scenario: Insert at beginning, middle, and end
- **WHEN** в трёх независимых случаях полный список равен A, B, а новое локальное правило вставляют на допустимый индекс 0, 1 либо 2
- **THEN** кандидат равен соответственно L, A, B; A, L, B; либо A, B, L

#### Scenario: Move shared rule across a local rule
- **WHEN** список равен A, L, B, а общее B перемещают на индекс 0
- **THEN** результат равен B, A, L, при сохранении наследования содержимого B

#### Scenario: Move uses resulting index
- **WHEN** список равен A, B, C, а A перемещают на индекс 2 после его изъятия
- **THEN** результат равен B, C, A

#### Scenario: Invalid index is rejected
- **WHEN** вставка или перемещение получает отрицательный индекс либо индекс вне допустимой длины
- **THEN** возвращается invalid_order_index без частичного списка и без изменения прежнего порядка

### Requirement: Template additions and removals use numeric positions

Для роутера без персонального порядка изменения последовательности общих правил SHALL следовать текущему шаблону. Для роутера с персональным порядком новое общее правило, вставленное в шаблон на индекс i, SHALL вставляться в его полный список на тот же числовой индекс i с сдвигом последующих правил, включая локальные. Удалённый из шаблона UUID SHALL удаляться из полного списка порядка роутера; относительный порядок остальных UUID SHALL сохраняться. При нескольких добавлениях и удалениях SHALL сначала удаляться исчезнувшие UUID, затем новые UUID SHALL вставляться по возрастанию их индексов в новом шаблоне, чтобы их относительный порядок соответствовал шаблону. Простая перестановка уже существующих общих UUID в шаблоне SHALL NOT сбрасывать персональный порядок.

Удаление UUID из списка порядка SHALL NOT само по себе удалять сохранённые переопределения или исключения. Их привязки и ошибки отсутствующего источника сохраняют контракт B06; итог, который не прошёл эту проверку, SHALL NOT публиковаться как готовая ревизия.

#### Scenario: New shared rule uses the same index on a personalized router
- **WHEN** шаблон A, B, C получает X на индекс 1, а полный персональный список роутера до изменения равен C, A, B
- **THEN** его новый полный список равен C, X, A, B

#### Scenario: New shared rule shifts a local rule
- **WHEN** шаблон A, B получает X на индекс 1, а полный порядок роутера равен A, L, B
- **THEN** после вставки на тот же индекс полный порядок равен A, X, L, B

#### Scenario: Deleted shared rule simply leaves the order
- **WHEN** шаблон удаляет B, а полный порядок роутера равен C, L, B, A
- **THEN** полный порядок после изменения равен C, L, A, без изменения содержимого L и остальных правил

#### Scenario: Several template changes use new numeric indices
- **WHEN** шаблон A, B, C становится X, A, Y, C, а полный персональный список роутера до изменения равен C, L, B, A
- **THEN** после удаления B и вставки X на индекс 0 и Y на индекс 2 полный порядок равен X, C, Y, L, A

#### Scenario: Existing template move preserves a personal order
- **WHEN** шаблон меняет порядок A, B на B, A, а роутер уже имеет персональный порядок A, L, B
- **THEN** персональный порядок остаётся A, L, B до явной правки или возврата к порядку шаблона

#### Scenario: Default router follows template move
- **WHEN** шаблон меняет порядок A, B на B, A, а роутер не имеет персонального порядка
- **THEN** его порядок становится B, A

### Requirement: Reset restores shared order and keeps local positions

Действие «Вернуть порядок шаблона» SHALL расставлять общие UUID в актуальной последовательности шаблона, сохраняя числовые позиции локальных правил в полном списке и их относительный порядок. Сброс SHALL NOT удалять локальные правила, их JSON, исключения, значения переменных или полные замены. Исключённые общие UUID SHALL участвовать в полном списке при расчёте позиций, даже если не видны в результате.

#### Scenario: Reset keeps a local numeric slot
- **WHEN** шаблон задаёт A, B, C, персональный полный порядок равен B, L, A, C, а L занимает индекс 1
- **THEN** после возврата полный порядок равен A, L, B, C

#### Scenario: Reset retains exclusion and content override
- **WHEN** общее B имеет полную замену и исключено, а роутер возвращает порядок шаблона
- **THEN** B занимает свою шаблонную позицию в полном списке, остаётся скрытым в видимом результате и сохраняет полную замену

### Requirement: Save gates publication of changed orders

Редактирование шаблона и конечных порядков нескольких затронутых роутеров SHALL давать кандидаты, которые можно проверить до сохранения. Экран редактирования SHALL предоставлять явное действие «Сохранить». До его успешного выполнения правки порядка SHALL NOT менять желаемые ревизии роутеров и SHALL NOT посылать агентам сигнал об изменении. При сохранении сервис SHALL проверить полный порядок каждого затронутого роутера и, если проверка порядка успешна, передать согласованный набор результатов сценарию публикации ревизий. Ошибка проверки порядка любого затронутого роутера SHALL блокировать публикацию всего набора, возвращать ошибки для исправления и сохранять прежние желаемые ревизии. Успешное сохранение SHALL NOT означать, что агенты уже применили новые ревизии: недоступные устройства получат актуальную желаемую ревизию после восстановления связи. Детали сравнения файлов, конкурентных правок и других ошибок публикации определяются C05–C07.

#### Scenario: Editing does not roll out rules
- **WHEN** пользователь переставил правила шаблона и одного роутера, но ещё не выбрал «Сохранить»
- **THEN** предпросмотр показывает кандидатов, а желаемые ревизии и состояние агентов остаются прежними

#### Scenario: One invalid affected order blocks save
- **WHEN** кандидат затрагивает несколько роутеров, и полный список одного из них содержит повторный UUID
- **THEN** сохранение возвращает ошибку этого роутера и не передаёт ни один из кандидатов в публикацию

#### Scenario: Successful save starts publication, not application
- **WHEN** все затронутые полные списки корректны и пользователь выбирает «Сохранить»
- **THEN** кандидаты передаются сценарию публикации для затронутых роутеров; статус «применено» появляется только после отдельного подтверждения агента

### Requirement: Invalid order input returns safe atomic errors

Проверка SHALL охватывать полный список до исключений. Повторный UUID SHALL давать duplicate_order_element; отсутствующий UUID правила — order_element_not_found; неверный индекс — invalid_order_index. Некорректный владелец или UUID SHALL использовать ошибки идентичности действующих контрактов. Операция SHALL возвращать полный результат своей области либо хотя бы одну ошибку без частичного результата и без мутации входов. Диагностика SHALL указывать владельца, позицию и корректный UUID, когда он известен, но SHALL NOT включать сырой JSON, персональные значения или невалидный UUID. Успех порядка SHALL NOT подтверждать корректность ссылок между правилами, готовность Xray, публикацию или применение.

#### Scenario: Duplicate rule is rejected even if excluded
- **WHEN** полный список содержит один UUID дважды, а один экземпляр помечен исключённым
- **THEN** возвращается duplicate_order_element без видимого частичного порядка

#### Scenario: Missing local rule is rejected
- **WHEN** полный список ссылается на локальный UUID, которого нет в полном снимке роутера
- **THEN** возвращается order_element_not_found; правило не заменяется другим по позиции или Xray-тегу

#### Scenario: Omitted rule is rejected
- **WHEN** полный снимок содержит локальное L, а полный список порядка содержит только общие A и B
- **THEN** возвращается order_element_not_found без частичного результата

#### Scenario: Inputs and result are independent
- **WHEN** вызывающая сторона изменяет успешный список результата либо проверка возвращает ошибку
- **THEN** исходные списки, шаблон, персональные данные и JSON остаются неизменными

### Requirement: Ordered router selection preserves chosen content

Сборка порядка одного роутера SHALL соединять полный список UUID из актуального шаблона и локальных правил с результатом выбора содержимого по `configuration-content-inheritance`. Она SHALL проверять полный список, включая исключённые общие UUID, до формирования видимого результата. Успешный результат SHALL содержать независимый полный порядок с происхождением каждого UUID и видимую последовательность активных правил с тем же происхождением и уже выбранным JSON. Исключённое общее правило SHALL занимать место только в полном порядке; его содержимое SHALL NOT собираться для видимой последовательности.

Перестановка SHALL NOT менять JSON, режим наследования, персональные значения, исходный шаблон или локальные записи и SHALL NOT интерпретировать выбранное содержимое повторно. Ошибка выбора содержимого либо порядка SHALL возвращать ошибку без частичного упорядоченного результата. Успех SHALL NOT означать готовность полного файла Xray или публикацию ревизии.

#### Scenario: Inherited and local content follow ID order
- **WHEN** общий A наследует актуальный JSON шаблона, локальное L содержит буквальный JSON, а полный порядок равен L, A
- **THEN** видимый порядок равен L, A с происхождением и соответствующим уже выбранным JSON каждого правила
- **AND** содержимое A и L не меняется из-за перестановки

#### Scenario: Full replacement moves without reassembling
- **WHEN** общее A использует собственный JSON целиком, а его UUID перемещён после локального L
- **THEN** видимый порядок равен L, A и A сохраняет выбранную полную замену без подмешивания шаблонного JSON или повторной подстановки

#### Scenario: Excluded rule keeps only its full-order position
- **WHEN** полный порядок равен A, B, L, общее B исключено и его содержимое не проходит проверку активного элемента
- **THEN** полный порядок сохраняет A, B, L с происхождением, а видимый содержит только выбранные A, L
- **AND** ошибка содержимого B не блокирует успешный результат при корректных метаданных B

#### Scenario: Content failure prevents ordered result
- **WHEN** полный порядок корректен, но выбор активного правила возвращает ошибку содержимого или персональных значений
- **THEN** сборка возвращает эту безопасную ошибку без полного и видимого кандидатов

#### Scenario: Order failure prevents ordered result
- **WHEN** содержимое активных правил выбрано успешно, но полный список порядка пропускает локальный UUID либо содержит повтор исключённого общего UUID
- **THEN** сборка возвращает соответственно order_element_not_found либо duplicate_order_element без видимого или полного кандидата

#### Scenario: Result and source data are independent
- **WHEN** вызывающая сторона меняет JSON либо списки успешного упорядоченного результата
- **THEN** входные данные, выбранное содержимое другого результата и последующая сборка остаются неизменными
