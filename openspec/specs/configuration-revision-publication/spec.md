# configuration-revision-publication Specification

## Purpose

Определить переход от редактируемого состояния к проверенным желаемым ревизиям и гарантировать согласованный результат публикации для всех затронутых устройств.

## Requirements

### Requirement: Publication is explicit and distinct from agent application

Сервер SHALL изменять желаемое состояние только явной публикацией. Предпросмотр и самостоятельное сохранение черновика SHALL оставлять желаемые ревизии без изменений. Подтверждение применения SHALL поступать отдельно от агента после проверки на устройстве и применения.

#### Scenario: An unready draft remains saved
- **WHEN** пользователь отдельно сохраняет структурно допустимый черновик, а последующая явная публикация отклоняет его
- **THEN** сохранённый черновик остаётся доступен, желаемые и применённые ревизии сохраняют прежние значения

#### Scenario: Preview does not accept a draft
- **WHEN** пользователь запрашивает предпросмотр кандидата порядка или содержимого
- **THEN** он получает результаты проверки без фиксации правок, порядка, желаемой или применённой ревизии

#### Scenario: An offline router can receive a new desired revision
- **WHEN** явное сохранение успешно публикует изменённый каталог для недоступного роутера
- **THEN** желаемая ревизия сохранена для выдачи при восстановлении связи, а применённая остаётся прежней до отдельного подтверждения агента

### Requirement: A shared publication uses confirmed template assignments

Персональная публикация SHALL использовать действующее назначение указанного роутера. Общая публикация SHALL включать всех роутеров с подтверждённым назначением изменяемого шаблона, включая недоступных, независимо от исключений и режимов переопределения. Ожидающая смена шаблона SHALL вступать в силу только после отдельного явного подтверждения для этого роутера.

#### Scenario: Shared publication during a pending switch
- **GIVEN** у роутера действует шаблон A, а смена на B ожидает подтверждения
- **WHEN** отдельно публикуют общую правку A или общую правку B
- **THEN** публикация A проверяет роутер с настройками действующего назначения A, а публикация B не включает его по ожидающей смене
- **AND** ни одна из операций не активирует B и не использует настройки, подготовленные только для B

#### Scenario: Confirmation updates later membership
- **GIVEN** отдельная операция смены шаблона успешно подтвердила переход с A на B
- **WHEN** далее рассматривается общая правка шаблона A или B
- **THEN** роутер входит в набор B и больше не входит в набор A

#### Scenario: Replacement is not grounds for early exclusion
- **WHEN** общая правка затрагивает роутер, полностью заменивший изменённый элемент
- **THEN** сервер проверяет итоговый снимок этого роутера и только по результату сравнения определяет необходимость новой ревизии

### Requirement: Personal publication uses an accepted shared snapshot

Сервер SHALL хранить принятый общий снимок независимо от черновика. Персональная публикация SHALL использовать неизменяемый принятый снимок действующего шаблона. Общая публикация SHALL принимать новый общий снимок только явной операцией, в том числе когда подтверждённых назначений ещё нет.

#### Scenario: An independently saved template remains a draft
- **GIVEN** снимок шаблона A версии N принят общей публикацией, а C03 отдельно сохранил черновик A версии N+1
- **WHEN** запускается персональная публикация роутера с действующим назначением A
- **THEN** используются общие данные версии N и публикация не принимает N+1 ни для одного устройства

#### Scenario: A shared publication can accept a template with no participants
- **WHEN** явно публикуется структурно корректный новый общий снимок шаблона, для которого нет подтверждённых назначений
- **THEN** сервер принимает общий снимок без выдачи желаемых ревизий
- **AND** результат не подтверждает проверку каталога для какого-либо роутера

### Requirement: Initial assignment is confirmed together with the first revision

Для роутера без действующего назначения сервер SHALL требовать отдельное явное первое подтверждение. Сервер SHALL принять назначение и первую проверенную ревизию атомарно. Начальный общий снимок SHALL приниматься этой операцией только при отсутствии принятого снимка и других действующих назначений этого шаблона.

#### Scenario: The first router can bootstrap a new template
- **GIVEN** у роутера нет назначения, у выбранного шаблона нет ни принятого снимка, ни действующих назначений, а команда указывает исходный черновик с ожидаемой версией
- **WHEN** пользователь явно подтверждает первое назначение и точный каталог проходит проверку
- **THEN** сервер принимает общий снимок, назначение и первую желаемую ревизию только для этого роутера
- **AND** устройства с неподтверждённым выбором того же шаблона остаются без назначения

#### Scenario: Failed initial confirmation preserves the draft
- **WHEN** первое подтверждение отклоняется из-за ошибки кандидата, недоступности Xray либо появления принятого снимка в ходе операции
- **THEN** сервер оставляет ранее сохранённый черновик и не создаёт назначения, принятого снимка или желаемой ревизии для этой команды
- **AND** конкурирующая успешная операция сохраняет свои результаты

#### Scenario: First assignment to an already accepted template
- **WHEN** пользователь явно подтверждает первое назначение на шаблон с принятым снимком
- **THEN** сервер проверяет каталог на основе принятого снимка и новых персональных настроек
- **AND** текущий отдельно сохранённый общий черновик не принимается этой операцией

### Requirement: Personalized order uses a known complete basis

Сервер SHALL сверять полный персональный порядок с полным общим порядком, на котором он основан, и пересчитывать по B08 при изменении этого основания. Неизвестное или несовместимое основание SHALL блокировать публикацию до явного согласования порядка. Проверка SHALL предшествовать исключениям и отключениям.

#### Scenario: Full order is reconciled for a known basis
- **GIVEN** сохранённый полный персональный порядок основан на известной версии общего порядка
- **WHEN** общий шаблон добавляет и удаляет правила
- **THEN** кандидат порядка перестроен по B08 и проверен для каждого затронутого роутера
- **AND** удаление UUID из порядка не удаляет автоматически переопределение или исключение, а оставшаяся ссылка на исчезнувший источник блокирует публикацию по B06

#### Scenario: Current template and old files do not establish order basis
- **WHEN** известен полный персональный список, но отсутствует подтверждённый исходный общий список
- **THEN** сервер сообщает о необходимости согласовать основание порядка и не меняет ни один сохранённый порядок или ревизию
- **AND** простое совпадение множества UUID либо предыдущие итоговые файлы не подменяют основание

#### Scenario: Inherited order does not require historical basis
- **WHEN** персональный порядок отсутствует и текущий шаблон меняет общий порядок
- **THEN** роутер следует новому общему порядку в кандидате

### Requirement: Publication validates the complete exact catalog on the server

Перед принятием публикации сервер SHALL собрать полный каталог B12 для каждого участника и проверить его точные файлы закреплённой версией Xray для целевого профиля. Доменные ошибки, отказ Xray и невозможность проверки SHALL иметь различимые результаты. Перед применением агент SHALL отдельно проверить полученную ревизию у себя.

#### Scenario: Empty section belongs to a complete loaded snapshot
- **WHEN** сервер полностью загрузил шаблон и настройки, а обязательная секция не содержит записей
- **THEN** он передаёт секцию B12 явно пустой
- **AND** отсутствие самого снимка либо невозможность полной загрузки даёт ошибку до сборки

#### Scenario: Xray rejects the exact assembled files
- **WHEN** B12 выдаёт каталог, но закреплённый Xray отвергает эти файлы
- **THEN** сервер возвращает безопасную ошибку конфигурации и не принимает публикацию ни для одного участника

#### Scenario: Validator unavailable is not a configuration result
- **WHEN** закреплённый Xray невозможно использовать или его версия не соответствует профилю
- **THEN** сервер возвращает отдельную ошибку недоступности проверки и сохраняет действующие ревизии

### Requirement: Only changed named file sets create revisions

Для одного целевого профиля сервер SHALL сравнивать точный набор имён файлов и байты каждого файла с действующей желаемой ревизией. Первый успешно проверенный каталог и изменение набора или байтов SHALL создавать новую неизменяемую ревизию. Равный набор SHALL сохранять прежнюю желаемую ревизию без повторной доставки как новой.

#### Scenario: A valid publication yields no new bytes for a router
- **WHEN** каталог прошёл обязательную проверку и совпадает с текущим желаемым каталогом по именам и байтам
- **THEN** результат для роутера сообщает об отсутствии изменения ревизии, даже если изменились исходное оформление или диагностические позиции
- **AND** успешная общая публикация может зафиксировать принятые исходные правки и основания порядка

#### Scenario: A file disappears or accepted bytes change
- **WHEN** проверенный каталог отличается именем, числом или байтами файлов, либо желаемой ревизии ещё нет
- **THEN** сервер сохраняет полный набор проверенных файлов в новой желаемой ревизии этого роутера

### Requirement: Publication rejects stale assumptions and commits atomically

Сервер SHALL проверять актуальность всех исходных версий, действующих назначений, состава участников и прежних желаемых ревизий перед фиксацией. Успешная публикация SHALL фиксировать принятую правку, пересчитанные порядки и изменившиеся желаемые ревизии вместе. Любая ошибка или конфликт SHALL оставлять их без частичной фиксации.

#### Scenario: One participant prevents a shared commit
- **WHEN** один из затронутых роутеров даёт ошибку источника, порядка, сборки, проверки Xray либо записи
- **THEN** правка, пересчитанные порядки и новые желаемые ревизии не фиксируются ни для одного участника
- **AND** диагностика указывает этап и безопасный контекст, без JSON, значений переменных и сырого вывода Xray

#### Scenario: Membership changes after preview or validation
- **WHEN** между получением исходного снимка и записью меняется использованный шаблон, использованная настройка участника, его желаемая ревизия либо состав назначений
- **THEN** сервер возвращает конфликт актуальности и требует подготовки нового кандидата
- **AND** действующие назначения и ревизии, принятые другой командой, сохраняются

#### Scenario: Reconciliation preserves a pending switch draft
- **GIVEN** у роутера действует A, для B независимо сохранён черновик, а публикация A перестраивает действующий порядок
- **WHEN** черновик B меняется во время публикации A
- **THEN** публикация A сохраняет только действующие порядок и основание A и оставляет последнюю запись B неприкосновенной
- **AND** если команда сама читает для публикации или обновляет какой-либо редактируемый черновик, изменение его версии до записи даёт конфликт

#### Scenario: Repeating a previously accepted publication
- **WHEN** повторная команда основана на актуальных версиях и проверенные байты совпадают с текущими желаемыми
- **THEN** сервер не выдаёт новую ревизию
- **AND** повтор со старыми версиями получает конфликт, даже если вызывающий не получил исходный ответ

### Requirement: Preparation requires complete sources for one router

Внутренняя подготовка SHALL принимать выбранный общий снимок с положительной версией и полный снимок одного роутера. ID выбранного шаблона у роутера SHALL совпадать с общим снимком. При отсутствии снимка или несовместимом контексте результатом SHALL быть безопасная ошибка без каталога.

#### Scenario: An empty complete snapshot still yields the base files
- **WHEN** оба снимка успешно переданы, относятся к одному шаблону и не содержат записей
- **THEN** результат содержит пять базовых файлов B12 и не содержит дополнительных файлов

#### Scenario: Missing data are not normalized to empty groups
- **WHEN** общего снимка либо снимка роутера нет
- **THEN** подготовка сообщает об отсутствующем снимке без каталога

#### Scenario: Incompatible source fails before preparation
- **WHEN** ID шаблона в снимках различаются, идентификатор недопустим либо версия общего снимка неположительна
- **THEN** подготовка возвращает безопасную ошибку контекста без каталога

### Requirement: Preparation preserves catalog semantics across the sources

Подготовка SHALL передавать B12 полные группы содержимого, переопределений и исключений. Необязательные группы SHALL сохранять явное присутствие. Отключение правила и входа SHALL действовать при общем или персональном флаге. Ошибка сборки SHALL возвращаться без частичного результата. Успех SHALL возвращать независимые точные файлы и диагностическую привязку B12.

#### Scenario: Local data and common elements contribute to one catalog
- **WHEN** снимки содержат общую секцию с персональными значениями, полную замену, исключение и локальный элемент
- **THEN** каталог соответствует B12 для этих данных, включая исходные UUID и безопасные позиции

#### Scenario: Only present optional groups are emitted
- **WHEN** один из полных снимков явно задаёт пустой stats, а оба не задают fakedns
- **THEN** каталог содержит результат для пустого stats и не содержит fakedns

#### Scenario: Both sources can disable the same supported element
- **WHEN** одно правило или вход выключены одновременно в общем снимке и персональном списке
- **THEN** элемент исключается из действующих файлов ровно один раз
- **AND** полная идентичность записи сохраняется для проверки порядка и зависимостей

#### Scenario: An unsupported disabled state is visible
- **WHEN** элемент общего снимка отмечен выключенным в секции, для которой эффективное отключение не поддерживается
- **THEN** подготовка возвращает `unsupported_disabled_section` с безопасной позицией без каталога

### Requirement: A prepared candidate carries the complete order basis

При персональном порядке подготовка SHALL принимать известное основание с ID, версией и полным общим списком UUID. B08 SHALL проверять и пересчитывать полный порядок до применения исключений и отключений. Неизвестное или несовместимое основание SHALL давать безопасную ошибку без каталога. Успех SHALL возвращать независимый полный персональный порядок и основание выбранного общего снимка.

#### Scenario: No personal order inherits the current template
- **WHEN** персональный порядок и локальные правила отсутствуют
- **THEN** подготовка использует наследование B08 и возвращает отсутствие персонального порядка и его основания

#### Scenario: Local rules require a complete personal order
- **WHEN** снимок содержит локальное правило, но персональный список отсутствует или его пропускает
- **THEN** подготовка возвращает ошибку неполного порядка B08 без каталога

#### Scenario: An explicitly empty order has a known empty basis
- **WHEN** полные общие и локальные правила отсутствуют, явно переданы пустой персональный список и известное пустое основание
- **THEN** результат сохраняет явно пустые списки и известное основание

#### Scenario: Current basis must describe the full current order
- **WHEN** заявлена версия выбранного общего снимка, но список основания отличается от его полного порядка или относится к другому шаблону
- **THEN** результат сообщает о несовместимом основании без каталога

#### Scenario: Earlier basis is reconciled before the current filters
- **WHEN** известный более ранний полный общий порядок содержит сохраняющиеся исключённые или выключенные UUID, а выбранный снимок добавляет или удаляет другие правила
- **THEN** результат использует пересчёт B08 и возвращает текущий полный список основания

#### Scenario: Removed sources remain visible to validation
- **WHEN** новая версия удаляет общее правило, на которое ссылается персональное исключение, переопределение или список отключений
- **THEN** подготовка возвращает безопасную ошибку соответствующей ссылки без каталога
- **AND** исходные списки остаются прежними

### Requirement: Isolated execution of the pinned validator

Сервис SHALL выполнять проверку точных файлов только в ограниченной одноразовой среде выбранного профиля.

#### Scenario: File initialization during the test
- **WHEN** Xray инициализирует предусмотренный профилем файловый журнал
- **THEN** запись возможна только в отведённом временном пространстве попытки, кандидат сохраняет исходные байты
- **AND** процессу недоступны настройки сервера и роутера, постоянные журналы, сокеты управления и внешняя сеть

#### Scenario: Isolation or resources unavailable
- **WHEN** ограничения нельзя установить либо проверка превысила срок или ресурсный лимит
- **THEN** результат означает недоступность проверки, выполнение прекращается, временные данные освобождаются, публикация заблокирована

### Requirement: Full catalog disclosure requires an explicitly trusted validator

Сервис SHALL передавать полный каталог внешнему исполнителю только при явной настройке его адреса и доверия обеих сторон через защищённый канал.

#### Scenario: Remote validation requested
- **WHEN** настроен доверенный внешний исполнитель и проверены удостоверения сервера и исполнителя
- **THEN** только этот исполнитель получает исходные имена и байты всех файлов, включая персональные секреты, и проводит изолированную проверку

#### Scenario: Remote transmission is not authorized
- **WHEN** внешний режим не настроен, проверка удостоверения не прошла или получатель предлагает перенаправление
- **THEN** каталог не передаётся неподтверждённому получателю, другой адрес автоматически не выбирается
- **AND** отсутствие доступного выбранного исполнителя блокирует публикацию и позволяет продолжать работу с черновиками

### Requirement: Each result identifies one exact validation attempt

Сервис SHALL принимать ответ выбранного исполнителя только при подтверждённом соответствии текущей попытке, её профилю и точному набору именованных байтов.

#### Scenario: Recognized outcomes for the current request
- **WHEN** закреплённый Xray завершил проверку полного переданного каталога и исполнитель подтвердил его принятие или отказ
- **THEN** вызывающий получает соответствующий результат для этого каталога без конфигурации, вывода Xray и временных путей

#### Scenario: Invalid or stale response
- **WHEN** ответ относится к другой попытке, версии или именованным байтам либо его формат или происхождение нельзя подтвердить
- **THEN** проверка недоступна, результат нельзя использовать для принятия ревизии
