# xkeen-exclusions Specification

## Purpose

Общие и персональные источники задают отдельный текстовый файл исключений для XKeen и определяют, когда устройство способно выполнить требуемый обход.

## Requirements

### Requirement: Exact authoring and bounded text substitution

Редактор SHALL сохранять исходный текст и стабильный UUID. В режиме наследования сборка SHALL разрешать ссылку `${name}` в позиции всей записи как строковое значение IP или CIDR. Имя с точкой сравнивается целиком. Комментарии и пустые строки не требуют значений. Сборка SHALL отклонять отсутствующее значение, значение с переводом строки, рекурсивную ссылку, неподдерживаемый тип и несколько записей в строке, сохраняя исходный черновик.

#### Scenario: Literal full override

- **WHEN** роутер выбирает полную персональную замену
- **THEN** записи проверяются как буквальные адреса, UUID сохраняется, исходный общий шаблон и персональные значения остаются доступны

### Requirement: Deterministic ip_exclude.lst

Сборка SHALL принять отдельный IPv4 или IPv6 адрес либо корректную сеть CIDR, пустые строки, CRLF и комментарии от знака #. После проверки всех строк она SHALL выдать файл UTF-8 с LF в порядке первых вхождений, без комментариев или повторных идентичных адресных диапазонов. Пустой явно настроенный список SHALL выдавать файл нулевой длины. Отсутствие настройки SHALL оставлять файл вне результата.

#### Scenario: Invalid address does not yield a partial file

- **WHEN** хотя бы одна запись содержит имя узла, scoped IPv6, неканонический сетевой адрес с установленными host bits, адрес с портом префикс /0 любой семьи, IPv4-mapped IPv6, повреждённый UTF-8 либо неподдерживаемую семью назначения
- **THEN** результат содержит безопасную позицию ошибки без фрагмента введённого текста, частичный файл отсутствует

#### Scenario: Separate evidence

- **WHEN** сервер собрал файл либо Xray подтвердил валидность своего JSON-каталога
- **THEN** система различает это состояние и подтверждённое применение исключений XKeen

#### Scenario: Host prefix deduplication

- **WHEN** список повторяет адрес IPv4 как /32 или адрес IPv6 как /128
- **THEN** файл содержит один обычный адрес на каждый диапазон в порядке его первого появления

### Requirement: Publication respects the effective capability of each assigned router

C06 SHALL отказывать до принятия новой ревизии, если непустой эффективный список требует неподтверждённой возможности обхода или устройство работает только с Xray. Оператор SHALL получить причину «Обход для указанных адресов обеспечить нельзя». Отсутствующий или пустой эффективный список SHALL допускать обычную публикацию Xray при прохождении остальных проверок. Подтверждение Xray не означает изменения или очистки firewall.

#### Scenario: Individual revision cannot honor bypass

- **WHEN** на роутере только с Xray получен непустой список после наследования или персональной замены
- **THEN** назначение и желаемая ревизия сохраняются, пользователь видит причину блокировки

#### Scenario: Atomic shared publication

- **WHEN** среди участников C07 хотя бы одному нельзя обеспечить обход для непустого эффективного списка
- **THEN** ни один участник не получает новую ревизию, принятый общий снимок также сохраняется без изменений

#### Scenario: Publication without active assignments

- **WHEN** шаблон публикуется с нулём действующих назначений
- **THEN** C07 может принять общий источник без желаемых ревизий и без утверждения о проверке на устройстве

### Requirement: Independent exclusion candidate

Сборка SHALL возвращать отдельный результат для файла ip_exclude.lst после проверки всего источника. При отсутствии элемента кандидат отсутствует. Если элемент явно задан и после проверки список пуст, кандидат содержит файл нулевой длины. При ошибке кандидат отсутствует, а код и позиция ошибки не содержат введённые адреса или значения переменных.

#### Scenario: Substitution and complete replacement

- **WHEN** один источник собирают сначала с персональными значениями, затем с полной заменой текста
- **THEN** получаются независимые кандидаты по правилам G06, исходник и параметры обоих вызовов остаются прежними
