# external-management-api Specification

## Purpose
Внешний HTTPS-канал обеспечивает отдельный программный доступ к прикладным операциям управления.

## Requirements

### Requirement: External API availability and authorization are independent

Сервис SHALL сохранять отдельно наличие внешнего API и требование внешних учётных данных. Выключенный API SHALL не разрешать управление при любом значении требования. При включённом API запрос SHALL требовать внешний Bearer только в объявленном авторизованном режиме.

#### Scenario: Authorization is changed while the API is off
- **WHEN** владелец меняет требование авторизации при выключенном API
- **THEN** API остаётся недоступным и сохранённое требование применяется после явного включения

#### Scenario: Agent and browser access survive API changes
- **WHEN** владелец меняет внешний доступ или его авторизацию
- **THEN** действующие сессии интерфейса и обмен с роутерами сохраняют свои правила и полномочия

### Requirement: External authorization has a distinct scope

Управление через внешний канал SHALL допускаться по HTTPS. Внешнее полномочие SHALL использоваться только для доступных программных операций управления. Веб-сессия и агентский ключ SHALL не заменять внешний Bearer. Управление переключателями, токеном и полномочиями D02 SHALL требовать отдельного допуска владельца.

#### Scenario: An agent key is sent to the management API
- **WHEN** внешний API требует авторизацию и клиент передаёт действующий агентский ключ
- **THEN** запрос получает отказ без раскрытия содержимого

#### Scenario: Authorization changed before a write
- **WHEN** переключение внешнего доступа или отзыв полномочия опережает попытку записать правку
- **THEN** запрос больше не допускается и данные управления не меняются

### Requirement: External template edits retain conditional write semantics

Чтение выбранного шаблона SHALL возвращать редактируемый снимок и предусловие его версии. Изменение SHALL применять правила выбранного элемента и условной записи C03. Ошибка SHALL оставлять сохранённую версию без изменений.

#### Scenario: The UI won a concurrent save
- **WHEN** внешний клиент применяет свою правку после изменения версии в UI
- **THEN** он получает конфликт предусловия и правка UI сохраняется

#### Scenario: Editing does not publish an application outcome
- **WHEN** внешний клиент успешно меняет сырой JSON выбранного элемента
- **THEN** следующая версия черновика читается, а принятые или желаемые ревизии остаются прежними

### Requirement: Установочные настройки закрывают внешний доступ

Сервис SHALL начинать с выключенным внешним API, включённым требованием авторизации и без токена. Сервер SHALL сохранять ранее установленные настройки при перезапуске и обновлении.

#### Scenario: Владелец включает API до выпуска токена
- **WHEN** владелец включает API и сохраняет исходное требование авторизации
- **THEN** внешние операции требуют действительный токен и остаются недоступны до выпуска

#### Scenario: Явно открыт приватный API
- **WHEN** владелец включает API и выключает требование авторизации
- **THEN** внешние операции доступны сетевым клиентам без токена, а интерфейс владельца явно показывает этот режим

### Requirement: Общий внешний токен показывается при выпуске

Сервис SHALL принимать один общий токен для защищённого внешнего API. Владелец SHALL получать его полное значение только при успешном выпуске или замене. Замена SHALL атомарно отзывать предыдущее значение.

#### Scenario: Повторное открытие настроек
- **WHEN** владелец открывает настройки после однократного показа
- **THEN** он видит наличие токена и может явно заменить его, а прежнее значение недоступно для просмотра или копирования

#### Scenario: Два клиента используют заменённый токен
- **WHEN** замена зафиксирована и клиенты пытаются выполнить новые защищённые операции с прежним значением
- **THEN** оба получают отказ и только новое значение допускает операции

### Requirement: Источник браузерной записи проверяется в обоих режимах

Сервис SHALL допускать внешний PATCH без Origin для программного клиента. При наличии Origin сервис SHALL требовать единственное корректное значение, совпадающее с фактическим HTTPS origin сервера по схеме, хосту и эффективному порту.

#### Scenario: Чужой сайт отправляет PATCH к открытому API
- **WHEN** при открытом без токена API клиент передаёт чужой, null, некорректный или повторный Origin
- **THEN** сервис возвращает 403 до записи; Forwarded-заголовки не дают права изменить ожидаемый источник
