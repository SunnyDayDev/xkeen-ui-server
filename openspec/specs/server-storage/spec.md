# server-storage Specification

## Purpose

Определить запуск сервера с постоянным хранилищем, сохранение данных при повторном открытии и безопасное применение миграций схемы.

## Requirements

### Requirement: Persistent storage is prepared at startup

Сервер SHALL открывать указанный дисковый файл. Для отсутствующего файла SHALL создавать хранилище с начальной версией схемы. Для файла с текущей версией сервер SHALL сохранять данные и историю применённых миграций при повторном открытии.

#### Scenario: Initialize storage on first launch

- **WHEN** сервер запускается с путём к новому файлу в доступном для записи каталоге
- **THEN** по этому пути создаётся хранилище с первой применённой миграцией
- **AND** каталог для пути по умолчанию создаётся автоматически при его отсутствии

#### Scenario: Reopen the current schema

- **GIVEN** сервер штатно завершился и в хранилище есть зафиксированная запись с тестовыми данными
- **WHEN** сервер снова запускается с тем же файлом
- **THEN** запись читается без изменений и начальная миграция зарегистрирована ровно один раз

### Requirement: Schema and migration history commit together

Сервер SHALL применять миграцию и фиксировать её версию в одной транзакции. При ошибке изменения этой миграции SHALL откатываться, а ранее зафиксированные данные и версии SHALL сохраняться. После первой неудачной попытки может остаться пустой файл без зафиксированных изменений.

#### Scenario: Failure after an earlier statement succeeds

- **GIVEN** хранилище с зафиксированными данными и миграция из нескольких операций
- **WHEN** одна операция в миграции завершается ошибкой после успешной записи
- **THEN** следы изменений неудачной миграции отсутствуют и новая версия не зарегистрирована
- **AND** ранее зафиксированные данные и версии читаются при повторном открытии

### Requirement: Unsupported storage fails visibly

Сервер SHALL сообщать об ошибках открытия и миграции оператору через stderr. При неподдерживаемой версии схемы или несовместимой истории миграций сервер SHALL отказаться менять хранилище. Диагностика SHALL обозначать этап и причину без вывода сохранённых значений.

#### Scenario: Database cannot be opened

- **WHEN** заданный путь указывает на каталог, недоступен для записи или содержит файл некорректного формата
- **THEN** запуск завершается с ошибкой и диагностикой в stderr

#### Scenario: Schema is newer than the binary supports

- **WHEN** хранилище содержит зарегистрированную версию новее поддерживаемой
- **THEN** запуск завершается с диагностикой несовместимой версии, а версия и данные сохраняются

#### Scenario: Migration history is incompatible

- **WHEN** файл содержит пользовательские объекты без истории миграций или журнал миграций имеет неверную структуру или триггер, пуст или содержит пропуск версий
- **THEN** запуск завершается с диагностикой несовместимой схемы, сохраняя исходные объекты и записи
