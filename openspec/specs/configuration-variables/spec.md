# configuration-variables Specification

## Purpose

Определить однозначную сборку JSON одного элемента из шаблона и его переменных с сохранением типов, проверкой заполненности и понятными ошибками до подготовки конфигурации устройства.

## Requirements

### Requirement: Element scoped exact variable names

При полной сборке сервис SHALL искать ссылку `${name}` только среди определений текущего элемента по полному имени, с учётом регистра, без обрезки пробелов и Unicode-нормализации имени. Точка SHALL быть обычным символом имени. Определение для сборки SHALL содержать непустое имя и ровно один тип из `string`, `number`, `boolean`, `object`, `array`; дефолт SHALL быть необязательным. Имя SHALL NOT содержать пробельные символы, управляющие символы, `$`, `{` или `}`. Другие символы, включая точки, дефисы, подчёркивания и буквы вне ASCII, SHALL быть допустимы. При полной сборке дубликаты имён в одном элементе, неизвестный тип и значения для необъявленного имени SHALL отклоняться. Определения всех переменных элемента SHALL проверяться, даже если они не используются в JSON.

При подготовке сохранения корректная целая ссылка SHALL автоматически добавлять отсутствующее определение согласно `References declare stored block variables`. Отдельное ручное добавление имени SHALL NOT быть обязательным. Это дополнение SHALL происходить до передачи сохранённого элемента в будущую полную сборку. Низкоуровневый вызов сборки либо подстановки с явно переданным неполным набором SHALL NOT создавать определения или значения вместо ошибки неизвестного имени. Структурно корректные, но семантически невалидные определения SHALL допускаться при сохранении согласно `configuration-element-storage`; это SHALL NOT ослаблять проверки сборки.

#### Scenario: Dot is part of a name

- **WHEN** шаблон содержит `{"address":"${server.address}"}`, определена string-переменная `server.address` и её значение равно `edge.example.com`
- **THEN** результат равен `{"address":"edge.example.com"}`
- **AND** объект со значением по имени `server` не заменяет определение `server.address`

#### Scenario: Element scopes and case are independent

- **WHEN** два элемента определяют `host` со значениями `one.example.com` и `two.example.com`
- **THEN** каждый получает собственное значение
- **AND** ссылка `${Host}` без отдельного определения `Host` даёт `unknown_variable` при прямом вызове сборки с этим неполным набором

#### Scenario: Invalid definitions or extra values

- **WHEN** переданы два определения `host`, имя `server address`, имя `a}`, пустое имя, тип `integer` или персональное значение для необъявленного `other`
- **THEN** сборка отклоняется с ошибкой соответствующего определения или значения

#### Scenario: Saving supplies a declaration before assembly

- **WHEN** сохраняется элемент `{"address":"${server.address}"}` без определения `server.address`
- **THEN** сохранённые определения содержат `server.address`, тип `string` и дефолт `""`
- **AND** для полной сборки требуется заполненное значение; наличие объявления не означает заполненность

### Requirement: Typed whole value substitution

Сервис SHALL разбирать шаблон как JSON и заменять только строковое значение, в точности равное `${name}`, на выбранное значение объявленного типа. Подстановка SHALL работать в корне, в полях объектов и элементах массивов на любой глубине. Сервис SHALL сохранять неизвестные поля, структуру и порядок элементов массивов. JSON-тип SHALL NOT преобразовываться автоматически; числовая строка SHALL NOT становиться числом. Числа SHALL сохранять математическое значение без потери точности; конкретная запись числа, пробелы JSON и порядок ключей объекта не являются контрактом.

#### Scenario: All five value types

- **WHEN** шаблон и выбранные типизированные значения имеют следующий вид

```json
{
  "template": {
    "host": "${host}",
    "port": "${port}",
    "enabled": "${enabled}",
    "settings": "${settings}",
    "targets": "${targets}",
    "custom": {"nested": ["${port}"]}
  },
  "values": {
    "host": "edge.example.com",
    "port": 443,
    "enabled": false,
    "settings": {"network": "tcp"},
    "targets": ["example.net"]
  }
}
```

- **THEN** результат равен следующему JSON

```json
{
  "host": "edge.example.com",
  "port": 443,
  "enabled": false,
  "settings": {"network": "tcp"},
  "targets": ["example.net"],
  "custom": {"nested": [443]}
}
```

#### Scenario: Root and exact numbers

- **WHEN** корневой шаблон равен `"${n}"`, `n` имеет тип number и значение `9007199254740993`
- **THEN** результат является числом `9007199254740993` без округления
- **AND** дробное значение `0.125` также сохраняется как число без изменения значения

#### Scenario: Wrong type does not use a default

- **WHEN** number-переменная `port` имеет дефолт `443`, а персональное значение равно строке `"8443"`
- **THEN** сборка даёт `type_mismatch`, не преобразует строку и не использует дефолт

### Requirement: Missing values and defaults

Сервис SHALL считать значение незаполненным, если оно отсутствует или является строкой, пустой после удаления пробельных символов с обоих концов. `trim` SHALL использовать набор Unicode White_Space. Эта проверка SHALL предшествовать проверке объявленного типа и SHALL применяться к значению переменной целиком; она SHALL NOT удалять поля или менять вложенные строки объекта/массива. Непустые строки SHALL сохраняться без обрезки.

Незаполненное персональное значение SHALL выбирать заполненный дефолт; незаполненный строковый дефолт SHALL быть эквивалентен отсутствующему дефолту. Если оба отсутствуют, сервис SHALL возвращать `missing_value`. Наличие дефолта SHALL NOT требовать персонального значения. Заполненный дефолт SHALL проверяться независимо от наличия персонального значения. Все объявленные переменные без заполненного дефолта SHALL требовать заполненного значения, даже если ссылка на них отсутствует. `false`, `0`, `{}` и `[]` SHALL считаться заполненными значениями своих типов.

#### Scenario: Empty and whitespace strings are missing

- **WHEN** string-переменная `host` без дефолта получает `""`, `" \t\n "` или `"\u00a0"`, либо значение отсутствует
- **THEN** каждый случай даёт `missing_value`

#### Scenario: Empty personal value inherits a default

- **WHEN** у `host` есть дефолт `edge.example.com`, а персональное значение отсутствует или равно `"   "`
- **THEN** выбирается `edge.example.com`
- **AND** для number-переменной с дефолтом `443` персональная строка `"   "` также считается незаполненной и выбирает число `443`

#### Scenario: Empty default and unused required definition

- **WHEN** определена переменная `host` с дефолтом `" \t "`, персонального значения нет и шаблон не содержит ссылку на `host`
- **THEN** сборка даёт `missing_value` для `host`

#### Scenario: Nonempty values preserve content

- **WHEN** переменные соответствующих типов получают `"  edge.example.com  "`, `false`, `0`, `{}` и `[]`
- **THEN** все значения считаются заполненными и подставляются без изменения
- **AND** значение object `{"label":"   "}` считается заполненным и сохраняет вложенную строку

#### Scenario: Invalid default remains an error

- **WHEN** number-переменная имеет строковый дефолт `"443"` и корректное персональное значение `8443`
- **THEN** определение отклоняется с `type_mismatch` для дефолта

### Requirement: Null is rejected

Сервис SHALL отклонять JSON `null` во входах сборки элемента: в сыром JSON шаблона, персональных значениях и дефолтах, включая вложенные поля и элементы массивов. Ошибка SHALL иметь код `null_not_allowed`. `null` SHALL NOT означать отсутствие, удаление поля или возврат к дефолту. Строка `"null"` SHALL оставаться обычной заполненной строкой. Отсутствие переменной или дефолта SHALL представляться отсутствием записи, а не `null`.

#### Scenario: Null does not fall back

- **WHEN** у `host` задан корректный дефолт, а персональное значение равно `null`
- **THEN** сборка даёт `null_not_allowed`, не используя дефолт

#### Scenario: Null in defaults and nested values

- **WHEN** дефолт равен `null`, object-переменная содержит `{"optional":null}` или array-переменная содержит `[null]`
- **THEN** сборка отклоняется с `null_not_allowed` и местом запрещённого значения

#### Scenario: Null in the raw template

- **WHEN** сырой шаблон равен `{"optional":null}`, даже если не содержит ссылок на переменные
- **THEN** сборка отклоняется с `null_not_allowed` по пути `/optional`
- **AND** шаблон `{"optional":"null"}` сохраняет строку и проходит эту проверку

### Requirement: Literal escaping and unsupported interpolation

В строковых значениях исходного шаблона сервис SHALL обрабатывать `$$` как буквальный `$` за один проход слева направо; полученный символ SHALL NOT повторно распознаваться как начало ссылки. Поэтому `$${name}` SHALL давать буквальный `${name}` без поиска переменной. Одиночный `$`, за которым не следует `{`, SHALL сохраняться.

Корректная неэкранированная ссылка вместе с любым другим содержимым строки SHALL давать `unsupported_interpolation`. Незакрытая ссылка и имя, нарушающее правила имён, SHALL давать `invalid_reference`. Обратная косая черта SHALL NOT служить экранированием ссылок; сначала действуют обычные правила JSON. Имена ключей объекта SHALL оставаться буквальными и SHALL NOT участвовать ни в подстановке, ни в обработке `$$`.

#### Scenario: Whole and embedded literal references

- **WHEN** исходные строковые значения равны `"$${host}"`, `"https://$${host}/path"`, `"$$$$"` и `"cost $5"`
- **THEN** они становятся соответственно `"${host}"`, `"https://${host}/path"`, `"$$"` и `"cost $5"` без поиска `host`

#### Scenario: Partial interpolation is rejected

- **WHEN** строка равна `"https://${host}/path"`, `" ${host} "`, `"${host}${port}"` или `"$${literal} ${host}"`
- **THEN** сборка даёт `unsupported_interpolation`
- **AND** сервис не склеивает строку, не обрезает её до ссылки и не оставляет неэкранированную ссылку как готовый результат

#### Scenario: Malformed references and backslashes

- **WHEN** строка шаблона равна `"${}"`, `"${host"`, `"${server address}"` или `"${a{b}"`
- **THEN** сборка даёт `invalid_reference`
- **AND** JSON-строка `"\\${host}"` содержит обычную косую черту перед ссылкой и даёт `unsupported_interpolation`, а не буквальное экранирование

#### Scenario: Keys remain literal

- **WHEN** шаблон равен `{"${key}":"fixed","$${key}":"fixed"}` и определения отсутствуют
- **THEN** оба ключа и значения сохраняются без изменения

### Requirement: Substituted data is not a new template

Сервис SHALL NOT повторно интерпретировать выбранное значение или дефолт как шаблон. Строки, объекты и массивы переменных SHALL подставляться как данные, даже когда они содержат `${...}` или `$$`. Значения SHALL NOT ссылаться на другие переменные посредством повторной подстановки. Проверка запрещённого `null` SHALL сохранять силу для вложенных данных.

#### Scenario: References inside supplied data remain literal

- **WHEN** шаблон `{"text":"${text}","options":"${options}"}` получает string-значение `"${other}"` и object-значение `{"label":"$${other}"}`
- **THEN** результат равен `{"text":"${other}","options":{"label":"$${other}"}}`
- **AND** определение `other` не требуется и повторная подстановка не выполняется

### Requirement: Atomic result and safe diagnostics

Сервис SHALL возвращать либо полностью собранный JSON, либо ошибки без пригодного для применения частичного результата. Исходный шаблон, определения и персональные значения SHALL оставаться неизменными. Невалидный JSON, повторяющиеся ключи JSON-объекта и текст после завершённого JSON-значения SHALL отклоняться до сборки. Проверка SHALL NOT ограничиваться каталогом известных полей Xray.

Каждая ошибка SHALL содержать код, ID элемента и источник (`template`, `definition`, `value` или `default`), а имя переменной и путь внутри JSON — когда они известны. Для синтаксически неразбираемого JSON SHALL указываться позиция вместо недоступного структурного пути. Ошибки SHALL NOT включать значения переменных, дефолты или сырой JSON. Порядок ошибок и полнота их накопления не являются контрактом; как минимум одна конкретная причина SHALL быть доступна.

#### Scenario: Unknown reference has a location

- **WHEN** элемент `outbound-demo` содержит `{"settings":{"address":"${missing}"}}` без определения `missing`
- **THEN** сборка даёт `unknown_variable`, ID `outbound-demo`, источник `template`, имя `missing` и путь `/settings/address`
- **AND** частичный результат не возвращается

#### Scenario: Invalid JSON input

- **WHEN** вход содержит незавершённый JSON, два корневых значения или повторяющийся ключ объекта
- **THEN** сервис отклоняет вход, не выбирая молча одно из значений

#### Scenario: Inputs and secrets are preserved

- **WHEN** сборка элемента с несколькими значениями завершается ошибкой типа в одном из них
- **THEN** входные данные остаются прежними, результат отсутствует, диагностика сообщает место и ожидаемый тип без вывода фактических значений

### Requirement: Substitution from prepared element values

Сервис SHALL предоставлять отдельную операцию подстановки, принимающую ID элемента, сырой JSON шаблона и подготовленный набор значений по именам только этого элемента. Подготовленный набор SHALL содержать уже выбранные значения: строки, числа, boolean, объекты или массивы, без определений и дефолтов. Операция SHALL использовать JSON-тип каждого переданного значения без автоматического преобразования и SHALL NOT самостоятельно выбирать дефолт или искать значения в других элементах.

Для шаблона с корректными целыми ссылками `${name}` и постоянными значениями операция SHALL подставлять значения в корне, полях объектов и элементах массивов, сохраняя структуру, неизвестные поля и порядок массивов. Имя SHALL сравниваться целиком, с учётом регистра, без обрезки и нормализации; точка SHALL оставаться частью имени. Числа как шаблона, так и подготовленных значений SHALL сохранять математическое значение без потери точности; форматирование и порядок ключей объектов не являются контрактом.

Подготовка набора и проверка полной конфигурации остаются отдельными операциями. Успех этого шага SHALL NOT означать выполнение всех требований полной сборки: проверки определений, заполненности, null и полного синтаксиса сохраняют силу на границе полной сборки. Гарантии этого шага для подготовленных входов не вводят разрешение на запрещённые полной сборкой данные.

#### Scenario: Prepared values retain all five types

- **WHEN** шаблон и подготовленные значения равны

```json
{
  "template": {
    "host": "${host}",
    "port": "${port}",
    "enabled": "${enabled}",
    "options": "${options}",
    "targets": "${targets}"
  },
  "values": {
    "host": "edge.example.com",
    "port": 443,
    "enabled": false,
    "options": {"network": "tcp"},
    "targets": ["example.net"]
  }
}
```

- **THEN** результат равен

```json
{
  "host": "edge.example.com",
  "port": 443,
  "enabled": false,
  "options": {"network": "tcp"},
  "targets": ["example.net"]
}
```

#### Scenario: Root substitution preserves the supplied type

- **WHEN** корневой шаблон `"${value}"` получает поочерёдно `"443"`, `0`, `false`, `{}` и `[]`
- **THEN** результат в каждом случае равен переданному значению с его JSON-типом
- **AND** строка `"443"` остаётся строкой, а `0`, `false` и пустые контейнеры не исчезают

#### Scenario: Nested references and unknown fields are preserved

- **WHEN** шаблон равен `{"custom":{"items":[{"port":"${port}"},"fixed","${port}"]},"extension":true}` и `port` равен `443`
- **THEN** результат равен `{"custom":{"items":[{"port":443},"fixed",443]},"extension":true}`
- **AND** неизвестные поля, постоянные значения и порядок массива сохраняются

#### Scenario: Exact names and element isolation

- **WHEN** два отдельных вызова используют шаблон `{"address":"${server.address}"}` и собственные наборы со значениями `one.example.com` и `two.example.com` для имени `server.address`
- **THEN** каждый результат содержит значение своего набора
- **AND** наличие только имени `server` с объектом `{"address":"one.example.com"}` не разрешает ссылку `server.address`
- **AND** наличие только имени `Server.Address` также не разрешает ссылку `server.address`

#### Scenario: Numbers in templates and values remain exact

- **WHEN** шаблон равен `{"constant":9007199254740993,"selected":"${n}"}` и `n` равен `9007199254740993`
- **THEN** оба числа в результате равны `9007199254740993`, без округления
- **AND** подстановка `0.12345678901234567890123456789` и `1e400` также сохраняет математическое значение

#### Scenario: Constant template needs no values

- **WHEN** корректный шаблон без ссылок, например `{"custom":[0,false,"fixed",{},[]]}`, получает пустой набор
- **THEN** результат семантически равен шаблону

### Requirement: Prepared substitution rejects invalid JSON inputs

Операция подстановки SHALL разбирать шаблон и каждое подготовленное значение как ровно одно JSON-значение. Неправильный или незавершённый JSON и лишний текст после значения SHALL приводить к `invalid_json`; повторяющиеся ключи объекта на любой глубине SHALL приводить к `duplicate_json_key`. Сравнение ключей SHALL выполняться после JSON-декодирования строк. Проверка SHALL охватывать и переданные значения, которые не используются в шаблоне. Одинаковые ключи в разных объектах SHALL быть допустимы.

#### Scenario: Invalid template has a safe position

- **WHEN** шаблон содержит незавершённый объект, два корневых значения или текст после завершённого значения
- **THEN** операция возвращает `invalid_json`, ID элемента, источник `template` и позицию ошибки без сырого JSON
- **AND** результат отсутствует

#### Scenario: Invalid supplied value is identified

- **WHEN** подготовленное значение `options` содержит неправильный JSON или два корневых значения, независимо от наличия ссылки на `options`
- **THEN** операция возвращает `invalid_json`, ID элемента, источник `value`, имя `options` и позицию ошибки
- **AND** результат отсутствует

#### Scenario: Duplicate keys are detected after decoding

- **WHEN** шаблон или подготовленное значение содержит `{"nested":{"a":1,"\u0061":2}}`
- **THEN** операция возвращает `duplicate_json_key` по пути `/nested/a`, с ID элемента и соответствующим источником
- **AND** для подготовленного значения указывается его имя
- **AND** результат отсутствует

#### Scenario: Keys in separate objects do not collide

- **WHEN** шаблон равен `{"first":{"a":1},"second":{"a":2}}` и набор пуст
- **THEN** операция успешно сохраняет оба объекта

### Requirement: Prepared substitution returns an atomic result and located errors

Если корректная целая ссылка отсутствует в подготовленном наборе, операция SHALL возвращать `unknown_variable`, ID элемента, источник `template`, точное имя и путь к ссылке. Путь SHALL использовать JSON Pointer: `~` экранируется как `~0`, `/` как `~1`, корень обозначается пустой строкой, элементы массива — индексами от нуля.

Операция SHALL возвращать либо новый JSON-результат без ошибок, либо как минимум одну конкретную диагностику и отсутствие результата. Шаблон и набор значений SHALL оставаться неизменными при успехе и ошибке; изменение возвращённого результата после успеха SHALL NOT менять входы. Диагностика SHALL NOT включать исходные значения или сырой JSON. Порядок и полнота накопления независимых ошибок не являются контрактом.

#### Scenario: Unknown variable identifies a nested reference

- **WHEN** элемент `outbound-demo` содержит `{"settings":{"address":"${missing}"}}` и набор не содержит `missing`
- **THEN** возвращается `unknown_variable`, ID `outbound-demo`, источник `template`, имя `missing` и путь `/settings/address`
- **AND** результат отсутствует

#### Scenario: Root and escaped paths locate unknown references

- **WHEN** ссылка `${missing}` находится в корне JSON либо в шаблоне `{"a/b~c":["${missing}"]}`
- **THEN** ошибка имеет соответственно пустой путь либо `/a~1b~0c/0`

#### Scenario: Error preserves all inputs and does not disclose data

- **WHEN** шаблон содержит известную и неизвестную целые ссылки, а подготовленный набор содержит строковое значение `demo-private-value`
- **THEN** операция возвращает ошибку неизвестной ссылки и не возвращает частичный JSON
- **AND** шаблон и все подготовленные значения остаются прежними
- **AND** диагностика не содержит `demo-private-value` или текст шаблона

#### Scenario: Successful result does not share writable input data

- **WHEN** успешная подстановка завершена и потребитель изменяет полученный результат
- **THEN** исходный шаблон и подготовленные значения остаются прежними

### Requirement: References declare stored block variables

При подготовке сохранения сервис SHALL обнаруживать корректные целые ссылки `${name}` в декодированных строковых значениях исходного JSON, включая корень, вложенные объекты и массивы. Для каждого отсутствующего имени SHALL добавляться ровно одно определение с типом `string` и JSON-дефолтом `""`. Имена SHALL сравниваться целиком, с учётом регистра и без Unicode-нормализации; область SHALL ограничиваться одним элементом. Тип SHALL NOT угадываться по имени переменной, имени поля, содержимому соседних полей или предполагаемой схеме Xray.

Обнаружение SHALL NOT менять исходный текст, подставлять значения или сканировать ключи объектов и JSON-дефолты. Буквальные ссылки через `$$`, частичная интерполяция и некорректные ссылки SHALL NOT объявлять переменные. Для объявления декодированная строка SHALL целиком совпадать с `${name}` с допустимым именем; строки с дополнительными символами SHALL сохраняться для последующей проверки сборки. JSON-экранирование SHALL декодироваться для распознавания, сохраняя исходную запись при хранении.

Начальный пустой дефолт SHALL означать незаполненность согласно `Missing values and defaults`. При изменении типа пустой дефолт SHALL оставаться допустимым незаполненным состоянием шаблона; тип `string` SHALL NOT автоматически восстанавливаться поверх пользовательского типа.

#### Scenario: A whole reference declares a string with empty default

- **WHEN** сохраняется `{"port":"${port}","options":"${options}"}` с пустым списком определений
- **THEN** появляются `port` и `options`, каждый с типом `string` и дефолтом `""`
- **AND** имена полей не превращают их в `number` и `object`

#### Scenario: Repeated nested references declare once

- **WHEN** сохраняется `{"a":"${host}","nested":["${host}",{"b":"${host}"}]}`
- **THEN** добавляется только одно определение `host`
- **AND** корневое содержимое `"${host}"` также объявляет `host`

#### Scenario: Exact names and block isolation

- **WHEN** один элемент содержит ссылки `${host}`, `${Host}` и `${server.address}`, а другой — `${host}`
- **THEN** первый получает три разных определения, второй — своё независимое `host`
- **AND** `server.address` не превращается в имя `server` и вложенное свойство

#### Scenario: JSON escaping does not hide a reference

- **WHEN** исходное содержимое равно `{"value":"\u0024{host}"}`
- **THEN** декодированная ссылка объявляет `host`
- **AND** исходное экранирование `\u0024` остаётся в сохранённом тексте

#### Scenario: Literal and invalid strings do not declare variables

- **WHEN** значения равны `"$${host}"`, `"$$${host}"`, `"https://${host}/path"`, `" ${host} "`, `"${host}${port}"`, `"${}"`, `"${host"` или `"${server address}"`
- **THEN** они не добавляют определений, а исходный текст сохраняется
- **AND** их допустимость и преобразование при сборке определяются существующим полным контрактом синтаксиса

#### Scenario: Keys and defaults are data for discovery

- **WHEN** JSON равен `{"${key}":"fixed"}`, а существующий дефолт содержит `{"label":"${other}"}`
- **THEN** `key` и `other` не объявляются по этим вхождениям

#### Scenario: Empty default survives a type change

- **WHEN** тип автоматически объявленного `port` изменён на `number`, а дефолт остаётся `""`
- **THEN** элемент сохраняется с типом `number` и прежним пустым дефолтом
- **AND** полная сборка требует заполненное числовое значение и не считает пустой дефолт готовой строкой или числом

### Requirement: Stored variable definitions survive reference edits

Подготовка сохранения SHALL только дополнять недостающие определения и SHALL сохранять прежние имена, типы, дефолты и порядок существующих записей, даже если имя больше не встречается в JSON. Повторное сохранение без изменения входов SHALL NOT добавлять дубликаты или сбрасывать настройки. При существующих повторных записях имени операция SHALL NOT выбирать одну или объединять их; отдельная проверка полной сборки SHALL отклонять такие определения.

Удаление определения SHALL быть явным изменением списка определений. Пока в JSON остаётся корректная ссылка на удалённое имя, подготовка сохранения SHALL снова объявлять это имя с начальными настройками. Для удаления без восстановления SHALL требоваться отсутствие соответствующих ссылок. Переименование ссылки SHALL добавлять новое имя и оставлять старое определение; автоматический перенос типа, дефолта или персональных значений SHALL NOT выполняться.

Чтение сохранённой записи SHALL восстанавливать фактически записанные определения без повторного обнаружения и без скрытого изменения записи. Обнаружение SHALL выполняться при подготовке следующего сохранения. Все оставшиеся определения, включая неиспользуемые, SHALL сохранять правила обязательности и проверки при сборке.

#### Scenario: Existing settings win over discovery defaults

- **WHEN** ссылка `${port}` уже имеет определение `number` с дефолтом `443`
- **THEN** повторное сохранение сохраняет `number` и `443`, не добавляя вторую запись

#### Scenario: Removing and restoring a reference keeps settings

- **WHEN** последняя ссылка `${port}` удалена из JSON, а определение не удалялось явно
- **THEN** тип и дефолт `port` сохраняются
- **AND** возвращение ссылки использует эти настройки

#### Scenario: Unused empty definition still needs a value

- **WHEN** JSON больше не содержит `${host}`, но осталось определение `host` с дефолтом `""`
- **THEN** сохранение разрешено, определение не удаляется
- **AND** полная сборка без персонального значения должна вернуть `missing_value` согласно существующему контракту обязательности

#### Scenario: Explicit deletion respects remaining references

- **WHEN** определение `host` явно убрано из переданного списка и ссылок на него больше нет
- **THEN** после сохранения и чтения оно отсутствует
- **AND** если ссылка `${host}` всё ещё есть, при подготовке сохранения появляется новое определение `string` с дефолтом `""`

#### Scenario: Rename does not transfer settings

- **WHEN** `${host}` меняется на `${server.address}` без явного изменения списка определений
- **THEN** `host` остаётся с прежними настройками, а `server.address` добавляется как `string` с пустым дефолтом

#### Scenario: Reading does not normalize a stored record

- **WHEN** читается структурно корректная запись с `${host}` и фактически пустым списком определений
- **THEN** чтение возвращает именно этот список и прежний JSON
- **AND** подготовка её следующего сохранения добавляет `host`, не меняя исходную прочитанную запись

### Requirement: Separate preparation of element variable values

Сервис SHALL предоставлять отдельную операцию подготовки значений одного элемента, принимающую его ID, определения переменных и персональные JSON-значения по именам. Операция SHALL возвращать полный набор выбранных значений для всех определений либо ошибки без частичного набора. Она SHALL применять правила точных имён, типов, заполненности и дефолтов этой capability независимо от наличия ссылок в содержимом элемента. Она SHALL NOT создавать определения или значения для неизвестных имён, читать настройки других элементов или менять сохранённые данные.

Операция SHALL NOT принимать или проверять сырой шаблон. Успешная подготовка SHALL подтверждать корректность только определений и выбранного набора; она SHALL NOT подтверждать готовность шаблона, полной конфигурации или ревизии к применению. Требования полной сборки и отдельной подстановки подготовленных значений сохраняются.

#### Scenario: Prepared defaults feed whole value substitution

- **WHEN** для элемента определены string `server.address` с дефолтом `"edge.example.com"` и number `port` с дефолтом `443`, а персонально задано `port: 8443`
- **THEN** подготовка возвращает набор `{"server.address":"edge.example.com","port":8443}` без ошибок
- **AND** последующая подстановка этого набора в `{"address":"${server.address}","port":"${port}"}` даёт `{"address":"edge.example.com","port":8443}`

#### Scenario: Empty definitions and values

- **WHEN** определения и персональные значения отсутствуют
- **THEN** подготовка успешно возвращает пустой набор выбранных значений

#### Scenario: Preparation does not interpret stored content

- **WHEN** сохранённый элемент содержит `{"optional":null,"address":"https://${host}"}`, а его определение string `host` имеет корректный дефолт `"edge.example.com"`
- **THEN** отдельная подготовка определения и значений успешно выбирает `host`
- **AND** содержимое элемента остаётся неизменным; успех подготовки не отменяет обязательный отказ полной сборки из-за `null` и частичной интерполяции

### Requirement: Preparation validates definitions and supplied names

При подготовке сервис SHALL проверять все определения по правилам `Element scoped exact variable names`, включая корректный UTF-8 имён, отсутствие недопустимых символов и точное совпадение типа с одним из пяти допустимых типов. Некорректное имя SHALL давать `invalid_variable_name`, повтор имени — `duplicate_variable`, недопустимый тип — `invalid_variable_type`. Персональное значение для имени без определения SHALL давать `unknown_variable` с источником `value`; оно SHALL NOT молча игнорироваться. Совпадение имён SHALL проверяться целиком, с учётом регистра и без нормализации.

#### Scenario: Invalid and duplicate definitions

- **WHEN** определения содержат пустое имя, `server address`, `a}`, имя с управляющим символом или некорректным UTF-8, два определения `host` либо тип `integer`
- **THEN** каждый отдельно переданный случай отклоняется с соответствующим кодом ошибки определения
- **AND** повтор `host` отклоняется даже при одинаковых типах и дефолтах

#### Scenario: Exact names and independent elements

- **WHEN** отдельные элементы определяют `server.address` с дефолтами `"one.example.com"` и `"two.example.com"`
- **THEN** каждый набор подготовки получает свой дефолт
- **AND** переданные имена `server` и `Server.Address` без собственных определений отклоняются, а не подменяют `server.address`

#### Scenario: Unicode names are not normalized

- **WHEN** объявлены `сервер.адрес`, `café` и `café` с разными корректными значениями
- **THEN** все три имени сохраняются отдельно, включая различие составного и разложенного представления Unicode

### Requirement: Preparation selects filled values without coercion

Подготовка SHALL применять `Missing values and defaults` и правила типов ко всем определениям. Отсутствие персональной записи или строка, пустая после Unicode White_Space trim, SHALL выбирать заполненный дефолт. При отсутствии обоих SHALL возвращаться `missing_value` с источником `value`. Проверка пустой строки SHALL предшествовать проверке объявленного типа. Значения SHALL NOT автоматически преобразовываться между типами; несовпадение SHALL давать `type_mismatch` и ожидаемый тип.

Каждый присутствующий персональный JSON и каждый заданный дефолт SHALL проверяться независимо от выбора итогового значения. Неверное персональное значение SHALL NOT заменяться дефолтом; неверный заполненный дефолт SHALL NOT скрываться корректным персональным значением. Успешный набор SHALL содержать ровно по одному значению каждого определения, включая неиспользуемые. Строки SHALL сохранять содержимое, числа — точное математическое значение, объекты — все поля, массивы — порядок. Строки внутри данных, включая `${name}` и `$$`, SHALL NOT интерпретироваться как шаблоны.

#### Scenario: Missing values and Unicode whitespace select defaults

- **WHEN** number `port` имеет дефолт `443`, а персональная запись отсутствует либо равна `""`, `" \t\n "` или `"\u00a0"`
- **THEN** во всех случаях выбирается число `443`
- **AND** без заполненного дефолта те же случаи дают `missing_value`

#### Scenario: Whitespace is preserved unless the entire string is missing

- **WHEN** string-переменные получают `"  edge.example.com  "` и `"\u200b"`, а object-переменная получает `{"label":"   "}`
- **THEN** все значения считаются заполненными и сохраняются; U+200B не входит в Unicode White_Space

#### Scenario: Unused definition still needs a value

- **WHEN** объявлена `host` без дефолта либо с дефолтом `" \t "`, персонального значения нет, и в содержимом элемента нет ссылки на `host`
- **THEN** подготовка отклоняется с `missing_value` для `host`

#### Scenario: False zero and empty containers are filled

- **WHEN** boolean, number, object и array получают соответственно `false`, `0`, `{}` и `[]` через персональное значение или дефолт
- **THEN** все четыре значения успешно выбираются с сохранением типов

#### Scenario: Wrong personal type does not fall back

- **WHEN** number `port` имеет дефолт `443` и персональную строку `"8443"`
- **THEN** подготовка возвращает `type_mismatch`, источник `value` и ожидаемый тип `number`, без результата

#### Scenario: Invalid unused default is still checked

- **WHEN** number `port` имеет дефолт `"443"` и персональное число `8443`
- **THEN** подготовка возвращает `type_mismatch` с источником `default`
- **AND** дефолт `"   "` вместо `"443"` считается отсутствующим и не мешает выбрать персональное число

#### Scenario: Data remains literal and numbers remain exact

- **WHEN** выбираются number `9007199254740993`, number `0.12345678901234567890123456789`, number `1e400`, string `"${other}"` и object `{"label":"$${other}"}` из персональных значений либо дефолтов
- **THEN** числовые значения сохраняются без округления и переполнения, строки остаются данными, определение `other` не требуется

### Requirement: Preparation rejects invalid JSON and null data

Каждая присутствующая персональная запись и каждый заданный дефолт SHALL содержать ровно одно корректное UTF-8 JSON-значение без повторных ключей. Пустой JSON-документ, неверный синтаксис и текст после корня SHALL давать `invalid_json`; повторные ключи — `duplicate_json_key`. Отсутствующая запись SHALL отличаться от присутствующей записи с пустым JSON-документом; последняя SHALL NOT выбирать дефолт.

Подготовка SHALL применять `Null is rejected` ко всем персональным значениям и заданным дефолтам: корневой и вложенный `null` SHALL давать `null_not_allowed` даже в невыбранном дефолте. Для синтаксически корректных данных с `null` и без иных ошибок определений запрет `null` SHALL проверяться до несовпадения корневого типа. `null` SHALL NOT означать отсутствие и SHALL NOT приводить к выбору дефолта. JSON-строка `"null"` SHALL оставаться допустимой строкой. Запрет `null` в сыром шаблоне остаётся требованием полной сборки вне входов этой операции.

#### Scenario: Present but invalid JSON is not missing

- **WHEN** у переменной есть корректный дефолт, а присутствующее персональное значение содержит пустой документ, неверный UTF-8, незавершённый JSON или два корня
- **THEN** подготовка даёт `invalid_json` с источником `value`, а не выбирает дефолт

#### Scenario: All defaults are parsed strictly

- **WHEN** у переменной есть корректное персональное значение, но её дефолт содержит неверный JSON или повторный ключ, в том числе `{"a":1,"\u0061":2}`
- **THEN** подготовка отклоняется с `invalid_json` либо `duplicate_json_key` с источником `default`
- **AND** такое же нарушение в персональном JSON отклоняется с источником `value`

#### Scenario: Root null never uses a default

- **WHEN** string `host` имеет корректный дефолт, а персональное значение равно `null`
- **THEN** подготовка даёт `null_not_allowed`, источник `value`, имя `host` и корневой путь `""`, без результата
- **AND** персональная строка `"null"` успешно выбирается как заполненная строка

#### Scenario: Nested null and unselected defaults are rejected

- **WHEN** персональное значение либо дефолт `options` содержит `{"a/b~c":[null]}`
- **THEN** подготовка даёт `null_not_allowed` по пути `/a~1b~0c/0` с соответствующим источником
- **AND** ошибка дефолта сохраняется при корректном персональном значении
- **AND** корневой дефолт `null` и массив `[null]` также отклоняются

### Requirement: Prepared values and diagnostics preserve input boundaries

Подготовка SHALL сохранять входные определения, дефолты и персональные значения неизменными и возвращать независимый набор: последующие изменения результата SHALL NOT менять входы и наоборот. При любой ошибке выбранный набор SHALL отсутствовать, даже если часть переменных корректна.

Каждая ошибка SHALL содержать код, ID элемента, источник (`definition`, `value` или `default`) и известное имя переменной. Ошибки определения SHALL указывать его место в переданном списке; ошибки содержимого JSON — путь относительно данного значения или дефолта либо байтовую позицию от нуля для синтаксической ошибки. `type_mismatch` SHALL содержать ожидаемый тип. Диагностика SHALL NOT включать персональные значения, дефолты или их исходный JSON. Порядок и накопление всех ошибок не являются контрактом; как минимум одна конкретная причина SHALL возвращаться.

#### Scenario: One failure prevents partial output

- **WHEN** подготовка получает заполненный `host` и обязательный `port` без значения
- **THEN** результат отсутствует, ошибка `missing_value` указывает ID элемента, источник `value` и имя `port`
- **AND** входы не меняются, значение `host` не включается в диагностику

#### Scenario: Result buffers are independent

- **WHEN** успешная подготовка выбирает объект из персональных данных и массив из дефолта
- **THEN** изменение любого возвращённого JSON-значения или набора не меняет входные значения и определения
- **AND** последующее изменение входных буферов не меняет результат

#### Scenario: Diagnostics identify definitions and hide data

- **WHEN** ошибка относится к повторному имени во втором определении, неверному типу определения либо неверному типу заполненного дефолта
- **THEN** диагностика указывает соответствующее определение или дефолт, известное имя и ID элемента
- **AND** возвращённые ошибки не содержат значений или исходного JSON даже при ошибке после успешно обработанных переменных

### Requirement: Complete variable assembly for one element

Сервис SHALL предоставлять единую операцию разрешения переменных одного элемента, принимающую ID для диагностики, сырой JSON шаблона, список определений и персональные значения. Операция SHALL применять все требования этой capability к именам, определениям, заполненности, дефолтам, типам, JSON, запрету `null`, синтаксису ссылок и подстановке. Результат SHALL быть новым JSON одного элемента либо отсутствовать при наличии хотя бы одной ошибки. Определения SHALL NOT автоматически добавляться при сборке; ID SHALL использоваться как диагностический контекст, без создания или проверки идентичности элементов этой операцией.

Успех SHALL означать разрешение переменных в JSON одного элемента; он SHALL NOT означать проверку схемы Xray, межэлементных зависимостей, проекцию служебной метки или готовность каталога конфигурации к публикации.

#### Scenario: Definitions defaults and template are assembled together

- **WHEN** шаблон равен `{"address":"${server.address}","port":"${port}","literal":"$${port}"}`, определены `server.address` типа string без дефолта и `port` типа number с дефолтом `443`, а персональное значение `server.address` равно `"edge.example.com"`
- **THEN** результат равен `{"address":"edge.example.com","port":443,"literal":"${port}"}` без ошибок

#### Scenario: Every definition and unselected default is checked

- **WHEN** шаблон не использует определённую переменную `host` без заполненного значения или дефолта
- **THEN** сборка возвращает `missing_value` для `host` без результата
- **AND** в отдельном вызове number-переменная `port` с дефолтом `"443"` и персональным значением `8443` даёт `type_mismatch` с источником `default`, даже если ссылка не используется

#### Scenario: Invalid definitions and extra personal values block assembly

- **WHEN** при корректном шаблоне определения содержат неверное имя, неизвестный тип или повтор имени либо персональный набор содержит необъявленное имя
- **THEN** единая операция возвращает соответственно `invalid_variable_name`, `invalid_variable_type`, `duplicate_variable` либо `unknown_variable` с тем же источником и местом, что отдельная подготовка значений
- **AND** результат отсутствует

#### Scenario: Assembly never declares an unknown reference

- **WHEN** шаблон равен `{"address":"${host}"}`, определения и персональный набор пусты
- **THEN** возвращается `unknown_variable`, источник `template`, имя `host` и путь `/address`
- **AND** определения остаются пустыми, результат отсутствует

#### Scenario: Supplied invalid JSON and null cannot bypass preparation

- **WHEN** персональное значение или присутствующий дефолт содержит невалидный JSON, повторный ключ или `null` на любой глубине
- **THEN** единая операция отклоняет его по правилам подготовки с `invalid_json`, `duplicate_json_key` либо `null_not_allowed` и источником `value` или `default`
- **AND** это распространяется на неиспользуемые значения и невыбранные дефолты без возврата частичного результата

#### Scenario: All supported roots and exact numbers remain supported

- **WHEN** корневой шаблон `"${value}"` получает через определения и персональный набор поочерёдно string `"443"`, number `9007199254740993`, number `0.12345678901234567890123456789`, boolean `false`, object `{}` и array `[]`
- **THEN** каждый результат имеет соответствующий JSON-тип и точное значение
- **AND** постоянный шаблон `{"extension":[0,false,"",{},[],1e400]}` с пустыми определениями и значениями успешно сохраняет структуру, неизвестные поля и точные числа

### Requirement: Prepared substitution validates original template syntax

Операция подстановки подготовленных значений SHALL применять `Literal escaping and unsupported interpolation` ко всем исходным строковым значениям шаблона, включая корень и вложенные массивы/объекты. Разбор SHALL выполняться после JSON-декодирования. Только исходная строка, целиком являющаяся одной корректной неэкранированной ссылкой, SHALL заменяться значением; проверка корректности имени SHALL предшествовать поиску имени в наборе. Полная сборка SHALL обеспечивать то же поведение.

При наличии корректной ссылки вместе с другим содержимым SHALL возвращаться `unsupported_interpolation`, независимо от наличия значения ссылки. При некорректной ссылке SHALL возвращаться `invalid_reference`. Если строка содержит обе причины, конкретная возвращаемая причина и полнота их накопления не фиксируются. Ключи SHALL оставаться буквальными. Операция подстановки SHALL NOT выбирать дефолты или проверять определения вместо отдельной подготовки.

#### Scenario: Escapes and isolated dollars are resolved once

- **WHEN** шаблон равен `["$${host}","https://$${host}/path","$$$$","cost $5","$","$${host"]` и подготовленный набор пуст
- **THEN** результат равен `["${host}","https://${host}/path","$$","cost $5","$","${host"]`
- **AND** экранированное начало незакрытой буквальной строки не даёт `invalid_reference`

#### Scenario: Odd dollar run leaves a real embedded reference

- **WHEN** исходная строка равна `"$$${host}"`
- **THEN** возвращается `unsupported_interpolation`: после экранированного доллара остаётся настоящая ссылка с дополнительным содержимым
- **AND** строка `"$$$${host}"` в отдельном вызове даёт буквальную строку `"$${host}"` без поиска переменной

#### Scenario: Partial references are rejected before lookup

- **WHEN** строка равна `"https://${host}/path"`, `" ${host} "`, `"${host}${port}"` или `"$${literal} ${host}"`
- **THEN** возвращается `unsupported_interpolation` как с подготовленными значениями для имён, так и без них
- **AND** результат отсутствует

#### Scenario: Malformed references are not unknown variables

- **WHEN** строка равна `"${}"`, `"${host"`, `"${server address}"`, `"${a{b}"` или `"${a$b}"`
- **THEN** возвращается `invalid_reference`, даже если низкоуровневый подготовленный набор содержит ключ с текстом ошибочного имени
- **AND** тот же запрет действует на некорректную ссылку внутри более длинной строки

#### Scenario: JSON escapes are decoded before template syntax

- **WHEN** исходный JSON равен `"\u0024{host}"` и подготовленное значение `host` равно `"edge.example.com"`
- **THEN** результат равен `"edge.example.com"`
- **AND** JSON `"\u0024\u0024{host}"` в отдельном вызове даёт буквальное `"${host}"`
- **AND** имя с JSON-экранированным пробелом, например `"${server\u0020address}"`, даёт `invalid_reference`

#### Scenario: Backslash is not a template escape

- **WHEN** исходный JSON равен `"\\${host}"`
- **THEN** декодированная обратная косая черта является дополнительным содержимым и возвращается `unsupported_interpolation`
- **AND** невалидное JSON-экранирование, например `"\${host}"`, даёт `invalid_json` до разбора ссылок

#### Scenario: Object keys are never processed as template strings

- **WHEN** шаблон равен `{"${key}":"$${host}","$${key}":"fixed","${broken":"fixed"}` и набор пуст
- **THEN** результат равен `{"${key}":"${host}","$${key}":"fixed","${broken":"fixed"}`
- **AND** ключи не объявляют и не требуют переменных и не вызывают ошибку ссылки

### Requirement: Prepared substitution rejects null in the raw template

Операция подстановки SHALL отклонять `null` в исходном шаблоне на любой глубине с `null_not_allowed`, источником `template` и путём к запрещённому значению, даже при отсутствии ссылок. Она SHALL сохранять строки `"null"` и иные разрешённые постоянные значения. Полная сборка SHALL обеспечивать тот же запрет наряду с проверками данных переменных из B01. Эти требования SHALL NOT ужесточать сохранение черновиков.

#### Scenario: Root and nested template null are rejected

- **WHEN** шаблон поочерёдно равен `null`, `{"optional":null}` и `{"a/b~c":[null]}` при пустом наборе
- **THEN** каждый вызов возвращает `null_not_allowed`, источник `template` и путь соответственно `""`, `/optional` и `/a~1b~0c/0`
- **AND** результат отсутствует

#### Scenario: Null text remains data

- **WHEN** шаблон равен `{"optional":"null","text":"","constant":false}` при пустом наборе
- **THEN** подстановка успешно сохраняет эти значения

#### Scenario: A saved draft can still fail assembly

- **WHEN** структурно корректный элемент содержит `null`, частичную ссылку или незаполненное определение
- **THEN** подготовка сохранения и чтение продолжают допускать его по контракту хранения
- **AND** последующая полная сборка отклоняет соответствующий случай с `null_not_allowed`, `unsupported_interpolation` или `missing_value`, не изменяя сохранённый черновик

### Requirement: Assembly preserves the boundary between template and data

Единая сборка и подстановка подготовленного набора SHALL обрабатывать синтаксис только исходных строковых значений шаблона. Полученные после `$$` строки и подставленные данные SHALL NOT снова проходить разбор ссылок или экранирования. Полная сборка SHALL при этом сохранять проверку `null` данных переменных и дефолтов. Неизвестные поля, порядок массивов и точные числа SHALL сохраняться по существующему контракту.

#### Scenario: Supplied strings and nested structures are never templates

- **WHEN** шаблон равен `{"text":"${text}","options":"${options}"}`, объявлены string `text` и object `options`, их персональные значения равны `"${other}"` и `{"items":["$$","${broken","https://${other}/path"]}`
- **THEN** результат равен `{"text":"${other}","options":{"items":["$$","${broken","https://${other}/path"]}}`
- **AND** определение `other` не требуется

#### Scenario: A chosen default remains literal data

- **WHEN** string-переменная `text` имеет дефолт `"$${other}"`, персональное значение отсутствует и шаблон равен `"${text}"`
- **THEN** результат равен `"$${other}"` без обработки долларов или поиска `other`

### Requirement: Complete assembly returns safe independent results and diagnostics

Единая операция SHALL сохранять входной шаблон, определения, дефолты и персональные значения при успехе и ошибке. Изменение успешного результата SHALL NOT менять входы. Ошибка SHALL содержать ID элемента, код и источник; JSON Pointer SHALL указываться для известного структурного места, а для синтаксической ошибки JSON — байтовая позиция от нуля. Правила локализации подготовки SHALL сохраняться: путь данных отсчитывается от корня конкретного значения или дефолта, путь определения — от списка определений.

Ошибки синтаксиса шаблона SHALL иметь источник `template`. Для `unknown_variable` с источником `template` имя SHALL быть точным именем корректной ссылки; для `unsupported_interpolation` имя SHALL указываться при единственной корректной ссылке и отсутствии других ошибок ссылки в этой строке. Для `invalid_reference` и строк с несколькими ссылками имя SHALL оставаться неуказанным. Ошибки SHALL NOT содержать сырой JSON, значения, дефолты или фрагменты некорректных ссылок. Ожидаемый тип SHALL указываться только для `type_mismatch`. Порядок независимых ошибок и полнота накопления не фиксируются.

#### Scenario: Nested syntax errors have safe locations

- **WHEN** элемент `element-demo` содержит `{"a/b~c":["https://${host}/path"]}`
- **THEN** ошибка имеет код `unsupported_interpolation`, источник `template`, ID `element-demo`, имя `host` и путь `/a~1b~0c/0`
- **AND** шаблон `{"a/b~c":["${}"]}` в отдельном вызове даёт `invalid_reference` по тому же пути без имени переменной

#### Scenario: Multiple references do not get an arbitrary diagnostic name

- **WHEN** строка равна `"${host}${port}"`
- **THEN** возвращается `unsupported_interpolation` с путём к строке и без имени переменной

#### Scenario: JSON failures stay distinct from reference failures

- **WHEN** шаблон содержит незавершённый JSON, неверный UTF-8, два корневых значения или повторные декодированные ключи объекта
- **THEN** сборка возвращает `invalid_json` с позицией либо `duplicate_json_key` с путём и источником `template`
- **AND** результат отсутствует

#### Scenario: Failure and success preserve input ownership

- **WHEN** сборка получает шаблон с известной ссылкой и отдельным ошибочным значением шаблона
- **THEN** возвращаются ошибки без частичного результата, все входы остаются прежними, диагностика не содержит подставленных данных
- **AND** в отдельном успешном вызове изменение буфера результата не меняет шаблон, определения, дефолты или персональные значения
